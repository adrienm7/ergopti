## Background menu work

The previous timer prepared at most one leaf per invocation but appended the
entire leaf inside Critical. A large leaf therefore prevented keyboard and tray
callbacks from starting until its complete registration ended. A bounded count
of leaves did not imply bounded native work.

Preparation now appends at most sixteen prepared rows per timer invocation. A
cursor owns the unappended suffix and advances only after a successful append.
The whole suffix remains available to synchronous popup initialization, which
finishes it before Windows paints. There is no partial visible menu or loading
row. Separator normalization occurs after completion, across batch boundaries.
Root projections transfer the exact cursor with surviving native menus. An
append failure retains failed ownership and refuses replay or timer rearming.

The existing Menu.populate_leaf diagnostic includes the reason, appended row
count and remaining row count. It carries no label, trigger or user text. The
row cap bounds work; it cannot guarantee native-call or OS scheduling duration.
Timer gaps may extend total background warming; root publication does not wait
for them, and an actual popup request still completes immediately.

Measure through the production MenuPopulation owner and renderer: construct
384 command rows, seed the native menu, time each Pump with QPC, drain to
completion and assert the final native count is 384. Discard three warm-up
leaves and retain twelve measured leaves per process. No timer gaps are inserted
in this component measurement. The baseline owner in the last control is read
from git revision 61ed853592a16d6441c5cc945c82d2c0edfa7cd6 into an owned temporary
include; production files remain unchanged. The live driver remains running,
with no concurrent test or benchmark process during measurement.

The second candidate contains scheduling variation: one complete drain took
88.87 ms, another 63.27 ms. These samples remain included. Ordinary full drains
are approximately 20–28 ms; the purpose is shorter continuous Critical spans,
not a claim of lower total CPU or a strict per-batch deadline. This fixture uses
plain rows, so it does not predict flag-icon or other expensive native row costs.

Evidence: ergopti-input-menu-{baseline,candidate}-{a,b}.txt and their TAP/output
receipts under %TEMP%, generated by the retained private

because one Pump consumed the complete leaf; they now retain a real remainder.
Coverage includes before-paint completion, separators, unchanged seed tokens,
partial-root transfer and a failed later batch without replay.

## Hotstring output-host routing

Both ordinary and raw-callback expansions previously requested a fresh bounded
caption unconditionally. For a known terminal executable, the existing routing
predicate already answers true independently of that caption. The WM_GETTEXT
transaction was therefore unnecessary, including its five-millisecond timeout
against a busy target.

Both paths now use one canonical executable predicate to decide whether a title
is needed. Known terminal executables retain their pacing and HWND/PID fences
while skipping the caption. Unknown executables retain a fresh bounded title:
one editor HWND can become a Codebuff/Freebuff terminal without changing its
process or native identity. A predicate failure or malformed verdict refuses the
receipt and logs its failure. Focus changes and resolver reentry remain fenced.

The read-only native fixture uses the actual foreground HWND/PID, production
process/class acquisition and the production bounded title reader. Only its
metadata executable name is injected as WindowsTerminal.exe to exercise the
known-terminal branch without switching the user's foreground application.
Alternate title-required/policy/policy/title-required blocks, each with ten
discarded warm-ups and 120 retained receipts. Every receipt was valid and none
reported a timeout. These are resolver measurements, not end-to-end hotstring
send measurements or a benchmark of the actual Windows Terminal process.

| Resolver mode            | Receipts | Median, ms | p95, ms | Maximum, ms |
| ------------------------ | -------- | ---------- | ------- | ----------- |
| Former title requirement | 240      | 0.3254     | 0.6059  | 40.0069     |
| Known-terminal predicate | 240      | 0.0941     | 0.1536  | 0.2732      |

The old-mode maximum includes desktop scheduling; it is not attributed solely
to WM_GETTEXT. An earlier ordinary-foreground comparison found 0.3268 ms with a
title and 0.0862 ms without one. No title is skipped for ordinary GUI applications
merely to reproduce that gain.

Evidence: ergopti-input-title-known-terminal-policy.txt and its TAP/output receipt
under %TEMP%, generated by ergopti-input-title-probe.cjs. The new terminal-policy
test failed before resolver support because the title probe still ran. Tests now
cover every known executable, same-HWND editor title changes, focus change,
reentry and invalid/error verdicts. Existing bounded-title and paced-output
tests remain green.

These mechanisms are specific to AHK's single-threaded timers and Win32 title
transactions. macOS already classifies terminal application identities without
this caption transaction; Linux does not use WM_GETTEXT. Shared feature behavior
and declarations are unchanged, with no unsupported-feature reason to add.

## Tooltip and shortcut assessment

The 17:30 live presentation lines attribute approximately 1.2–1.5 ms to content
reveal, 0.7–1.5 ms to paint and 1.9–2.4 ms to border preparation. Repeated text
measurement already owns a bounded font-handle cache; native title/selection
workers and prediction span reuse also already exist. The warning snapshot does
not prove that whole-window pooling or shorter debounce delays would improve
complete tooltip latency safely. No such speculative change is introduced.

RemapEmit's warning maximum is 29.08 ms and its warning median 6.87 ms. Its native
send ordering remains unchanged: removing serialization or terminal pacing would
trade correctness for apparent throughput. Both shortcuts and tooltip callbacks
benefit from background menu preparation yielding between bounded batches, but
that end-to-end benefit has not been measured with physical input.

The full AHK suite passes 7754/7754 and its execution manifest is complete.
Focused native-menu, output-host and terminal groups pass 14, 10 and 7 cases
respectively. The title-deadline consumer census retains both conditional and
unconditional title acquisitions, with all three deadline cases passing.
Complete include-graph compilation and the real-process startup smoke pass;
pure expansion E2E passes 5/5. Encoding, strict conventions, HotPath inventory,
source census, pinned-read and false-green ratchets pass. Broader pre-existing
and filesystem-related JS/format failures are recorded in the
[menu pass](../menu_third_pass/report.md#regression-verification).
