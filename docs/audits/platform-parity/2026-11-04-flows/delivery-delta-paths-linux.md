## Two different “legacy” operations

`linux/infra/legacy_folder_migration.lua:86–109` plans config/state/data old-folder merges into each base's `ergopti` folder, then prepares the cache directory. It uses shared `legacy_folder_migration.lua` and native rename/list/mkdir ports. `ergopti_hotstrings.lua:125–126` executes it **before** logger/storage boot; its report is logged at line 161. Existing destination entries win; conflicting legacy entries are retained under `before-folder-migration/ergopti_plus`, not merged as preference keys. The explicit scope is maintainer installs: adapter header lines 19–21 says no Linux build was published with those old folders.

This must not be confused with LCF-001's later `infra.legacy_hotstring_storage.import`: that operation interprets storage aliases into TOML preferences and then retires alias keys. Successful folder migration can make the same old alias bytes available at the new bootstrap path; it does not fix failed alias retirement or clear LCF-001. If both old and new storage files exist, folder-conflict backup policy determines which file is active, so the historical exact install setup must be stated rather than claiming every legacy folder becomes active.

Locale canonical startup authority is still an existing `[script].locale` row adopted by `infra.script_scope`; native `storage.json` is still the locale alias. A changed directory does not alter the canonical-vs-native ordering relevant to LCF-002.

## Evidence compatibility and remaining limits

The retained config probes locate storage with `Storage.path()` and initialize isolated runner home; inspected `legacy-neutral-real-storage.lua` and `locale-split-commit.lua` do not hard-code the old native-store directory. Crypto short-write proof explicitly overrides entries into its scratch fixture. Clipboard probes use recording ports. These locator choices survive the folder change structurally, but this review did not replay them or transform historical receipts into delivery receipts.

Tests that stub `infra.config_paths` must now provide `default_config_dir()` when real storage/API entries are loaded; the production locale-persistence test was updated accordingly in this delta. The direct `i18n.lua` runtime body is otherwise unchanged. Audit prose naming `~/.config/ergopti_plus/storage.json`, `api_keys.json` or old log directories should be read as original-commit evidence and qualified with this delivery mapping.

Source-level equality was checked with immutable Git blob comparisons and targeted diffs. Initial sqlite-owner lookup used an incorrect `adapters/` path and failed; corrected tree lookup identified `modules/keystats/sqlite_writer.lua`, whose delta is empty. No finding was inferred from the failed lookup. This pass makes no claim about migration rollback, unusual filesystem names, live upgrade behavior, cache completeness, cross-device rename success or performance; those require their own migration audit/native checks.
