# Audit: cross-OS parity of the three drivers

Run on 2026-10-24 against `dev` (HEAD `71ee3804e2`, working tree dirty with other agents' edits).
Read-only: no source or test file was changed and no test suite was run. Scope: the Windows
(AutoHotkey v2), macOS (Hammerspoon Lua) and Linux (LuaJIT) drivers, and `_shared`. Maintainer goal:
the same behaviour on all three OS wherever possible, unless there is a good reason.

This report updates, and does not redo, [the test parity audit of 2026-10-18](2026-10-18-test-parity-audit.md)
(status of its work items in section 14). The prioritised TODO entries are in
[2026-10-24-cross-os-parity-todo-entries.md](2026-10-24-cross-os-parity-todo-entries.md); each entry
cites the row ids used here (`H3`, `C1`, ...).

## Method and provenance

Seven parallel read-only sweeps (hotstrings/tap-hold/layouts, AI and metrics, updater/diagnostics/
logging/performance, config/i18n/tests, centralisation, constants) plus a direct census of
`_shared/modules/features/manifest.toml` (python `tomllib`) and `_shared/modules/menu/menu_manifest.json`.
Every row carries a provenance tag in its evidence cell or in the section notes:

- **V**: the file, row or count was opened or computed by a script.
- **I**: inferred from names, sizes, headers or grep counts. Treat as a hypothesis until confirmed.

Verdict codes: **(a)** difference with a good reason, **(b)** difference without a good reason, align
(direction given), **(c)** missing feature on an OS, **(d)** UI-only gap (row, window, string,
shortcut). Effort: S under a day, M a few days, L a week or more. A reason counts as "stated" only if
it is in a menu `reason_key`, a driver doc or a memory topic; a reason found only in a code comment
or a test is flagged as unstated for the user.

## Headline

1. **The manifest declares restrictions without saying why.** Of 363 menu-manifest rows with a
   `platforms` filter, 288 have no `reason_key`; most are frames that split one control per driver,
   but the genuine feature gaps (per-app metrics exclusion, AI per-app profile overrides, layout
   pause switch, hotstring preview switches on Windows) have none. In `manifest.toml` 228 of about 380
   flattened entries are platform-restricted and only 14 carry a `reason_key` (V, scripts of this
   audit; counts depend on the flattener, re-run before quoting).
2. **Three names for one concept.** The metrics master switch is `metrics.metrics_enabled`
   (Windows) against `metrics.enabled` (macOS, Linux); the WPM readouts have three vocabularies
   (`wpm_widget_*`, `float_*`, `wpm_menubar_*` against `menubar_*`). The manifest `platforms` of at
   least four keys disagree with what the code reads (C5).
3. **Real behaviour divergences that no shared vector pins**: the repeat key (Linux doubles at a word
   start, the two others refuse), the complex-key time-gate multiplier (macOS only), the base
   expansion delay (three different keys), the word delimiter storage (Windows override file against
   config leaves), the Windows separator set (wider than Linux's three).
4. **Linux is the thinnest driver**: no per-app metrics exclusion, no LLM model delete or hardware
   ranking, no `think:false`, no LLM telemetry rows, no logger sub-files, no AI acceptance and
   autocompletion delay rows, no magic-key editor, fewer event tables in keystats.
5. **Windows is the thinnest on shared contracts**: no consumer of the 105 `_shared/lua/test`
   contracts, no preview-switch parity, no PhaseStats, hand-ported config migration and menu renderer.
6. **Duplication is by re-implementation, not by copy-paste.** `_shared` is clean of OS calls (V:
   no `hs.*`, `os.getenv`, `io.popen` or `os.execute` in `_shared/lua`), but it holds about 11% of the
   logic (60K lines against 222K macOS, 110K Linux, 222K AHK). Largest duplicated families: LLM
   prediction orchestration, menu frame builders, keystats queries and walker, hotstring override
   parser, storage and scope ownership protocols (section 15).
7. **Magic values**: 810 six-digit hex literals in 84 files (258 distinct), 111 timing/size
   constant names defined in more than one file (38 with different values), 41 of 145 timing keys
   with no reader, about 182 locale keys with no reference (section 16).
8. **Docs drift** misleads the next reader: `SCHEMA.md`, `logger/SPEC.md` ("Linux installs no sink"),
   `windows/README.md`, `linux/modules/README.md`, tooltip README, keystats README, the tap-hold
   "ONE global" threshold header, `platform_reason.llm_configuration_surface_is_not_on_linux`.

## 17. Limits of this audit

- Linux behaviour is read from source only; `linux_evidence.json` marks nearly every Linux feature
  `hardware_proven: no` or `unverified`. No driver, test or lint gate was run.
- Rows tagged I rest on grep counts or file inventories. In particular the Linux "missing" event
  families (S2), the Windows `metrics.enabled` read, the macOS release-notes page (U5) and the
  Windows/Linux crash-report rows must be confirmed before work starts.
- Counts of manifest entries come from a flattener written for this audit; the 2026-10-18 audit
  counted 369 features, this one about 380 flattened (140 top-level entries); both are
  method-dependent.
- Similarity figures (R-rows) are line-set overlap or 8-line windows after whitespace
  normalisation; they under-count same-logic-different-text, so real duplication is higher.
- The working tree carries many other agents' uncommitted edits (all locale files, the composer
  page, the TODO); values may move.
