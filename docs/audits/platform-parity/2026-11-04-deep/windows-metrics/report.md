# Windows × metrics: collection, privacy, persistence and projection

Audited SHA: `89b0b774c8c960c7ad458ac3cb98d5c97598e518`.
Date: 2026-11-04. Audit-only; no repository edits, commit or push. Completed Windows-hotstrings artifacts were preserved.

## Result and scope boundary

Two bounded passes found three new source-confirmed defects: movement-only pointer distance never flushes (WM-001); enabled encryption leaves durable raw journals in plaintext (WM-002); explicit dashboard cache reset leaves its durable reader image reusable (WM-003). These were not the previously documented missing Linux collectors or Windows-only raw event families. All findings include reproducible native procedures below; none is represented as live Windows execution.

This pass covers the raw typing/mouse/automation producers, central admission, journal and SQL ingestion, state/replay, reader cache and dashboard reset, plus pause/privacy/shutdown boundaries. It does not exhaust every native collector, SQL query combination, encrypted-store migration failure or physical focus race. The native AHK environment was unavailable. Paths below are relative to `static/ergopti_plus/` unless a `docs/` or `tools/` prefix is shown.

## Pass 2: backward ownership and adversarial sequences

- **Motion -> flush -> quit:** start with no keystrokes/clicks/scrolls and positive mouse distance. `KL_FlushBuffer` reports success immediately at `keystats.ahk:667-670`; no row owns that distance. Even if a caller directly supplies a distance-only snapshot, `_KL_PublishBufferSnapshot` returns success before `KL_AppendLog` (:734-735). `KL_Stop` treats this successful flush as drained (:1227 onward), then sets initialized=false. This is WM-001, not merely delayed sampling.
- **Motion -> app change -> subsequent typing:** outgoing context attempts the same flush and then advances session_app. Distance remains in the global accumulator and can be emitted under the new app's later typing row. This is a secondary attribution consequence of WM-001, source-confirmed; native event-order timing was not measured.
- **Pause / reset with pending text:** collection pause is deliberately independent of driver pause and privacy filters (`keystats_collection.ahk:32-58`). It attempts a flush before setting its flag. Unlike session reset it does not require a true flush receipt; retained state can be retried. Existing tests intentionally allow pausing when a seam returns false. This difference alone was **not** reported as loss without a native failing scenario. Session reset explicitly refuses failed flush or failed session close (:112 onward).
- **Current focus differs from payload context:** `KL_AppendLog` rechecks payload app/title as well as live privacy. This refutes a naive claim that a focus-cache verdict always authorizes outgoing private titles. Secure field uncertainty is fail closed; no password-coverage guarantee is inferred without UIA runtime.
- **SQL append fails after journal succeeds:** checkpoint remains old, durable raw line remains, next ingest replays the same stable ID. Failure to save state likewise retains offset for replay. These paths were source-inspected; native disk-full/share-lock injection was unavailable.
- **Enable encryption -> input -> ingest:** journal JSON contains the literal text/events; later SQL uses encrypted values. Journal is retained through normal operation until rollover; failure/migration can extend that exposure. At-rest migration rewrites data.sql (module header :12-26), explicitly leaving today.log buffering, and does not remove its plaintext. WM-002 applies before and after successful SQL conversion.
- **Reset -> fresh worker -> no new ledger tail:** reset deletes prefetch JSON, but preserved reader.sqlite attaches in the worker. With unchanged ledger, the disposable-reader branch returns its existing aggregates (`keystats_reader_db.ahk:258-266`). Thus a reset cannot force those aggregates to be rebuilt. Native reset-owner tests replace the external worker and never create this durable image, so they do not refute WM-003.
- **Suspend / shutdown:** central guard prevents new content rows while paused, with designated closing/lifecycle exceptions. `KL_BeginShutdown` owns the terminal lease, producers stop before final flush, retryable durability failures refuse shutdown. `KL_Stop` includes cancellation of prefetch and migration work. No broad claim that native timer cancellation always succeeds was made.

## New findings

### WM-001 — movement-only pointer intervals never persist

Severity medium, confidence high, G2 (silent missing output).

Root cause: both empty-state predicates in `windows/modules/keystats/keystats.ahk:667-670` and :734-735 test events/clicks/scrolls but omit mouse distance. Distance is accumulated independently by `keystats_mouse.ahk:637-645` and `KL_BumpMouseDistance` (:1317).

Reproduce in an isolated Windows session: initialize metrics with no key/click/scroll data, set/supply valid movement samples so `Keystats.mouse_distance > 0`, then call the real flush. It returns true, leaves distance unchanged and queues no typing event. Quit without other input: no distance row reaches data.sql. Deterministic native fixture should also directly pass a distance-only snapshot to the real publisher to cover both predicates. On focus change followed by typing, verify the old app owns movement rather than the successor.

The visible effect is missing or misattributed pointer distance; collector success and flush success are silent. macOS shares the bug: `_detach_buffer_snapshot` in `macos/modules/keystats/log_manager.lua:572-575` has the same omission. Linux differs: `record_pointer` (:1170-1182) creates `pending.mouse`, and `capture_flush` (:2262-2274) emits a row even with no keyboard events. This is accidental drift/common bug, not a documented intentional difference. Regression should assert distance conservation across movement-only flush, app switch, pause, rollover and shutdown on Windows/macOS, with Linux as a comparator.

### WM-002 — “Encrypt logs on disk” leaves raw journal text and events in plaintext

Severity high, confidence high. Confidentiality failure; G1-G5 do not directly encode confidentiality, so the finding's guarantees array is empty.

The setting is labelled “Encrypt logs on disk (Security)” (`_shared/data/locales/en.json:2035`), with explicit shared menu rationale that it protects logs on disk (`_shared/modules/menu/menu.toml:2002-2006`). `KL_AppendLog` queues the raw typing map, including text and per-key events. `keystats_ingest.ahk:256-259` writes `KL_JsonEncode(e)` directly to today.log; the durable journal handoff likewise uses `_KL_JournalEncodeDefault` (`keystats_journal.ahk:82`, :369). `keystats_json.ahk` is a generic codec with no encryption. Encryption occurs later in `keystats_sql.ahk:68-69` for SQL text/events_json only. `today.log` remains present until rollover (`keystats_rollover.ahk:103`), including already-consumed records.

Reproduce with synthetic text in an ordinary permitted editor: enable encryption and wait for any migration to complete; type a unique non-sensitive marker; wait for ingest/native durable flush. Read the local device's today.log and data.sql without waiting until midnight. Expected current behavior: marker and key sequence remain readable in journal; SQL typed-text values are encrypted. Repeat while forcing SQL conversion/append failure: journal remains plaintext and retryable. This exposure does not require encryption failure or password-filter failure.

Documentation qualification, read after the first report: `static/ergopti_plus/docs/security/keystats_privacy.md:77-103` explicitly describes ordinary plaintext text in both today.log and data.sql as an accepted default trade-off, then recommends disabling keystats **or enabling at-rest encryption** for plaintext privacy. It narrowly describes encrypted SQLite `events_typing.text`/`events_json` fields and explicitly permits clear aggregates. It also promises protection against off-machine disclosure (disk theft, backups, synced folders), while disclaiming same-machine secrecy because keys derive from machine identity. Therefore this finding does not challenge intentional default plaintext, selective clear aggregates or the stated local-attacker limit: it identifies an unprotected durable raw-journal copy under the encryption opt-in, which can itself be backed up/copied off machine. The narrow DB-column mechanism explains the implementation, but the document provides no explicit journal exception to the broader recommended/off-machine protection. Product must either cover that copy or accurately state the residual scope; severity reflects readable protected raw text, not a claim of whole-store encryption.

Comparison: macOS `rotation.lua:313` also directly json-encodes raw entries into today.log before aggregation/encryption. Linux has no equivalent append-only raw JSON journal; inspect its DB/WAL/temp behavior separately rather than infer that it has no other exposure. No explicit plaintext-journal exemption was found. The Windows migration comment treats data.sql as data at rest but that does not make the durable today.log nonpersistent; an intentional architecture choice was not established for this gap.

Regression: real journal disk-file scan under enabled encryption, before/after ingest and after restart; assert both marker text and recoverable per-key payload are absent while replay still reconstructs identical aggregates. Cover migration during active input, failure and retained journals, plus macOS. Encrypting only the SQL copy or deleting clear files after writing does not fix plaintext journal persistence.

### WM-003 — explicit cache Reset preserves the reader image it promises to clear

Severity low, confidence high, G2. No everyday aggregate corruption is asserted; this breaks explicit cache-recovery behavior.

`windows/modules/keystats/keystats_webview.ahk:700-725` says all layers are purged for a full cold read, calls `KLR_ResetCache`, and deletes only `KLPF_PrefetchPath`. `KLR_ResetCache` at `keystats_reader_db.ahk:139` closes RAM state only. Durable `KLR_CachePath` is `cache/reader.sqlite` (`keystats_reader_cache.ahk:86`). The spawned full worker still calls `KLR_BuildDatabase` (`keystats_prefetch.ahk:1016`), restores the same image (:218) and returns unchanged cached aggregates with no new ledger tail (:258-266). No explicit reset-generation or force-cold argument reaches it.

Reproduce on a private synthetic store: build a valid reader image, leave ledgers unchanged, set a recognizable wrong aggregate in that image while retaining valid cache metadata, open dashboard and issue actual Reset. Inspect the resulting read path or aggregate: preserved reader image is reused. Also use a non-mutating diagnostic fixture to assert reset must retire/revoke the observed reader-image identity before the successor build. Existing clear-cache-owner tests only cover prefetch file/RAM and stub the external worker, so miss this layer.

The symptom is failure to recover derived aggregate state despite a successful “caches purged” diagnostic. macOS resets its Projection and removes its own snapshot (`macos/ui/metrics_typing/init.lua:210-225`); Linux clears its manifest cache (`linux/modules/keystats/keystats.lua:1435`), appropriate to its direct authoritative DB. Neither has this exact Windows durable reader-image layer. Normal warm reuse is explicitly intentional and measured; failing to revoke it for an explicit full reset is not documented as intentional. Regression must use a real saved reader image and actual subsequent worker, while fencing peer publication/active jobs and preserving unrelated stores.
