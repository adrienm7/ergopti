# Windows word-reset and AI-context continuity audit

Audited commit: `b17e47ed3bb92c106703d3e3482b3c2973f5bc1e`.

Two source-confirmed roots: synthetic modified Backspace asserts a word boundary that the equivalent physical event explicitly refuses to promise; complete AI context survives edited/selected text through physical shortcut branches. No AutoHotkey, native Windows input, editor, actual request or private data was executed or accessed. The source-contract Python program authenticates 22 exact pinned files and checks 24 lexical relationships. Those are source checks, not runtime tests or a translation of AHK. No latency, memory leak, native delivery or G4 claim is made.

## Scope and ownership

The reviewed module is word context: ordinary/modified arrows and navigation; plain/modified Backspace; Ctrl+Z/Y and Select All; terminal Enter versus multiline Shift+Enter; Escape/Tab; idle reset and recovery; tap-hold command/held modifier/layer attribution; runtime setting publication; hotstring versus prediction/agent context; lifecycle generation and observer handoff.

`_OnPrefixKeyDown` first records the physical input generation and revokes programmable input ownership, checks pause and an already claimed end key, applies idle policy, handles Ctrl+F/L focus relocation, revokes incomplete fragments, then routes modified Backspace, generic shortcuts, plain Backspace, Space and the context-reset navigation class. The two LLM key-feed calls are only in the final plain-Backspace and navigation branches. A hooked prefix character separately enters `LLM_Bridge_FeedCharForPrefix` and the hotstring matcher under a serialized transaction.

`HS_CommitSyntheticEffect` is the separate declaration owner for driver-produced input. Real `TextPressKey` calls funnel through `_TextSenderSendInput` -> `HS_RunSyntheticInputTransaction`, which commits the RAM declaration and OS send in one Critical span. It returns presentation work to run afterward; failed/partial sends invalidate precise context, and the error remains observable. The declaration is required because every native sender runs at SendLevel 0, below both I1 InputHooks.

## WRSW-001 — Synthetic Alt/Win+Backspace invents a known word start

Severity: medium. Confidence: high for the actual source chain. Additional property: `physical_synthetic_word_boundary_parity`; no G1–G5 claim and no native reproduction.

Reproduction projected from the exact source:

1. In a stable ordinary editor, use the supported `send_shortcut` action parameter `alt+backspace` (or `win+backspace`). The action exists on all platforms in `_shared/modules/actions/actions.toml`; the actual shared vocabulary admits `alt`/`win` and named `backspace`. A gesture or tap-hold binding can dispatch it; this is not a helper-only synthetic payload.
2. The actual `GestureSendInput` -> `SendInputParse` -> `SendInputEmit` path reaches `TextPressKey` with Alt plus Backspace. Its successful payload `!{Backspace}` enters `HS_RunSyntheticInputTransaction` -> `HS_CommitSyntheticEffect` before OS emission. `HS_SyntheticPayloadKind` excludes modified Backspace from configurable shortcuts and returns `edit`.
3. For a successful nonfragment edit, the owner uses `KnownBoundary := !SendFailed && !IncompleteContext`, then `_PrefixCommitInputContext(0, KnownBoundary)`. It therefore clears the buffers **and sets the next run's start true**, including Alt/Win+Backspace.
4. A physical Alt/Win+Backspace goes through `_OnPrefixKeyDown` -> `_PrefixInvalidateInputContext(_PrefixFocusedControlToken, _PrefixWordDeleteChordHeld())`. The latter accepts only real Ctrl without Alt/Win, so it resets to **unknown false**. This is the explicit policy: the deletion/undo amount is unknown. The existing genuine physical test asserts that Alt+Backspace “promises no word start.” The shared manifest says these siblings forget the word by an unknown amount regardless of the shortcut toggle.
5. After the synthetic owner sets focus token zero, a subsequent resolved focus does not repair the false promise: `_PrefixEnsureInputContext` deliberately preserves `HSE_StartIsWordBoundary` for an unbound context. A word-only immediate `r` -> `R` mapping can therefore fire after synthetic Alt+Backspace at a position whose word start is unknown, while the physical equivalent correctly refuses. In a native editor where Alt+Backspace undoes an edit and leaves the caret inside an older word, this can replace text unexpectedly. That editor interaction remains unexecuted; the source-established difference is the published boundary verdict.

Root cause: generic successful synthetic `edit` has one blanket boundary result. It does not distinguish Ctrl's known previous-word deletion from Alt/Win's unknown undo/delete semantics. This is separate from the preceding module's Linux repeat/reset finding: no repeat is involved and neither a Linux ACK nor its default reset establishes this result.

Visibility: the transport and context commit can both succeed; the DEBUG line says both buffers reset, but does not identify that the boundary promise is stronger than the physical path. An exception backstop cannot reveal valid-but-wrong state.

Controls: Ctrl+Backspace legitimately starts a word; ordinary Backspace decrements by a complete scalar; failed output clears the known boundary rather than promising successful movement; arrow and shortcut off settings intentionally retain context according to their policy. None of those controls justifies successful Alt/Win+Backspace advertising a word boundary. No full native test was run.

Regression direction: execute real parsed `send_shortcut` -> TextPressKey -> canonical synthetic effect and physical keydown equivalents in genuine AHK with faithful output/focus recording seams. Cover Ctrl/Alt/Win/Shift combinations, stale/unbound/same focus, fragment and send refusal, all three setting values. Compare actual matcher boundary and whether word-only/in-word mappings fire afterward. Keep declaration and native output serialized; do not weaken send/focus fences or pretend every context must start a word.

Evidence owners: `infra/send_input_parameter.ahk:402–428`; `adapters/text_sender.ahk:495–535,1027–1070`; `infra/hotstrings/hotstring_buffer_effects.ahk:78–93,152–223`; `infra/hotstrings/hotstring_inputhook.ahk:1245–1268,1790–1803`; actual physical control `tests/unit/modules/hotstrings/engine/test_hotstring_event_word_reset.ahk:262–273`.

## WRSW-002 — Physical editing shortcuts leave complete AI context unchanged

Severity: medium. Confidence: high for the source chain. Additional property: `ai_context_continuity_after_unknown_edit`; no G5 prediction-quality claim and no actual network/persistence measurement.

Concrete source reproduction: activate predictions with normal complete text context and `reset_on_nav=true`; in a stable control type `OLD_WORD`, press Ctrl+Backspace to delete the word, then type `x` before an idle reset. Alternatively select all with Ctrl+A, then type `x`, replacing that selection. The equivalent agent-only setup has predictions off, automatic agent typing observation on, and `_LLM_Bridge_AgentFeeding=true`. There need be no prediction already loading or visible.

The source owners produce this sequence:

- `_OnPrefixKeyDown` handles modified Backspace in an early branch, invalidates the hotstring input context and returns before either LLM key-feed call. The generic shortcut branch—including Ctrl+A/Z/Y—likewise invokes `HS_ApplyEventWordReset` and returns early. Ctrl+F/L have another earlier focus-reset return; this audit's decisive scenario stays in one control and does not depend on those focus paths.
- `_PrefixCommitInputContext` and `_PrefixRevokeIncompleteFragments` call only `LLM_Bridge_DiscardIncompleteInput`. Its explicit contract is to discard **incomplete UTF-16 contexts**. For an ordinary complete ASCII buffer it immediately returns false, preserving `_LLM_Bridge_Buffer` and `_LLM_Bridge_AgentBuffer`.
- The bridge's dispatcher key fallback is deliberately disabled whenever the normal `_PrefixInputHook` exists, so it does not provide a second shortcut notification. `KS_RecordPhysicalKeyDown` increments a generation; it does not clear or edit either AI text buffer.
- The next physical `x` enters `LLM_Bridge_FeedCharForPrefix`, which applies `_LLM_Bridge_ApplyBufferEdit(0, ch)` or `LLM_Bridge_MirrorAgentEdit(0, ch)` to the retained complete context. It therefore appends `x` to the obsolete `OLD_WORD`, despite the application having deleted/replaced it.
- A **fresh** prefix observer captures the new physical generation/focus and forwards the current stale semantic text to `_LLM_Bridge_NotifyChar` -> `LLM_Agent_OnTyping` / `LLM_Engine_OnKeystroke`, or directly to `LLM_Agent_OnTyping` for agent-only mode. Existing physical/content/focus receipt checks reject old observers and old output correctly; they cannot distinguish the new observer's already incorrect context.

Root cause: model invalidation for an unknown edit is implemented only for the hotstring/preview buffers. The bridge notification lives below early returns; incomplete-fragment revocation is mistakenly the only bridge edit on those paths. `reset_on_nav` is checked inside `LLM_Bridge_ResetPredictions`, which these branches never call, so the reproduction is not a user choosing context retention by setting that option false.

Visibility: complete buffers are valid strings and the new observer owns current input; every call can succeed. Length-only diagnostics and stale-output generation guards report no semantic mismatch. Existing idle-navigation tests directly call the bridge's reset/forwarded key entry for arrows/Home/etc.; that does not exercise real prefix-hook shortcut branching. No assertion here says that an arbitrary natural-language prediction must be correct, or that deleted words were actually transmitted during this audit.

Related synthetic gap, retained under this same continuity root: successful `HS_RunSyntheticInputTransaction` declarations edit the matcher/preview but contain no AI/agent full-buffer edit for a driver-produced Backspace, Enter/Tab/navigation or shortcut; SendLevel 0 intentionally prevents hook echo. A tap-hold Enter/Tab or custom synthetic navigation therefore needs explicit AI-context semantics as well. A plain physical arrow reaches the normal bridge reset, physical plain Backspace removes one scalar and physical Enter/Tab/Escape flushes; these are positive source controls, not evidence that synthetic siblings were received.

Regression direction: genuine AHK dispatch through `_OnPrefixKeyDown` with the actual complete bridge/agent owners and recording application/output/observer seams. Assert correct empty/known edited context after Ctrl+Backspace and Ctrl+A replacement for active predictions and agent-only mode, including no active request. Include Ctrl+Z/Y, Alt/Win+Backspace, Ctrl+F/L, Ctrl+V, source layouts/AltGr, tap-hold modifier/command sources, synthetic keys and failed send; retain explicit reset_on_nav=false policy. Check the exact buffer passed to the new real engine/agent observer and preserve cancellation/focus/admission guarantees. Do not fix by weakening stale-owner checks, enabling self-echo or blindly decrementing a whole-word deletion by one scalar.

Evidence owners: `hotstring_inputhook.ahk:1025–1040,1128–1140,1746–1859`; `hotstring_buffer_effects.ahk:113–130,152–281`; `modules/keymap/llm_bridge.ahk:166–184,1076–1088,1158–1205,1243–1266,1287–1314,1447–1507,1688–1704`; `adapters/key_state.ahk:228–260`; `adapters/text_sender.ahk:136–148`.

## Policy, intentional differences and qualified ambiguities

| Aspect                              | Policy and source-qualified comparison                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Idle                                | Shared default/recommended 3 s, zero disables. Windows evaluates idle before controls as well as text, retaining an exact forgotten word for an immediately following Backspace. macOS skips a bare-Backspace idle wipe; Linux evaluates typed character idle. Routed `project-backspace-word-start` explicitly documents these architecture differences.                                                                           |
| Arrow switch                        | Shared default/recommended true; all modifier combinations remain governed by arrow policy. Off intentionally leaves the word open after caret movement. This is a deliberate setting, not an automatically filed safety defect.                                                                                                                                                                                                    |
| Shortcut switch                     | Shared default/recommended true; native Ctrl/Alt/Win combinations count; Shift and layout-specific AltGr alone type. Off intentionally keeps word context across Ctrl+V or Ctrl+Z, as the manifest states. AI context has its own reset-on-navigation policy.                                                                                                                                                                       |
| Tap-hold switch                     | Windows/Linux support a separate switch. macOS explicitly cannot distinguish Karabiner tap-hold origin from ordinary input and follows the shortcut switch; manifest reason is explicit. This preexisting documented availability gap is not a new finding.                                                                                                                                                                         |
| Tap-hold ownership                  | Windows recognizes current command tap, owned Ctrl/Alt/Win modifier and active nav layer; native modifiers and Shift/AltGr retain their own semantics. Generated/synthetic arrows stay governed by arrow policy.                                                                                                                                                                                                                    |
| Backspace and select-all            | Plain scalar decrement; Ctrl+Backspace known word start; physical Alt/Win+Backspace unknown; Ctrl+A outside terminals promises a selection whose replacement empties the field. Native inline autocompletion can consume a suggestion rather than a typed scalar; the routed memory explicitly marks this as a known limit.                                                                                                         |
| Enter                               | Bare terminal Enter records known empty line; Shift+Enter does not. Physical Enter/Tab/Escape clear AI context. Windows holds Enter/Tab only when completing a hotstring to avoid editing a new prompt. | Modified Home/End/Page Up/Page Down | Actual Windows physical and synthetic paths classify these modified keys as shortcuts; off keeps the word. Bare navigation still resets. Manifest wording says both “other navigation keys still forget” and broadly “a key struck with Ctrl/Alt/Win” follows shortcut policy. The modifier scope of the former promise is not explicit. This is a documented policy ambiguity, **not a third confirmed bug** without adjudication. |
| Settings/runtime                    | Getters use shared defaults before load; boot validates types/finite idle values with a loud outdated-value warning; setters publish only after durable config gateway acceptance and read runtime live without reload. A refused menu rebuild after an acknowledged write is not evidence that the write failed.                                                                                                                   |
| Lifecycle                           | Prefix pause/shutdown retire deferred owners and incomplete units; global lifecycle hard-resets the matcher. Bridge stop retires prefix observer/dispatcher/pointer watch and active context, with separate agent feed reset. ## Test trust, refutations and closure

Read actual event-word-reset, idle/click reset, Backspace word-start and LLM navigation test owners. The event tests genuinely check physical Alt+Backspace unknown state and arrow/shortcut/tap-hold policy; they do not pass the same Alt+Backspace through parsed public synthetic input or inspect complete AI context after real prefix-hook shortcut branching. The navigation context tests have behavioral assertions but directly call reset/bridge-forwarded navigation entry points. They are narrower evidence, not full owner integration.

Refuted/qualified: mandatory reset for every modifier chord (shortcut-off is explicit policy); tap-hold macOS discrimination as a newly discovered bug (known explicit restriction); repeat fallback resetting the Linux boundary (prior module URL-001, not this Windows root); failed synthetic edits asserting a boundary (SendFailed correctly yields false); surrogate fragments surviving reset (separate incomplete-unit ownership exists); idle Backspace losing its old word (generation-bound recovery exists); a stale old prediction observer defeating physical-generation admission (receipt checks do reject it; WRSW-002 uses a newly captured observer); formatting G4/lag or memory-growth claims from source alone (unmeasured). A hypothetical 49-day idle tick rollover is refuted by the supported runtime's 64-bit A_TickCount domain, explicitly documented in `infra/tick_count.ahk`; the legacy modulo32 helpers apply to DWORD origins and must not be mistaken for the native clock width. Extremely large free idle numeric input could require a native AHK conversion edge check; no runtime evidence was available and no speculative finding is counted.

After the final two confirmed roots, two complete bounded dry sweeps revisited all coverage aspects and both decisive chains. Each authenticated the same 22 files and reran the same 24 lexical checks against the pinned source. Each found zero further confirmed roots. `dry-sweeps.json` identifies the retained `.txt` stdout receipts. This closes this bounded source review, not all possible native/OS behavior or the repository audit as a whole.

Native gaps: AutoHotkey parse/runtime; genuine InputHook modifier/OnChar ordering; public gesture/tap-hold binding receiving; actual Ctrl/Alt/Win editor operations and clipboard/application Undo semantics; SendInput fallback when another hook runs; target-app deletion/grapheme behavior; real engine HTTP and agent callbacks; widget/menu and user-choice receiving; latency and native owner memory lifetime. No production or registered test code changed.
