## Result and proof boundary

Two newly confirmed source-level failures concern **different boundaries** of selection commands: startup can clear/copy after an external foreground-window change (WCP-001); transformed/wrapped output can paste into a new foreground window after later clipboard preparation (WCP-002). Physical-generation/pause variants require caller-specific native scheduling evidence and are not independently certified by the supplied fixtures. Neither duplicates WH-001 or WM findings, prior input/gestures findings, or existing TODO entries found in the 18 deep reports. Searches were explicitly against `docs/audits/platform-parity/2026-11-04-deep/*/report.md` and TODO, then relevant historical Windows audit references.

All Windows findings are derived from actual production source and reachable caller chains. Python source assertions executed; native AHK probes are provided **unexecuted**. No Windows desktop/native input, clipboard, UIA, receiver or timer was exercised. The probes do not imply native runtime success. Scope is the Windows clipboard/selection flow, with source comparators on other OSes; other agents own full macOS/Linux audits.

The sweep continued after finding defects. Passes 3 and 4 below were consecutive dry passes with no further confirmed issue; this does not certify every native interleaving or native API receipt.

## WCP-001 — external foreground changes do not revoke startup before clipboard clear/copy

Severity **medium**, confidence **high**, guarantees **G2/G3**. Source-confirmed; no native execution.

`GetSelectionAsync` records the initiating physical-input generation (`infra/hotstrings/hotstring_send.ahk:765`) and foreground before `CB_SaveAll`. After potentially yielding snapshot it calls `_SelectionCaptureStartCurrent`, then clears the clipboard and sends Ctrl+C. The helper at :875 only checks A_IsSuspended, the active job object and request ID. It never compares HWND or `Job["generation_fn"]()` with the captured physical generation. Those comparisons happen later in `_SelectionCapturePoll` (:915-924), after irreversible clipboard mutation and copy emission.

**Primary retained sequence:** invoke case-change/wrap/Search on selected text; the OS foreground changes externally while snapshot/preparation runs; snapshot returns. This does not depend on an AHK pseudo-thread preempting a Critical caller. Physical-generation-only schedules remain source-level hypotheses unless their real callback timing is established. No explicit GetSelectionCancel occurs for ordinary input—its only production caller outside the function is lifecycle suspend. Startup still clears the clipboard and emits Ctrl+C into whatever now has focus. The poll later cancels as “superseded by input” or “foreground changed”. If a new user copy occurred after the saved snapshot but before clear, the eventual owned-clear restoration can replace that newer copy with the older snapshot. The loss requires that specific timing, not every focus change.

**Why hidden:** the later cancellation looks successful and logs its reason; it cannot undo copying from the wrong context or recover a user copy already cleared. Existing startup tests (`test_hotstring_send_failure_containment.ahk:_SCSC_Startup`) inject pause, explicit cancel and nested GetSelection requests, all of which alter a helper input. Existing physical-generation tests alter generation only after startup. They do not cover this transition. No test result is inferred from reading them.

**Reproduction artifacts:** `probes/selection-startup-foreground-probe.ahk` is the primary externally changed foreground port scenario, using actual GetSelectionAsync; it is unexecuted. The older unexecuted `probes/selection-startup-native-probe.ahk` calls the actual public GetSelectionAsync with recording save/clear/send/sequence ports. Its save boundary advances only the physical generation; baseline accepts startup and records one clear and one copy. No real clipboard output is needed in that isolated harness. `probes/source-evidence.py` verifies the actual source order and missing fields, but is not a substitute for running AHK.

**Regression:** invalidate physical generation and HWND separately inside foreground/save/clear/copy preparation boundaries. Before the first mutation, assert refusal with zero clears/copies and no restore over a newer clipboard value. After mutation, assert exact-token cleanup and latest-copy preservation. Preserve the explicit rule that releasing the initiating chord alone must not cancel. Other OS comparators: Linux `modules/shortcuts/manager.lua:592-597` captures destination before `Clipboard.transform_selection`, which receives a publication/current guard; macOS uses its owned text-action scope/transaction. Native equivalence must be tested rather than assumed.

## WCP-002 — selection output loses original destination admission during clipboard preparation

**Evidence qualification:** the confirmed source path is an external foreground change. Typed wrapping explicitly releases Critical, so ordinary pause is not globally ruled out; however directly calling Suspend in a fake SaveAll does not prove the full native ToggleSuspend/lifecycle schedule. That schedule remains unexecuted.

Severity **high**, confidence **high**, guarantees **G2/G3**. Source-confirmed; native Windows timing/output unexecuted.

Capture completion correctly checks physical generation/foreground/pause before invoking `_GestureSendTransformedSelection`. UIA wrapping correctly consumes a current selection snapshot. Their next operation is **SendInstant**, whose source (`infra/hotstrings/hotstring_send.ahk:486-580`) acquires clipboard ownership, snapshots through `CB_SaveAll` (:542), writes (:551), arms restoration, and sends Ctrl+V (:563) with no pause/foreground/control/physical-generation predicate after preparation. `_SelectionCaptureJob` has already retired before the transform continuation, so lifecycle GetSelectionCancel cannot revoke that executing output. Typed-symbol wrapping explicitly releases caller Critical across this round trip (`modules/keymap/layout.ahk:630`), and clipboard operations can yield.

**Reachable sequence:** transform a selected text or wrap it by typing a symbol; let preparation of the output clipboard snapshot yield (clipboard reader contention/rich-format rendering is a native way to create the boundary). Pause the driver or change focus/selection while this preparation is in progress. Resume the interrupted stack: it writes the prepared old selection and emits Ctrl+V despite the pause or changed target. This can replace text in the new context. UIA invalidation/capture cancellation alone does not reach the sender's already-owned local text. Native scheduling/receiver behavior has not been observed here; the code path itself contains no final admission.

Plain paste has the same missing destination/pause boundary in `GesturePastePlain`: snapshot and native ownership CAS authenticate **clipboard contents**, then SendFinalResult emits without a destination/pause guard. Its native CAS should not be confused with destination admission. This sibling is included in the regression class, not counted as another defect.

**Why hidden:** the sender reports successful primitive emission; its restore protects clipboard ownership but says nothing about the destination. Tests of SendInstant clipboard custody use the real caller's Critical contract around a private Edit and test current/newer/same-text copies. They do not revoke driver pause/selection destination while open-thread wrapping preparation yields. TextSender's atomic-admission option and native editor re-admission are real safeguards, but these transformation callers use SendInstant/SendFinalResult rather than that guarded path.

**Artifact:** `probes/source-evidence.py` extracts the exact SendInstant and verdict bodies and generates `sendinstant-pause-native-probe.ahk`. Only the native clipboard/send boundaries are recording functions; the fake snapshot changes the isolated process's paused state. Expected baseline observation is suspended=1 with one write/one send/result=true. The generated AHK is explicitly **unexecuted**; Python only verified source structure and recorded its exact body digest.

**Regression:** carry immutable HWND/control/input generation and a pause/lifecycle generation from selection admission through the last output boundary, then test changes inside SaveAll/receipt/restore/timer preparation. Assert no stale clipboard write/paste, correct original pressed-symbol fallback where appropriate, exactly-once synthetic guard retirement and clipboard recovery. Include asynchronous case transform, explicit wrap, typed wrap, plain-paste and clipboard-free fallbacks. macOS text actions have parent scopes and guarded transaction stages; Linux captures publication before injection/transform. This comparison establishes existing per-driver ownership mechanisms, not comprehensive proof the other OSes are flawless.
