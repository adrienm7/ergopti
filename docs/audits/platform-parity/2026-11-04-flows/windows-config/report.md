## WCF-001 — widget coordinate writes have no tuple transaction or acknowledged recovery

Severity **low**, confidence **high** for source-derived failed compensation. Reviewed criterion: promised durable storage-pair consistency. The conditional reentrant schedule is not native G3 proof. No AHK/Registry execution.

Actual owner: `windows/ui/wpm/wpm_config.ahk:_WPMWidget_StorePosition` (:306-327). It writes X then Y with separate `Store.Call`s, and publishes RAM after both return true. On failure it executes two `try Store.Call(previous)` statements without checking either Boolean/exception receipt, retains no retry debt and reports only the initial persistence failure. The source comment explicitly says a half-written pair never reaches the next boot. Actual `Store` is `_WPMWidget_StoreSet` -> ST_Set -> Reg_WriteString, whose post-write logger/native boundary can yield; the position owner has no lease or tuple serialization across those calls.

**Failure sequence:** durable/RAM anchor starts (10,20). Drag/reset requests (100,200). X=100 succeeds, Y write refuses, then X/Y recovery attempts also refuse (e.g. the store remains unavailable). Helper returns false and RAM remains (10,20), but Registry contains (100,20). Drag-end restores the native surface from RAM (`ui/wpm/wpm_widget.ahk:497`), so the mixed durable pair remains hidden until a later launch reads both numeric coordinates. Initial failure is reported loudly; the _failed compensation and durable mixed pair_ are not separately reported or retained. This finding does not claim the primary write failure is silent.

**Reentrancy sequence with all writes successful:** outer call requests (100,200), commits X=100, then is interrupted during its storage/native/logger boundary by a second position operation (300,400). Nested call writes both and publishes (300,400); outer resumes writing only Y=200 and publishes RAM (100,200). Registry is now (300,200), a tuple requested by neither action. There is no failed receipt or error notice in this branch. A controlled StoreFn can reenter at the exact first-write boundary and demonstrates the owner logic; real Windows event timing has not been executed or measured.

**Reachable callers:** widget drag end, reset-position command and graph/display configuration helpers use this owner. Other config.toml setters use stronger central leases; moving the widget was explicitly designed to persist via runtime Storage instead of config.toml.

**Existing test limit:** `tests/meta/ui/wpm/test_wpm_persistence_transaction.ahk:_WPMPT_PositionGoesToStorageNotConfig` verifies source ordering and the presence of failure reporting, not successful rollback receipts, recovery debt or tuple concurrency. WPM coordinate-load tests prove both coordinates numeric/visible, so a mixed pair of valid numbers is accepted and does not expose this error by validation.

**Evidence/probe:** executed `probes/source-evidence.py` asserts actual separate write/unchecked compensation structure and extracts the verbatim owner body into `probes/wpm-position-rollback-native.ahk`. The AHK contains recording Storage boundaries for both failure and nested-success sequences; no Registry function is invoked by that isolated probe. It remains **unexecuted** because no native AHK environment exists. `logs/source-evidence.txt` records exact body digest and audited SHA. Source assertions are not runtime tests.

**Regression:** execute the actual owner with storage effects and receipts recorded, covering first failure, second failure, recovery false/throw, reload with retained recovery and reentrant successful position changes at every storage boundary. Assert either a single atomic tuple publication or an exact outstanding recovery obligation; no accepted mixed tuple. Test actual drag/reset/graph caller behavior as well as the owner. Linux `ui/wpm/widget.lua:105` uses Storage.set_many for both coordinates; macOS `ui/wpm/wpm_widget.lua:339-340` still sets X/Y separately, so inspect its caller/receipt policy independently rather than claiming cross-OS correctness from shared WPM data.
