# ErgoptiPlus AHK Driver - Adversarial Hardening Audit

**Date:** 2026-07-20  
**Scope:** `static/ergopti_plus/windows/` (AutoHotkey v2 driver, 890 `.ahk` source files)  
**Method:** Multi-agent adversarial audit - 5 context agents, 24 module/cross-cutting finders, 25 PROJECT_MEMORY watch-list verifiers, per-finding adversarial refutation (2 independent lenses for critical/high), loop-until-dry completeness critic. 420 raw findings -> deduped -> adversarially verified. Baseline suite green before audit (3170/3170 pass, encoding conformant, whole-program syntax valid).  
**Guarantees:** G1 robustness (no unhandled exception / crash / keyboard-lock in any state), G2 no missing output (no silent no-op), G3 no races (async ordering), G4 no perceptible lag.

> Confidence: **confirmed** = proven by code reading and/or field logs; **probable** = strong code evidence; **needs-live-check** = requires a live repro. Every finding below survived at least a majority adversarial-refutation vote OR is corroborated by a real crash report / log line.

### Most fragile zones

1. **Boot ordering (the dominant risk).** Static hotkeys and `#HotIf` evaluators arm at parse time (~700 ms into boot) but the globals they read (`Features`, tap-hold/timing constants) are assigned up to ~2 s later - a ~1.3 s per-boot window, and *permanent* after any aborted boot. One keypress in that window throws an unhandled exception inside a `#HotIf` evaluator; the new fatal-before-ready error net escalates it to `ExitApp(1)`. This is the single **critical** finding (F01), proven by a real crash report (`2026-07-19T08-03-45Z.json`) plus 3 identical signatures on 07-16. Several **high** findings (double-boot race, timing constants reset to 0, config clobber) share this boot-ordering root class.

2. **Hotstring engine state across suspend/resume and live rebuild.** `HSE_Buffer` is never reset on resume (stale terminator fires destructive backspaces), the personal-TOML cache is never invalidated after a save (edits silently revert), and the prefix-watcher index diverges permanently if toggled while suspended.

3. **Personal-info combo generation.** Two independent defects in `hotstrings_text_expansion.ahk`: iterating Map *values* instead of *keys*, and indexing a Map without `.Has()` - either bricks boot if the user removes a default personal-info alias.

4. **Typing-thread latency (G4).** Real logs show `Tooltip.ResolvePos` up to **2.56 s**, `OnChar`/`HSE.FeedChar` up to **701 ms** on a space character - the tooltip pipeline (Build->ResolvePos->Present + a 5,000-10,000 px border scan) runs inline on the character hot path.

### Honest verdict

The driver is **well-instrumented and heavily tested** (3170 passing tests, a mature meta-test layer that already pins most known foot-guns), and the documented PROJECT_MEMORY invariants are **almost all still in place**. But the recurring project failure mode holds exactly as PROJECT_MEMORY predicts (`project_ahk_invariant_incomplete_application`): the hardening invariant is applied at the documented site and missed at a sibling - 18 of 25 watch-list entries are *fix-in-place-**and-same-class-found-elsewhere***, and one (`metrics-live-foreground`) has **regressed**. The boot-ordering critical (F01) is in the field crash logs today. This is *not* a clean bill of health - it is a prioritized, reproducible worklist. Verification was adversarial but the final loop-until-dry pass was cut short by API session limits, so the coverage register marks which zones reached "dry" and which are "audited, one pass".

### F01 - Keypress during boot/onboarding kills the driver: #HotIf helper dereferences unset global Features, and the new fatal-before-ready error net turns that into ExitApp(1)

- **Severity:** critical  |  **Confidence:** confirmed  |  **Guarantee violated:** G1  |  **Verdict:** CONFIRMED
- **Location:** `modules/shortcuts/altgr.ahk:30`
- **Sibling / related sites:**
    - static/ergopti_plus/windows/modules/shortcuts/base_modifier.ahk:39 (the armed #HotIf consumer)
    - static/ergopti_plus/windows/modules/tap_holds/nav_layer.ahk:36-47 (raw Features[…] on #HotIf continuation lines, invisible to the section-7 scan)
    - static/ergopti_plus/windows/ErgoptiPlus.ahk:36-45 (pre-assignment block that omits Features)
    - static/ergopti_plus/windows/modules/shortcuts/altgr.ahk:181-189 (HotIf closures inherit the same unguarded helper)

**Repro (initial state + exact actions):** Cold-start the driver (or run first-boot onboarding). Static hotkeys arm at load-complete, but `global Features` is only assigned at ErgoptiPlus.ahk:454 (~400-1300 ms into auto-execute per the boot profiler; the window lasts MINUTES during the blocking Onboarding_Run at :311). In that window press LAlt+CapsLock: the parse-time-armed `#HotIf _LAltKeepsBareModifierForCapsLockCombo() and _AnyShortcutEnabled("lalt_caps_lock")` (base_modifier.ahk:39) calls _AnyShortcutEnabled, whose first statement `!Features.Has("shortcuts")` throws UnsetError. ErgoptiGlobalErrorHandler sees _DriverBootPhase != "ready" (error_net.ahk:76-82) and runs ExitApp(1) — the entire driver exits mid-boot / mid-wizard. Field proof of the throw: crash_reports/2026-07-19T08-03-45Z.json (UnsetError 'Features', stack altgr.ahk:30 <- base_modifier.ahk:39 #HotIf) plus 3 identical signatures in ErgoptiPlus_errors_2026-07-16.log at 12:30.

**Root cause:** The pre-pump global block at ErgoptiPlus.ahk:36-45 deliberately pre-assigns every #HotIf-consumed global (CapsWordEnabled, LayerEnabled, TapHold) EXCEPT Features, while base_modifier.ahk:39's #HotIf reaches Features through the helper _AnyShortcutEnabled which has `global Features` but no IsSet() guard (altgr.ahk:28-30). The existing source-scan guard (tests/unit/test_features_manifest.ahk:667-691) only inspects lines that START with '#HotIf ' and contain 'Features[', so both the helper-function indirection and multi-line '#HotIf (' continuation blocks (nav_layer.ahk:36-47) are invisible to it. This morning's fatal-before-ready seam (correctly) closed the zombie-half-driver mode but upgraded this pre-existing throw from 'logged and continued' (07-16 behaviour) to 'whole driver exits'.

**Why it is silent today:** Pre-ready the handler does `try LoggerError` then ExitApp(1) with no MsgBox/toast; if the chord lands before LoggerInit (ErgoptiPlus.ahk:327) even the log line is lost (see finding 2). The user just sees the tray icon vanish — or, during first-run, the onboarding wizard close with no config written.

**Proposed fix:** Two layers, per conventions 5.3: (a) fail-fast guard in the helper — first line of _AnyShortcutEnabled: `if !IsSet(Features) { return false }` (and add `IsSet(Features)` as the first conjunct of the nav_layer.ahk:36 #HotIf block; it is currently shielded only by LayerEnabled being false at boot). (b) Do NOT pre-assign an empty `Features := Map()` in the :36-45 block without auditing — several IsSet-guarded #HotIf sites (layout.ahk:680/969/976, win.ahk:24/637) index Features raw after IsSet and would convert UnsetError into a Map-key throw on an empty Map.

**Regression test (encodes the root cause):** `tests/unit/test_features_manifest.ahk` - Extend section 7 twice: (1) make _FMv2_HotIfFeaturesLines accumulate multi-line '#HotIf (' blocks up to the matching close-paren before applying the Features[/IsSet check, so nav_layer.ahk:36-47 is scanned; (2) new test that FileReads modules/shortcuts/altgr.ahk, extracts the _AnyShortcutEnabled body, and asserts InStr(body, "IsSet(Features)") is > 0 AND smaller than the first InStr(body, "Features.") — encoding the root cause that a helper reachable from a parse-time #HotIf must be self-sufficient.

### F04 - CS_Read has no inline-comment handling: 'metrics_enabled = false # comment' silently inverts to TRUE and starts the keylogger, then SaveFullConfig persists the inversion

- **Severity:** high  |  **Confidence:** confirmed  |  **Guarantee violated:** G2  |  **Verdict:** CONFIRMED
- **Location:** `lib/config_shortcuts.ahk:99`
- **Sibling / related sites:**
    - static/ergopti_plus/windows/lib/config_shortcuts.ahk:351-366 (all truthiness-based boolean consumers: metrics_enabled, wpm_menubar_colors, the three privacy filters)

**Repro (initial state + exact actions):** Hand-edit autohotkey/config.toml (a legal TOML edit the module header explicitly invites: 'hand-written sections survive'): set 'metrics_enabled = false # désactivé pour confidentialité' under [ahk.metrics]. Reload. CS_Load -> CS_Read keeps the whole 'false # désactivé…' as the value (only whole-line comments starting with # are skipped, :85); CS_CoerceValue falls through every branch to the bare-string fallback (:161); 'MetricsShortcuts.enabled := s["metrics_enabled"] ? true : false' (:352) treats the non-empty string as truthy -> metrics ENABLED -> KL_Init + 9 KL_*_Start() run (ErgoptiPlus.ahk:690-712). **Root cause:** config_shortcuts.ahk hand-rolls a second TOML parser over the same file the canonical ParseTomlFile/_IniCache pipeline owns (single-source-of-truth violation, §5.2), and that mini-parser strips only full-line comments, never inline ones, while the boolean consumers use truthiness on the resulting bare string instead of validating the coercion.

**Why it is silent today:** No parse error is raised anywhere; the value coerces to a truthy string, the feature flips on without any log above DEBUG, and the following save legitimizes the corrupted value on disk. For a privacy toggle this is the worst possible silent failure direction.

**Proposed fix:** In CS_Read (or CS_CoerceValue), strip ' #…' comments outside quoted strings using the same raw-stream in_str/escaped tracking already used by the array tokenizer; additionally make CS_Load reject non-boolean values for boolean keys (fail-fast §5.3) — or better, delete the parallel parser and read the [ahk.metrics] section from _IniCache.
