## Definite static finding

Official2.55.0.windows.5 ZIP places both DLLs in `mingw64/bin`. Official2.56.0.windows.2 places both in `ucrt64/bin` and contains neither old `mingw64/bin` DLL. Its official release notes explicitly describe the MINGW64→UCRT64 migration (and a credential-manager compatibility shim, not a promise of old DLL directory compatibility).

The exact current fixture C# OpenSSL class is36573B, SHA256763eaf881ffd5fe98cb961c9b1f7114f0cc3f690878558e6c59a450b3388afd2, matching the unchanged body identified by parent. `managed_remote_transport.ps1:654` hardcodes `ProgramFiles/Git/mingw64/bin`; line656 calls VerifyDirectory, which refuses absence or a reparse point in any ancestor (486–495). Thus this literal source cannot receive the new official MinGit distribution at its actual location. This is a concrete **source/path compatibility candidate**, not yet a proven cause of the old/current GHA case failures.

Actual hosted full Git installation directory inventory, DLL hashes and loader error were NOT retained/received.
