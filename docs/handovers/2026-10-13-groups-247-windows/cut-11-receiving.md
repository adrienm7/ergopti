# Linux model-consent affinity and asynchronous continuation

Apply `linux-model-consent-affinity.patch` first, then `linux-model-consent-continuation.patch`. Both are incremental source changes; the second depends on the exact first patch listed in its manifest. No runtime, vendor, CI or roster files change.

The first correction snapshots the admitted model/origin/requesting callback and actual default download module/start function before showing consent. Reentrant replacement refuses; every retry checks those identities. Automatic notices belong to an exact endpoint and delivered receipt. Old success cannot clear a later notice.

The second correction preserves an accepted asynchronous pull's engine consent after the modal returns. `Offer.handle` keeps its first handled Boolean and adds an exact affirmative installer-admission receipt. The caller releases the original consent on success or a once-only retirement callback after known retained transport/UI cleanup. Cancel acceptance without observed settlement cannot release it. Failed requests keep the existing same-window guarded retry; origin changes, pause/scope withdrawal and newer actions still revoke the original owner. Stale completion/retirement cannot release a successor owner.
