## Runtime path changes relevant to reading the audit

- Shared declaration `_shared/modules/paths/app_dirs.toml` now explicitly chooses `Ergopti` on Windows/macOS and `ergopti` under Linux XDG roots. Windows generated support/config/cache/logs accessors and new `windows/infra/app_folders.ahk` resolve `%LOCALAPPDATA%\Ergopti\`.
- Installed Windows locator moves from `%APPDATA%\Ergopti\paths.toml` to `%LOCALAPPDATA%\Ergopti\paths.toml`; default config moves from `%USERPROFILE%\.config\ergopti_plus\` to `%LOCALAPPDATA%\Ergopti\config\`. Source development `_generated\paths.toml` and isolated startup-smoke path selection remain separate branches.
- Default logs move from `%LOCALAPPDATA%\ergopti_plus\logs\` to `%LOCALAPPDATA%\Ergopti\logs\`. Migration-registry cache now uses `AppFoldersCacheDir()` under `Ergopti\cache\`. LogsDirPath/ConfigDirPath still represent relocation overrides; old audit examples naming previous defaults are historical paths, not the new installed defaults.
- Managed Ollama changes from `%LOCALAPPDATA%\ergopti_plus_ollama` to protected sibling `%LOCALAPPDATA%\Ergopti-ollama`. The explicit ACL reason for a separate direct LocalApplicationData child remains; do not describe it as a purpose subfolder of the main root.
- `infra/boot.ahk` now runs `LegacyFolderMigrationRun(_PathsFile)` before transition recovery/ReadPathsToml, except startup smoke. New `infra/legacy_folder_migration.ahk` explicitly documents rename without overwrite, empty-target release, conflicting legacy entries moved to `before-folder-migration`, prior locator backup before rewrite, and maintainer-only provenance (no published build used old folders). This is a changed startup/persistence surface, not a repair of the six finding owners.
- `ReadPathsToml` no longer performs the previous opportunistic bundle-path copy inline; migration is centralized before it, and new default comments use AppFoldersDefaultConfigDir. Cache-only change in `config_migrate.ahk` does not alter schema transaction logic reviewed for WCF.
