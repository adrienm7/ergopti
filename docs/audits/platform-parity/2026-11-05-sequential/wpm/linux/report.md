## WPML-001 — A refused redraw loses the obligation to hide an already visible widget

Severity: low. Confidence: high for the owner invariant and refusal-handling branch. Guarantee: G2. This is an injected native-refusal sequence, not a claim about how frequently real GTK refuses a valid redraw.

Reproduction: start the actual `ui/wpm/widget.lua` against the actual `adapters/wpm_surface.lua`. Deliver WPM=42 so the native-shaped window becomes visible. On the next active tick, make the native window's resize throw before changing the existing visible window (a literal-false wrapper control is also retained); the prior visible window remains visible. Restore healthy native methods, then tick WPM=0 with source none after the idle-hide timeout. The widget stays visible, and native hide receives zero calls. Explicit stop hides it. A healthy redraw/idle sequence hides normally.

Root: `ui/wpm/widget.lua:459` assigns `_state.shown = Surface.draw(...) == true`. `adapters/wpm_surface.lua:274-290` catches a refused/throwing resize/move/show/queue operation and returns false; this does not imply the existing window was hidden. The subsequent idle branch (`widget.lua:441-443`) calls hide only if `_state.shown` is true. A failed refresh therefore clears bookkeeping ownership while the old native visibility persists. This also makes a configuration snapshot claim `shown=false` for that still-visible surface.

Visibility/backstops: the initial redraw refusal is logged by the real surface. The later lost idle-hide obligation is silent because hide is never attempted. An explicit stop still invokes hide independent of shown and succeeds; a later successful active redraw also reestablishes shown and permits subsequent idle hiding. This is a stale floating display, with no evidence of lost typing or a keyboard lock.

Decisive evidence: `probes/owner.lua`, `logs/final-sweep-a-owner.log`, `logs/final-sweep-a-owner-throw.log`, corresponding sweep B logs, and `logs/source-boundaries.txt`. The canonical exception-seam run and the wrapper-false control each include `REFUSED_REDRAW native_visible=true owner_shown=false`, `IDLE_HIDE_CALLS delta=0`, and successful `EXPLICIT_STOP` / `HEALTHY_IDLE` controls. The probe uses the production surface's draw/hide implementation, not a replacement renderer returning invented business answers. GTK resize normally returns void/nil; literal false is only a wrapper-refusal control. The throw-mode logs are the canonical native-exception seam evidence.

Regression direction: execute the actual widget and actual surface with a previously visible window. Refuse/throw at each redraw native boundary, then restore native health and advance beyond idle timeout. Assert that the existing surface receives an acknowledged hide, even when redraw acknowledgment was false. Preserve visibility/recovery ownership until native hide acknowledges it; do not treat draw false as proof of hidden state.

## Preserved hypotheses and refutations

1. **Ordinary stop inverse debt has no runtime retry caller.** Both owners can retain `_restore_debt` after a failed exact inverse; subsequent public commands/ticks/restore reject the debt and configuration snapshots return nil. Once native/persistence recover, direct `retry_configuration_restore()` resumes operation in the retained probe. Only the original stop calls that helper in production. This is an observed recoverability limitation, **not a canonical finding**: fail-closed admission while native state is uncertain can be deliberate. Initial ERROR explicitly says previous state is retained for restoration, and process restart is available. No automatic recovery promise was found. Any future change must preserve exact inverse ownership and scope fences. Both widget and tray controls are in `probes/owner.lua`.
2. **No-tray GTK pump coupling.** The actual tray adapter returns without pumping when never started, while the widget restore/tick is not tray-gated. Probe shows queued draw remains pending with no tray, then drains after starting the actual tray owner. The webview secondary GTK pump only runs while its own native windows exist. However, README and daemon log call a manual launch without --tray “headless”; whether a persisted floating widget is owed in that mode is unknown. Retained as intent question, not finding. Every packaged service passes --tray.
3. **Missing native libraries are not a silent crash.** Surface binding logs the absence and returns unavailable; --tray preflight names missing desktop dependencies and distinguishes optional windows. A running widget flag alone proves requested policy, not native display. No missing-library issue is reported here.
4. **Failed hide does not automatically lose its existing shown state.** Actual Surface.hide verifies hidden state and retains the window on refusal; ordinary stop keeps compensation debt. The confirmed defect is the separate redraw assignment, not an invented lack of native acknowledgment everywhere.
5. **Off-screen position after topology change:** source mechanism exists; user intent/default-position policy and actual hotplug receiving are not established here. Not merged with WCF-001, which concerns durable mixed coordinates.
