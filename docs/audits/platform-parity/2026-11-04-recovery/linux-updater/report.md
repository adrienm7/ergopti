## LUR-001: async install retains a blocking unbounded smoke

The actual async installer yields for branded tar readers and artifact retirement, but retains `DEFAULT_OPS.smoke` (`linux/modules/updater/installer.lua:288–289`), which calls synchronous `os.execute` through :57–58. `install_transaction:447` checks the original admission before and after the child; no timer, timeout or owned child can interrupt it. `install_owned:590–604` overrides only listing/extract/archive retirement, and its :630 coroutine resume cannot preempt synchronous native I/O. An installed wrapper whose help is slow/hung therefore occupies the daemon Lua/event loop beyond its install deadline.

Run **LuaJIT**, not stock Lua:

```text
cd /workspace/ergopti/static/ergopti_plus/linux
USER=agent LOGNAME=agent PYTHONDONTWRITEBYTECODE=1 /workspace/scratch/parity-toolchain/ci-bin/luajit /workspace/scratch/parity-recovery/linux-updater/probes/smoke-blocks-loop.lua
```

The probe uses actual `install_owned`, real shared InstallBudget, original transaction/default filesystem operations, native ownership checks, real POSIX child and libuv timer. Its explicit admitted archive-reader collaborator copies a synthetic complete fixture payload; this is not authenticated HTTP/FD chain qualification. Only its new scratch candidate launcher changes from exit0 to `sleep 0.65; exit0`. Old-tree backup, activation, smoke and rollback use production operations. Latest `logs/smoke-blocks-loop-final.txt`:

| Case              | Original install budget | Call duration | 10ms heartbeat during call  | Terminal state                               |
| ----------------- | ----------------------- | ------------- | --------------------------- | -------------------------------------------- |
| Healthy control   | 250ms                   | 91.6ms        | 0 ticks                     | succeeds, new root active                    |
| Bounded slow help | 250ms                   | 724.4ms       | 0 ticks, fires after return | deadline finally observed, old root restored |

Parent independent replay (`logs/root-smoke-blocks-loop-luajit.txt`) measured healthy63.4ms / slow716.3ms with the same deferred heartbeat. This supports **G4 for controlled daemon event-loop starvation**; it is not a measurement of typical desktop typing latency or an actual grabbed keyboard. Source establishes no local timeout for a never-returning child; no indefinitely hung process was launched. Successful rollback after a finite delay does not undo the earlier loop stall.

Why existing tests miss it: async receiving fixtures model tar/cleanup ACKs; native transaction fixtures run an immediate `--help` launcher. Boolean success/failure and eventual rollback do not establish that the loop progresses while waiting. Regression: actual default smoke with delayed bounded help + live heartbeat + deadline, owned bounded child cancellation/physical ACK, one terminal callback and exact old-tree rollback. Do not replace it with another fabricated smoke result.

## Producer-to-recovery review

Archive transfer: original reservation before reentrant native construction; captures methods by raw identity; early/duplicate result held until original child physical settlement and fresh lineage/deadline; unknown constructor/observer debt stays busy. Cancellation is logical until exact original transport/artifact settlement. Failed temporary allocation only receives known-refusal message after physical ACK. Later private artifact install is a separately accepted lifetime. `manager.install_native_archive:1849–1908` reserves before resolution/native admission, captures context, joins physical installer completion, and consumes one callback. Later page close/pause does **not** abort an already accepted transaction (`execution_current` explicit), preserving safe forward/rollback custody. This is intentional, distinct from acquisition pause gates.

Installer ownership: staging/active/backup verification checks canonical installed schema, file digest membership, native regular-file/close stability and directory identity. Old backup is moved into staging, verified again, then retired; inverse failure retains namespace. Candidate activation/smoke rollback rechecks exact identity, never deletes a foreign changed root. Same-filesystem no-replace move protects vacant destination. Source evidence does not prove safety against every hostile noncooperating writer/namespace race or power failure; no stronger claim made.

Backup owner: filesystem ports use original classified compare-and-publish writer; copies read back and manifest last excludes interrupted folder. Links to directories not traversed, dangling links omitted, unknowable targets refuse. Restore preflights all copies, pre-backs current files, then conditional per-file writes/readback; partial error reports recovery backup. No deletion of extra unrelated user files inferred. Native file fault tests cover no-newline names, special entries and refused copy paths.

Restart: exact systemd cgroup ancestor detection, shell quoting, foreground setsid acquisition receipt; relay tests zombie through /proc/status and waits exit before launch. Existing cancellation marker ownership and pause handoff reviewed; no second confirmed root. systemctl --no-block status is queued admission, not process-ready acknowledgment. Control successor completion/deadline is separate. No live user manager/cgroup/process termination invoked.

## Root supplemental active-loop control

[smoke-live-loop.lua](probes/smoke-live-loop.lua) strengthens the same LUR-001 observation. The actual installer is invoked from a timer callback inside an already-running libuv loop. Both cases have three real 10ms heartbeat ticks before entry and a resumed tick afterwards. Healthy native call: 90.8ms, maximum tick gap101.0ms, install succeeds. Bounded slow help: **727.7ms**, zero ticks during call, maximum tick gap**738.0ms**, original budget250ms, failure restores the old tree. [Raw output](logs/root-smoke-live-loop.txt) and [parsed measurements](logs/root-live-loop-measurements.json) retain both controls. No keyboard/session latency, user install or actual network was exercised.

The first harness attempt failed its pre-entry-heartbeat assertion before executing the installer: synchronous fixture preparation had aged libuv’s cached loop clock, making both new timers overdue on the first turn. The fixture now calls `uv.update_time()` before timer registration, establishing actual ticks before entry. [Initial failure](logs/root-smoke-live-loop-initial.txt) is retained and is not attributed to the product. This is a stronger observation of the existing root, not an additional finding or a fabricated native timing baseline.
