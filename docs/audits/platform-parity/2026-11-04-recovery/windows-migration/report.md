# Windows legacy-folder migration recovery audit

Audited SHA: `3a680d9f530a9af686fccc16d3f7611ec7fb034c`.
Date: 2026-11-04 UTC. Scope: Windows `infra/legacy_folder_migration.ahk`, its boot/path-resolution/file-system ownership chain, and relevant shared/macOS/Linux comparators. Audit only: no production/test edits, registered tests added, real user configuration, environment changes, native input, installation, commit or push.

## Result and provenance

Four source-confirmed recovery/selection defects are retained. They affect the first boot that migrates the maintainer's legacy folders; the explicit decision that no published builds used these old folders limits exposure. Existing bytes are generally preserved in the new location or a backup. This report does not claim irrecoverable loss of all personal files or a silent primary I/O error when a warning is actually emitted.

Evidence has three separate levels:

1. Executed Python assertions over exact pinned Windows owners, with SHA-256 identities in `logs/source-evidence.json`.
2. Executed actual shared Lua migration core on **real private POSIX files**, with Windows-plan ordering mapped from the AHK source. Eight adverse/control cases and the five committed shared contract groups pass as _observations of current behavior_. This corroborates the ported algorithm; it is not executed AHK/Win32 behavior. The actual TOML codec decodes the quoted-key control.
3. Supplied `probes/native-windows-fixtures.ahk` includes the actual Windows migration owner and binds getters/FS ports to a fresh A_Temp fixture. It is **unexecuted**. Its one absolute #Include needs rebinding to the same pinned checkout on Windows. The directory-move refusal scenario is intentionally excluded from this AHK probe: production uses builtin DirMove rather than its injectable file FSMove seam. No claim that a file-port stub injected a native directory refusal.

No Windows/AHK/Wine execution or native timing was available. Findings express the supplementary property **preservation of an authoritative configuration/recovery namespace during automatic migration**; they do not invent G1–G5 guarantees where those do not directly describe durable selection. All manifest guarantee arrays are empty and name this additional property explicitly.

## Findings

### WFM-001 — migration selects a new or removed configuration despite a refused cohort operation

Severity **medium**, confidence **high**. Supplemental durable-authority property. Source-derived AHK; actual shared-core real-file corroboration.

`LegacyFolderMigrationRun` :256-268 unconditionally performs all moves, then rewrites the locator using static old->new rules. It neither checks `Report["kept"]` before rebasing nor rolls back moves when rewrite returns `backup_refused`. Boot :66-80 ignores the report. The rewritten locator therefore need not correspond to a successfully migrated image.

Two inverse reproducible schedules:

- Start with old default config containing `OWNER=PERSONAL`, old locator naming it, new destination absent. Refuse the config directory move (ACL/sharing/native rename failure). The helper records `kept` and then successfully rewrites ConfigDirPath to the empty new destination. Boot loads a new/default configuration while the user image remains at the old directory. The refusal itself is WARNed; continuing to the wrong configuration is not recognized as a cohort failure.
- Pre-create `new paths.toml.before-folder-migration` (a foreign backup must remain untouched), with new config absent. Locator and personal config moves succeed; rewrite refuses the existing backup. Active locator still names the now-removed old directory. Boot creates that old directory and sees no personal config. Retry cannot overwrite the backup; if the first boot recreated an empty old folder it can itself be backed up on the next run while the stale locator persists. Real-file replay checks the second attempt.

A destructive locator-write refusal is a variant of the same unowned publication: `FSWrite` (`adapters/file_system.ahk:109-144`) opens active path with `w`, may truncate, and removes an opened partial file on failure. Migration retains the old verified backup but neither restores the locator nor blocks boot. `ReadPathsToml` then generates defaults. The log falsely narrows all `backup_refused` outcomes to “backup could not be written”, even when backup succeeded and active write failed. No automatic restart recovery consumes the retained backup.

**Evidence:** real-file cases `refused-config-move-still-rewrites`, `refused-locator-backup-after-successful-moves`, `refused-locator-write-removes-active-file`; full success/idempotence control. Directory refusal and write refusal are explicit recording ports on actual shared core; native refusal timing is not claimed. Windows source assertions independently verify ordering, lack of outcome admission and real destructive writer semantics.

**Regression:** exercise the full production boot owner with every move/backup/publication refusal, including open/short-write/close/partial cleanup, plus crashes at each durable boundary. Require an authoritative complete old/new config and locator or a loud boot refusal with actionable recovery. Verify failure cannot select empty defaults, old backup is preserved, restart settles outstanding debt, and independent existing new data remains untouched. Source-freshness/CAS against an external paths editor belongs at this same publication boundary; no live external race was executed here.

### WFM-002 — a configured descendant is moved away without rebasing its locator

Severity **medium**, confidence **high**. Supplemental preservation of explicit user selection. No injected I/O failure required.

Create personal config at `%USERPROFILE%\.config\ergopti_plus\profiles\private\config.toml`; set ConfigDirPath to that exact descendant with forward slashes. On first new boot, `LegacyFolderMoveEntry(LegacyConfig, NewConfig, ...)` :260 moves the **entire ancestor** into `Ergopti\config`. The rewrite rule :265 and equality :184 match only the ancestor itself. Migration reports locator `unchanged`; it still selects the removed `old\profiles\private`, while private bytes now live under `new\profiles\private`. Boot recreates the selected old path and loads empty/default state. Same mechanism applies to explicitly selected descendants of moved legacy logs or other moved ancestor roots when their actual folders are moved.

This does not ask to rewrite every unrelated custom path. The real-file `control-external-override-stays-live` preserves a chosen Documents folder outside the moved roots. The defect is moving the selected object's ancestor while claiming the chosen locator needs no change. Files remain recoverable at the new location; no permanent deletion claim.

**Regression:** actual boot with exact default, custom external path, selected descendant, normalized separator/case variants, and a selected descendant behind a native alias. Track the selected object's identity across the move: preserve it at the chosen path or rebase to the actual receipt destination; do not invent selection of another profile. Include occupied-destination/backup outcomes separately from successful relocation.

### WFM-003 — the migration regex misses valid locator TOML identities accepted at boot

Severity **medium**, confidence **high**. Supplemental preservation of semantically identical valid configuration. No injected I/O failure required.

Use valid locator `"ConfigDirPath" = "C:/Users/u/.config/ergopti_plus/"` instead of bare ConfigDirPath, with actual user path. The current `ReadPathsToml` (`infra/toml/toml_helpers.ahk:1518-1530`) deliberately decodes quoted key identities and string escapes via `TOML_ParseDocument`; both forms select the same old default before migration. `LegacyFolderRewritePathsText` :175 accepts only `\w+` bare keys and basic double-quoted values. It leaves this quoted-key locator unchanged while moving old config away. Next boot uses the semantically recognized, now dangling old path and creates/defaults it.

Literal strings and escaped character spellings are sibling semantic forms to cover; the retained decisive reproduction is quoted key, where the regex rejection is unambiguous. Real-file `valid-toml-quoted-key-missed` runs actual shared rewrite and actual TOML codec, demonstrating decoded ConfigDirPath still points to old image after move. Native Windows semantic-reader execution remains absent; its actual decoder call and preservation rationale were inspected directly.

Distinct from WFM-002: here the decoded value is the **exact default**, so descendant-prefix handling alone does not fix it. The owner must compare decoded identities/values, not a narrower textual shape.

**Regression:** full migration/readback for bare/quoted/literal keys and strings, legal escapes, comments, non-ASCII profile names, and no-op preservation. Require equivalent valid locators to select the same retained image. Do not canonicalize or overwrite unrelated unknown keys merely to fix matching.

### WFM-004 — moving the locator strands its old recovery WAL before boot can inspect it

Severity **medium**, confidence **high**. Supplemental existing recovery/quarantine guarantee. Source-derived Windows integration; real-file orphaning observed.

The old stable locator was `%APPDATA%\Ergopti\paths.toml`. A previous build can leave its valid pending cohort WAL or malformed/unreadable WAL at `paths.toml.config-transition.wal` after interruption. The original recovery owner derives WAL beside that locator (`ConfigTransitionWalPath`, `infra/config_transition.ahk:261-267`); present malformed WAL explicitly yields quarantine (`ConfigTransitionInspect` :879-904), and boot refuses quarantine.

New migration moves **only** old paths.toml (:256-259), leaving its WAL and sibling transition artifacts in the Roaming directory. Migration can also move config target directories before recovery. New boot then recovers only the new LocalAppData locator (:70). `ConfigTransitionInspect` returns absent for its absent new WAL, so old quarantine or pending recovery is bypassed. `LegacyFolderRemoveIfEmpty` deliberately leaves the old directory containing those files; nothing else in this scoped flow discovers it. Merely copying the WAL later would not suffice because its validated locator/target/artifact namespace can retain old absolute paths.

**Reproduction/control:** put a malformed nonempty old WAL beside the old locator; run migration on a private tree. Old WAL and artifact remain, new WAL does not exist, new locator and config are moved. `old-locator-wal-orphaned` verifies those actual paths. Source `ConfigTransitionInspect` proves inspection of the old malformed bytes would quarantine, whereas absent new namespace bypasses parse entirely. The probe does **not** execute a valid native prepared cohort or pretend the synthetic malformed bytes are valid WAL. A successful no-WAL migration remains the control.

**Regression:** before any legacy locator/target move, run the real recovery owner or refuse to migrate an unsettled namespace. Rehearse every journal phase and malformed/unreadable namespace on isolated Windows, retain exact artifact identities and whole old/new cohorts, then migrate. Assert a journal cannot become invisible simply because the locator moved. Include source-local and installed locator selection separately; do not treat an unvalidated relocated WAL as valid under a different locator.

## Refutations, tests and gaps

- Occupied nonempty new config displacing old config to backup is a documented policy, not WFM-001 by itself. Existing backup refusing overwrite is correct; failing to preserve/stop on the resulting incoherent selection is the finding.
- Ordinary second-driver overlap is fenced before migration by the named mutex; no double-launch finding retained. Detached workers exit through their dedicated branch before full boot.
- Native exceptions from parent creation, directory move and file FSMove are converted into retained `kept` reasons; no blanket G1 crash allegation. Empty-base environment failure deliberately throws.
- Success is idempotent; real-file control's second run moves nothing and returns unchanged. Failure recovery is not therefore proven idempotent: existing-backup obstruction remains after success of independent earlier moves.
- The committed AHK tests replay individual nine moves and four text vectors, file backup refusal and boot source order. They do not execute whole migration+boot under failed mixed outcomes, descendant/quoted-key locators or old locator WAL. Existing green source-order test explicitly enforces migration before recovery, so it is not proof WFM-004 is safe.
- False-green mechanical scan under pinned Node 22.22.2 passes all six categories at zero. Manual inspection separates source spelling tests from behavioral owner coverage. Python assertions here are explicitly source checks, not a replacement for native lifecycle tests.
- Actual shared Lua committed contract passes five groups: nine move vectors, three POSIX text vectors, backup, invalid-port/plan refusals and logging. Windows backslash vector is intentionally excluded on POSIX and is not counted as exercised.
- The first scratch attempt to add codec/contract controls failed to resolve `text_utils` because package.path lacked `?/init.lua`. The owned harness path was corrected to the real shared directory; final replay succeeds without copied/fake modules or production changes. This setup failure is not product evidence.
