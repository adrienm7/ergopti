## Findings and consequences

- Linux retires the matcher after a repeat. `ac★ê` remains `accê`, whereas
  manually typing `accê` invokes the shipped correction and produces `accu`.
  The same reset fabricates a word boundary: with an enabled word-start-only
  automatic `x → z` rule, `po★x` produces `pooz`; manually typing `poox` does
  not expand. macOS public-entry controls preserve `poox` in both cases.
- A repeat can derive a character from previously private output and publish it
  as public. Actual macOS and Linux Lua owners demonstrate this using real
  personal-information producers and synthetic values. Windows source confirms
  the corresponding path after a supported private programmable output;
  Windows personal-field expansions have a final-output barrier and are an
  explicit counterexample. The demonstrated leak is a derived scalar, not a
  claim that the whole private value reaches a prompt.
- Windows deferred Notepad/terminal completion labels the same repeat
  differently from the ordinary sender, changing live WPM coloring. The
  canonical hotstring row has no category/section fields; durable category
  corruption is not claimed.
- Linux's specialized Backspace restoration had no generated behavior
  declaration. A supplementary shared catalogue now feeds the site and
  documentation without inventing a setting. The historical finding remains
  in this audit; its implementation status is tracked separately.
- An ancillary actual JavaScript import confirms that existing English inventory
  headings/legend mappings sit inside JSDoc and are absent from the exported
  dictionary. Their apparent presence in source is not a valid translation test.
  The root repaired those existing exports in this delivery; the pinned finding
  remains historical evidence. A final actual import confirms thirteen required
  inventory mappings, including the old headings and legends.

## Intent, alternatives and unestablished intent

The maintainer explicitly excludes repeat doubling from the advance preview:
`project-the-bubble-never-offers-a-doubling` in
`docs/memory/text-input-and-config.md`. This does not exclude the separately
registered repeat-correction mappings. Repeat is deliberately a last fallback;
registered mappings, personal combinations and programmable owners retain their
documented precedence. Repeat and private/key/callback outputs are excluded from
cascade links rather than recursively sent through the input watcher.

Windows erases/retypes the preceding scalar and magic key, while Linux erases
the already typed magic key and emits one scalar; macOS can suppress the physical
event and emit a copy. These source-derived mechanisms do not establish equal
native Undo grouping. Ctrl/Cmd+Z remains application-owned. Only Linux has the
specialized immediate-Backspace trigger receipt in the inspected hotstring
owners. No permanent product decision excluding Windows/macOS was located;
that absence is parity work, not an intentional exclusion inferred from code.

Linux restoration is conditional: an immediate eligible unmodified Backspace,
literal output with something left to compensate, and the original admitted
field/privacy authority. Key-token output, empty output without a replayed
terminator, changed focus, later typing/navigation and lifecycle retirement do
not carry a universal restoration promise. A zero-length replacement followed
by physical Backspace can simply delete preceding application text. The audit
records that limitation without attributing the physical deletion to an extra
injector write. Native grapheme/line deletion, selection behavior, application
Undo/redo grouping and rich formatting remain receiving qualifications.

## Automatic review and its limits

The live [behavior inventory](../../../behavior-inventory.md) supplements the
existing configuration/action/menu inventories. Its authored source is
`static/ergopti_plus/_shared/modules/features/behaviors.json`; the regular feature
inventory generator, website prebuild and generated-output drift gate own its
projections. Every declared platform has a qualification and reviewed source
owners. Changed owner bytes require explicit review; generation never silently
updates their hashes. All required shared locales carry the new labels/notes.

These conservative whole-file receipts detect drift in named owners. They do
not discover an undeclared feature, prove a negative across the whole repository,
or establish semantic equivalence. Extending the register remains an explicit
review responsibility. Runtime defects and missing platform implementations
remain open in the root TODO; this campaign does not implement input fixes.

The dated `project.py` validator checks role slots, provenance, qualified
coverage, findings, evidence custody and deterministic projections. Its two
positive owners include a legitimate all-zero finding set; 22 malformed controls
are rejected. This is a custom cross-platform schema, not the legacy AHK/HS
report-validator envelope. Run the commands in [README.md](README.md).

Replay the archived decisive programs with the pinned toolchain on `PATH`:

```sh
python3 replay.py /path/to/ergopti --output /tmp/ergopti-repeat-replay
```

The script retains exit codes, actual program hashes and stdout/stderr. Root
delivery qualification and current-source replay receipts are in `validation/`.
Historical worker receipts identify their original scratch/worktree locations;
those paths are provenance, not dependencies of the portable decisive programs.

Their exact original bytes are retained as `.txt` copies, with original/current
digests and verified JSON-value equality in
[format-provenance.json](validation/format-provenance.json). Historical claim values remain unchanged; canonical evidence hashes describe
the current formatted archive.
