# macOS word reset and AI context continuity audit

Audited commit: `b17e47ed3bb92c106703d3e3482b3c2973f5bc1e`.

Two additional owner-level findings: independent AI retention/reset is undone by the next character, and terminal empty-prompt ownership omits keypad Enter. Four compact Lua programs execute actual owners over repository native-port fixtures. Native desktop receiving, real network delivery, performance and long-running memory are unmeasured. No production or registered tests were edited.

## WRM-001 — Next typing overrides the independent AI navigation preference

Severity **medium**, confidence **high**; named property `independent_ai_context_policy`. No G1–G5 label is forced onto a context-policy defect.

Actual public Keymap actions prove both directions of the same root:

- With AI `reset_on_nav=false` and the shipped `arrow_resets_word=true`, type `bonjour`, press Left, then `x`. Immediately after Left, the hotstring buffer is empty and AI context correctly remains `bonjour`. The next letter replaces AI context with `x`, dropping the retained sentence. Cmd+Z with `shortcut_resets_word=true` and a mouse click exhibit the same loss.
- With AI `reset_on_nav=true` and `arrow_resets_word=false`, type `bonjour`, press Left, then `x`. Immediately after Left, AI context is correctly empty while the hotstring word is intentionally retained. The next letter rebuilds AI context as `bonjourx`, resurrecting the text the AI preference just cleared. Cmd+Z with `shortcut_resets_word=false` has the same result.
- Matching option combinations are positive controls. No-tooltip Escape obeys AI continuation in the two tested combinations.

`public-context.lua` executes twelve public native-port scenarios: five mismatches, seven positive controls. Actual Keymap, Bridge and shared ContextBuffer execute; prediction-engine activity is an external fixture observer. A separate `context-request.lua` executes the actual Bridge, PredictionEngine and shared PromptBuilder with fake HTTP transport. It mirrors the exact caller state transitions independently proven by the public program and captures four serialized request bodies. The two mismatched option combinations respectively omit the retained original sentence and reintroduce the cleared original sentence; matching options behave correctly. This is composed caller and request-owner evidence, not one uninterrupted native desktop/network execution. No request leaves the fake port.

Root: `check_nav_reset` applies `ContextBuffer.retained_after_navigation` correctly, but `update_preview_body` subsequently assigns `_state.llm_buffer = ai_context_of(buf)` from the cursor-relative hotstring buffer (`llm_bridge.lua:751–761`). The independent AI window has no edit owner across a hotstring-buffer reset, so the next physical edit substitutes the hotstring lifetime for the user's independent AI policy. The shared ContextBuffer documentation explicitly gives the two buffers separate lifetimes and says the AI navigation preference owns that question. No private-mapping redaction bypass is claimed here: the synthetic test phrase is ordinary public text, and the existing private-prefix mark remains a separate protection.

Visibility: normal typing and request construction succeed without a diagnostic; existing navigation tests inspect retained AI text immediately after navigation, then test stale hotstring refusal, without asserting continuation after the next ordinary character. All selected baseline tests remain green. The immediate navigation log can be correct even though the next key reverses its effect.

Regression direction: actual public arrow, shortcut and click owners followed by ordinary typing, Backspace and expansion; cross product both independent preferences. Require the retained AI sentence to survive a hotstring reset, and a cleared AI sentence to remain absent when hotstrings intentionally continue. Carry the observation through real request serialization with a fake transport. Preserve private output exclusion, idle/source/focus/pause invalidation and default hotstring reset behavior. Do not disable word reset, force both settings to the same value, or re-enable stale hotstring actions to retain AI text.

## WRM-002 — Terminal empty-prompt receipt excludes keypad Enter

Severity **low**, confidence **high** for the executed owner/key-identity difference; named property `enter_key_identity`. This is a qualified finding: the reproduction requires a terminal that treats bare keypad Enter as submission and subsequent Backspaces at an empty prompt. Actual native Terminal receiving was not executed; no universal G2 claim is made.

Source identity is explicit: generated HID identity maps `NumpadEnter` to keycode 76; Bridge names keycode 76 `Numpad Enter (same behaviour as Return)` and accepts both 36 and 76 for prediction validation. Main Keymap's terminal empty-prompt branch accepts only `Keycodes.RETURN` (36), and its no-prediction Enter reset also omits 76.

The actual public Keymap/TOML fixture classifies the application as Terminal, registers word-only `r → R`, and drives `a`, submit, `a`, Backspace twice, `r`. Main Return 36 publishes an empty prompt receipt, preserves the fresh word start through the extra Backspace, and emits `R`. Keypad 76 with either CR or ETX payload retains the pre-submit word in the logical buffer and emits no word-only expansion. The extra blank-prompt Backspace cannot retire stale pre-submit context because `start_is_line_start` was never set. This measures Lua owner state and recorded synthetic output under the stated native condition, not actual native terminal editing.

`keypad-enter.lua` retains both payload controls and the main Return positive. Separate nonterminal payload controls show that a CR event with either code expands an end-char mapping, while ETX with code 76 does not. This additional payload observation is conditional on that native spelling and is not asserted as independently measured macOS event behavior. It proves keypad events are not globally discarded: the terminal receipt defect exists even under CR, which the end-char matcher otherwise accepts.

Root: the terminal submission and no-prediction reset branches use the narrower Return key identity instead of the Enter family already recognized by the prediction path. Existing word-start regressions cover keycode 36 only, so they pass without covering keypad identity.

Regression direction: actual public terminal classification and main/keypad Enter controls with real supported event spellings; test empty-prompt deletion and subsequent word-only triggers, ordinary multiline and Shift+Return controls, visible prediction acceptance and pause/focus refusal. Native receiving should verify the terminal's keypad binding and event payload. Do not normalize every control character or blindly promise an empty prompt in a terminal mode that binds keypad Enter differently.

## Coverage, intentional differences and refutations

`public-edits.lua` adds sixteen public owner controls: idle ordinary typing; idle bare Backspace preserving the editable word; Option/Cmd/Ctrl Backspace; deleting beyond observed text; Terminal Return versus Terminal Shift+Return and TextEdit Return; Cmd+A in TextEdit versus Terminal; Cmd+L in Safari versus TextEdit; a foreign-remapper Cmd+Z; pause/resume and stop. These controls record both buffers and boundary flags. Terminal and app identity are native ports, not actual focused applications.

Intentional behavior is grounded in the shared feature manifest and current source:

- Idle defaults to three seconds; zero disables it. Bare Backspace after idle edits the previous word, exactly as the manifest requires. Fresh ordinary typing after idle starts a new word. The observed AI refresh after idle Backspace is not counted as another root.
- Arrow and shortcut resets default on. Turning either off deliberately keeps the hotstring buffer and word-start state across that event. Modified arrows follow the arrow setting. Cmd/Ctrl chords are shortcuts; Option/Shift typing stays text.
- A click always empties cursor-relative text. `click_resets_word=false` changes the next word-start classification, not whether unknown old text is retained. Scroll is explicitly excluded because it does not move the text cursor; the source also gives event-frequency rationale, but this audit makes no timing measurement.
- macOS Option+Backspace is the previous-word deletion and opens a word. Cmd/Ctrl+Backspace delete an unknown amount and reset to an unknown boundary. These are explicit OS-specific modifier semantics in the shared manifest.
- macOS intentionally has no independent `tap_hold_resets_word` option: the shared manifest names Karabiner output arriving like keyboard input, so its shortcuts follow `shortcut_resets_word`; its arrows follow the arrow setting. This absence is already documented and is not a new missing feature or defect. The public foreign-remapper Cmd+Z control observes the ordinary shortcut path, without claiming a native Karabiner receiving test.
- The empty-line backstop is deliberately special: a terminal prompt after bare Return, a whole selected field, and a browser location selection can remain at a word start when Backspace deletes nothing. A terminal Cmd+A selects scrollback; Cmd+L outside a browser promises no empty field. Main Return versus keypad identity is WRM-002's qualified exception.
- Native Cmd+Z/redo/SelectAll chords pass through to the host. These programs certify Ergopti state only, not native editor undo, selection or redo effects.

Escape no-tooltip currently clears or retains the hotstring buffer according to the AI reset preference, while consumed visible Escape revokes cursor-relative eligibility. Linux's unconditional Escape word reset is an observed implementation asymmetry; no additional standalone Escape defect is inferred without a settled independent product rule. Source inspection plus existing registered Escape tests cover trap deferral refusal, runtime quarantine and pending-preview invalidation. The mirrored next-edit lifetime defect is WRM-001, not a duplicate Escape finding.

Other refutations: the settings manager's `is_finite_number` accepts booleans and rejects nonfinite numeric candidates, so its name does not imply that the AI boolean toggle is rejected. The actual runtime getter and transactional settings owner are inspected rather than assuming a nil-returning setter means failure. Keymap pause/resume/stop revoke both contexts; tagged synthetic output is handled by provenance before physical text routing. The already-confirmed undo/repeat privacy and Linux repeat word-boundary findings are not duplicated here. Mac's byte-gated hotstring trimming and mirrored AI capacity differ from Linux's separate 2048-codepoint object, but no additional lower-bound promise for a configured context cap was established; this remains a qualified inventory observation, not a new finding.

Ten exact registered modules run in fresh Lua processes: **145 selected cases, zero failures**, every selected module positive. This includes ten neighboring cascade-count controls within the selected word-reset-policy file and nine source-structure outage controls; they are not presented as 145 native receiving cases. Module counts are 37 arrow/shortcut, 26 word-reset policy, 14 sparse preferences, one navigation invalidation, two Escape invalidation, six Escape fixture isolation, 26 shared context vectors, nine tap-outage structure, sixteen action-epoch reconciliation and eight private-context baseline cases.

Their receipts distinguish manual source-review conclusions from program exit status. No additional root emerged.
