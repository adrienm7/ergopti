# ErgoptiPlus Windows AHK adversarial audit — 2026-08-20

## 1. Executive summary

### Verdict

The audited driver is not yet able to guarantee `G1`–`G5`. This pass found
**29 findings: 7 High, 21 Medium, and 1 Low**. The most fragile surfaces are the
hotstring output transaction, foreground-host classification, backend-specific
LLM lifecycle, gesture modifier ownership, and auxiliary asynchronous menu
publication.

The strongest failures are user-reachable:

- a terminal hotstring is declared fired and committed to `HSE_Buffer`,
  `_PrefixBuffer`, and the LLM context before its delayed sender runs;
- disabling metrics leaves `KLHook.prev_app` permanently empty, yet four
  functional output paths treat that property as authoritative;
- the remote API backend is admitted through Ollama readiness, so a valid remote
  configuration can produce no prediction when local Ollama is absent;
- a `cycle_windows` gesture sends `{Blind}{RShift up}` even while the user is
  physically holding `RShift`;
- the crash-report "off-thread" fix is only a `SetTimer(-1)` hand-off and still
  executes the measured diagnostic workload in the parent AHK interpreter;
- a misspelled LLM validation modifier is persisted as if it meant “no
  modifier”, turning all ten digits into swallowing hotkeys while a suggestion
  is visible;
- custom prompt-profile CRUD reports durable success even though the profile
  graph is absent from both the real config collector and boot loader, so the
  prompt disappears after restart.

This audit did work that the preceding passes did not:

1. It resolved `%APPDATA%\Ergopti\paths.toml` first, then followed
   `_AhkSubDir := "autohotkey\"` in
   `static/ergopti_plus/windows/infra/boot.ahk:77`.
2. It re-derived every cited timing from the retained artifacts themselves,
   using entry timestamps rather than rotated filenames.
3. It separated nested and interrupted wall spans from contiguous stalls.
4. It audited the recent fix commits, especially `7c3335795`,
   `b38352eee`, `a9e1d7a0b`, `b572f8354`, `50c2d43e6`, and
   `00843ecd6`, for forgotten siblings and false-green guards.
5. It compared every production mutation of `_PrefixBuffer` with the
   corresponding `HSE_Buffer` transition.
6. It repeated bounded adversarial sweeps until each covered zone completed a
   discovery-clean pass. Open findings remain open; "dry" means that the last
   full discovery pass found no additional defect, not that the code is fixed.

## 2. Findings

### `AHK-001` — Deferred terminal hotstrings commit before output exists

- **Severity:** High
- **Confidence:** Confirmed by source and behavioral seams; physical live repro
  still recommended.
- **Locations:** `static/ergopti_plus/windows/infra/hotstrings/hotstring_dispatch.ahk:107-131`,
  `:532-565`, `:639-684`;
  `static/ergopti_plus/_shared/modules/timings/constants.toml:206`.
- **Guarantees:** `G2`, `G3`, `G5`.

**Concrete reproduction.** In a recognized Windows Terminal/OpenTUI host,
register a fixture hotstring, type its trigger and completing character, then
type `q` inside the configured terminal delay of at least `20 ms`. The
completing callback returns before `_HSE_RunTerminalTransaction` starts and
`BlockInput("Send")` is acquired. The visible `q` can therefore land before the
fixed backspace count and be erased or splice into the replacement. A second
deterministic reproduction injects a scheduler that accepts the runner, then
invokes it with an emitter returning false: scheduling reports success, all
buffers commit, and no replacement appears.

**Root cause and silence.** `_HSE_BeginTerminalTransaction` returns true when
`SetTimer` is merely armed. The caller interprets that as an emitted fire,
updates last-character state, applies `HSE_ApplyExpansion` to `HSE_Buffer`,
mirrors the effect to the LLM context, resets the preview, and schedules
suppression release. The later sender can only log refusal; it has no owner,
target HWND, input generation, lifecycle epoch, or rollback authority. The fire
therefore looks successful in state and logs even when the screen is unchanged
or corrupted.

The current tests do not contradict the finding.
`tests/unit/test_terminal_hotstring_pacing.ahk:125-156` deliberately proves the
empty scheduling gap and rejected scheduling, but not an accepted timer whose
sender later fails or a physical key in that gap.
`tests/meta/test_expansion_burst_atomic.ahk:146-170` protects only the paced
runner. `tests/meta/test_deferred_hotstring_lifecycle_guards.ahk:26-33` does not
enumerate this new callback. `tests/unit/test_hse_send_failure_transaction.ahk`
tests synchronous branches.

**Fix.** Introduce one terminal transaction owner spanning
schedule → target/input/lifecycle revalidation → send → canonical commit. Capture
foreground HWND/PID, input generation, suspend generation, and registry
generation. At the runner entry, abort if any changed. Commit `HSE_Buffer`,
`_PrefixBuffer`, LLM context, metrics, and the fire log only after the sender
returns success. Sender refusal must leave all canonical state unchanged.
Removing the defer is not an acceptable shortcut because the current terminal
render-order tests require the completing callback to return first.

**Regression test.** Add
`tests/unit/test_terminal_hotstring_transaction_owner.ahk`. Its fake terminal
surface must:

1. capture a scheduled transaction;
2. insert physical `q` before running it;
3. assert final screen is `replacement . "q"`, never a lost `q`;
4. change HWND, suspend generation, and registry generation in separate arms
   and assert zero output/commit;
5. return false from the accepted emitter and assert `HSE_Buffer`,
   `_PrefixBuffer`, LLM context, last-character state, metrics, and fire queue
   are byte-for-byte unchanged.

The test fails before the fix because the scheduling result is currently the
commit verdict.

**Current-`dev` residual after `c6d081890`.** The original precommit was
replaced by `_HSE_TerminalOwner`, but the complete transaction is still not
owned. `_HSE_RunOwnedTerminalTransaction` snapshots `TrailingText` before
`_HSE_SendTerminalPaced` acquires `BlockInput("Send")`; that helper restores
`BlockInput("Default")` before `_HSE_CommitTerminalOwner` runs. A physical
character can therefore arrive outside the snapshot before protection, or
between visible send and canonical commit. The existing owner test injects its
suffix before invoking the runner and cannot exercise either boundary.

Two sibling ownership failures must be fixed in the same commit. First,
`_HSE_BeginOwnedTerminalTransaction` publishes `_HSE_TerminalOwner` only after
an injected scheduler reports success. An inline scheduler therefore runs a
transaction that cannot be current, then leaves it published and pending; a
throw while arming the native timer similarly lacks a complete rollback. The

### `AHK-027` — A global trigger collides with navigation and profile variants

- **Severity:** Medium
- **Confidence:** Confirmed by source and native variant precedence; no live

absent, but AHK then selects the eligible unconditional trigger variant. A new
prediction starts (or its callback returns for missing context/dependencies)
instead of the focused application receiving `Alt+7`. With seven slots, the
same physical chord selects slot seven, so one saved chord has two unrelated
meanings based only on result cardinality.

navigation remains enabled and a custom profile occupies slot five. The

selects that profile; the requested prediction trigger is silently shadowed.

navigation and profiles own contextual variants of the same native hotkey.

the fallback when a contextual predicate returns false. All three owners accept
their configurations independently. `LLM_Menu_NavOwnsSpec` arbitrates only the

plan. Existing tests model each surface separately and therefore never execute
native cross-owner precedence.

policy before native registration. Either reject every ambiguous overlap before
persistence, or publish one explicit priority owner that accounts for trigger,
navigation, and profile eligibility. Test both configuration orders for
trigger/navigation and trigger/profile collisions, including eligible and
ineligible contextual variants. Every physical chord must terminate exactly
once in one of `{navigation, profile selection, trigger, native delivery,
visible rejection}`.

**Remediation (`c7f3406`).** One physical-identity policy now freezes the
captured registration-layout identity of the global trigger and inventories the
static `Tab` owner plus every latent or published `Ctrl+1..9` profile and
navigation plan before accepting it. Trigger replay and live edits reject
overlaps before native reservation or durable mutation; conversely, profile and
navigation publication reject the active or recovering trigger before

recovery, WAL reconciliation, rebind, and rollback, so an ineligible contextual
variant leaves the original event to Windows instead of falling through to a

## 5. Tooltip fidelity (`G5`)

`HSE_Buffer` is the canonical bounded engine context; `_PrefixBuffer` is the
current-word projection used to schedule/render the tooltip. Byte-for-byte
equality is neither required nor desirable after a terminator. The invariant
audited here is stronger and semantic: both must describe the same focused
screen and the preview decision must be the engine's answer for that state.

### Duplicated prediction logic

No current second decision engine was found:

- `_PrefixCollectCandidates` at
  `infra/hotstrings/hotstring_inputhook.ahk:2234-2260` asks
  `HSE_PreviewNextDecision(HSE_Buffer, nextChar)` for both completion routes.
- `_PrefixDecisionDisplayText` at `:2160` formats the returned decision; it
  does not rematch triggers or reapply gates.
- `_PrefixWordBoundaries` at `:165` delegates to
  `_HSE_WordBoundarySet` rather than caching a second character set.
- `_PrefixIndex` and `_TriggerSet` are analytics/boot/near-miss indexes. The
  live tooltip decision explicitly does not read them.

The remaining fidelity defects are therefore transactional, not two competing
predictors: `AHK-001` publishes the canonical answer before the screen
transaction, and `AHK-002` selects the physical sender from optional metrics
state. A regression test should compare the actual fake text surface with
`HSE_Buffer` and the preview after every transition, not merely assert that the
two in-memory buffers derive from shared helpers.
