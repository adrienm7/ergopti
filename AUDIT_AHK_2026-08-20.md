# ErgoptiPlus Windows AHK adversarial audit — 2026-08-20

## 1. Executive summary

### Verdict

The audited driver is not yet able to guarantee `G1`–`G5`. This pass found
**29 findings: 7 High, 21 Medium, and 1 Low**. The most fragile surfaces are the
hotstring output transaction, foreground-host classification, backend-specific
LLM lifecycle, gesture modifier ownership, and auxiliary asynchronous menu
publication.

The strongest failures are user-reachable:

- a terminal hotstring is declared fired and committed to `HSE_Buffer`,
  `_PrefixBuffer`, and the LLM context before its delayed sender runs;
- disabling metrics leaves `KLHook.prev_app` permanently empty, yet four
  functional output paths treat that property as authoritative;
- the remote API backend is admitted through Ollama readiness, so a valid remote
  configuration can produce no prediction when local Ollama is absent;
- a `cycle_windows` gesture sends `{Blind}{RShift up}` even while the user is
  physically holding `RShift`;
- the crash-report "off-thread" fix is only a `SetTimer(-1)` hand-off and still
  executes the measured diagnostic workload in the parent AHK interpreter;
- a misspelled LLM validation modifier is persisted as if it meant “no
  modifier”, turning all ten digits into swallowing hotkeys while a suggestion
  is visible;
- custom prompt-profile CRUD reports durable success even though the profile
  graph is absent from both the real config collector and boot loader, so the
  prompt disappears after restart.

This audit did work that the preceding passes did not:

1. It resolved `%APPDATA%\Ergopti\paths.toml` first, then followed
   `_AhkSubDir := "autohotkey\"` in
   `static/ergopti_plus/windows/infra/boot.ahk:77`.
2. It re-derived every cited timing from the retained artifacts themselves,
   using entry timestamps rather than rotated filenames.
3. It separated nested and interrupted wall spans from contiguous stalls.
4. It audited the recent fix commits, especially `7c3335795`,
   `b38352eee`, `a9e1d7a0b`, `b572f8354`, `50c2d43e6`, and
   `00843ecd6`, for forgotten siblings and false-green guards.
5. It compared every production mutation of `_PrefixBuffer` with the
   corresponding `HSE_Buffer` transition.
6. It repeated bounded adversarial sweeps until each covered zone completed a
   discovery-clean pass. Open findings remain open; "dry" means that the last
   full discovery pass found no additional defect, not that the code is fixed.

#### `AHK3-01` — Model changes do not retire pending Ollama lifecycle work

- **Severity:** Medium.
- **Confidence:** High, derived from the production mutation and callback path.
- **Guarantees:** `G2`, `G3`.
- **Locations:** `static/ergopti_plus/windows/ui/menu/menu_llm/backend_lifecycle.ahk:17-38`,
  `:133-141`, `:186-237`;
  `ui/menu/menu_llm/actions.ahk:240-264`.

**Concrete reproduction.** Enable Ollama with model `A` while its dependency
check or installer is pending. Select model `B` before the captured ready or
failed callback returns. The successful model transaction publishes `B`,
reinitializes the engine, and schedules its warmup, but it neither increments
`_LLM_BackendLifecycleEpoch` nor schedules a replacement lifecycle intent. The
old `A` callback therefore passes `_LLM_Menu_BackendLifecycleIntentIsCurrent`.
An old failure can disable the now-current `B` configuration; an old success can
rebuild/start the bridge and consume resources under an intent whose model is
no longer selected.

**Root cause and silence.** The captured intent stores `model`, but its currency
predicate compares only epoch, backend, enabled state, and API-entry identity.
`_LLM_Menu_ApplyModelCommitted` does not call the lifecycle invalidator. Existing
AHK-003 tests cover backend, enabled, API-entry, and A-B-A epoch changes, but no
test changes only the model between dependency admission and callback delivery.
The stale callback uses ordinary success/failure UI paths, so no ownership error
is logged.

**Fix and regression test.** Make the model part of intent currency and retire
or replace the prior lifecycle intent after a successful model commit. Extend
`test_llm_backend_lifecycle_dispatch.ahk` through the production dispatcher:
capture `A`, publish `B`, then deliver `A` ready and failed callbacks and require
zero bridge start, menu build, warmup, or failure mutation. Add current-`B` and
model A-B-A controls so a broad permanent refusal cannot pass.

#### `AHK4-01` — Walker replay discards consumer exceptions and silently rejects the metrics cache

- **Severity:** Low-Medium.
- **Confidence:** High for the swallowing path; the poison-row reproduction is
  source-derived rather than live-injected.
- **Guarantee:** `G1` diagnosability and robustness adjacency. The publication
  boundary remains fail-closed.
- **Locations:** `static/ergopti_plus/windows/infra/sqlite3.ahk:471-476`;
  `modules/keylogger/keylogger_reader_db.ahk:326-330`, `:829-845`;
  `modules/keylogger/keylogger_walker_events.ahk:55-63`.

**Concrete reproduction.** Insert a durable `events_typing` row whose timestamp
has non-numeric minute characters, for example `2026-08-24 12:xx:00`, then run
the real cold metrics-cache rebuild. `KLW_WalkTypingEntry` reaches
`Integer(mm)` and throws. `SQLite_EachRow` catches and discards the `Error`,
returns `-1`, and the three-sweep replay reduces the failure again to `-1`.
The cold builder closes and rejects the candidate cache without publishing
partial aggregates, but no retained diagnostic names the logical/window/system
sweep, row, or original exception.

**Root cause and silence.** `SQLite_EachRow` uses a bare consumer catch, the
replay driver collapses every negative result and its own exceptions into one
Boolean, and the caller sees only `{ok:false}`. Existing keylogger fail-loud
tests exercise SQL failures rather than a throwing row consumer, so deleting
all exception context remains green. The timestamp formats themselves are
sliced correctly; malformed numeric residue is this poison-row class, not a
separate finding.

**Fix and regression test.** Preserve the fail-closed candidate transaction,
but carry or emit one sanitized diagnostic containing the statement family,
replay sweep, row identity/index, and original `Error.Message`. Exercise an
in-memory SQLite database through the real cold replay with one valid row and
one poison row. Require `{ok:false}`, no partial aggregate publication, and
exactly one owned diagnostic with the original cause. A valid-only control must
still publish normally, and deleting exception propagation or the diagnostic
must make the regression red.

#### `AHK5-01` — Mouse park and distance metrics are dead on negative screen coordinates

- **Severity:** Medium.
- **Confidence:** High, source-derived from deterministic coordinate states.
- **Guarantee:** `G2` silent missing output.
- **Locations:** `static/ergopti_plus/windows/modules/keylogger/keylogger_mouse.ahk:119-129`,
  `:440-486`.

**Concrete reproduction.** Place a monitor left of the primary display and
keep the pointer at `x=-1920`. Every distance tick stores that negative value,

`park_last_x < 0` as uninitialized on every tick, continually restarts
`park_still_since`, and never emits `mouse_idle_park` after the three-second

ambiguity, and the `(-9999,-9999)` fired-position sentinel can collide with a

**Root cause and silence.** Initialization, a prior parked position, and real

exception or log occurs; dashboards display plausible zeros. Existing mouse
tests inspect suspend/filter ordering, not negative-coordinate behavior.

**Fix and regression test.** Replace sign and magic-coordinate sentinels with
explicit `has_previous`, `park_armed`, and `park_fired` ownership flags, while
preserving suspend/filter resets. Drive the production park tick through an

one exact park event, then move on the negative monitor and require non-zero
distance. Keep positive-coordinate, reset, jitter, and dedup controls; reverting
either former sign guard must make the regression red.

#### `AHK5-02` — A diagnostic write can turn a successful dashboard push into failure

- **Severity:** Low-Medium.
- **Confidence:** High, source-derived from deterministic fault injection.
- **Guarantees:** `G1`, `G2`.
- **Locations:** `static/ergopti_plus/windows/modules/keylogger/keylogger_webview.ahk:686-725`,
  with the adjacent unguarded profile-directory creation at `:225-230`.

**Concrete reproduction.** Open a metrics dashboard and lock
`webview.log` with exclusive sharing while `KLWV_PushPrefetch` runs.
`PostWebMessageAsString` can successfully deliver the blob, but the following
success `FileAppend` is inside the same `try` and throws. The catch therefore
misclassifies the delivered payload as a COM failure, then immediately performs
another unguarded append to the same locked file. That second exception escapes
into `KLWV_DelayedFirstPush` or `KLWV_OnFirstBuildTerminal`, aborting first-paint
recovery. If it does return `false`, callers consume retry budget and can report
exhausted first paint even though the dashboard already received the payload.

**Root cause and silence.** Fallible observability I/O participates in the
functional delivery transaction, and the failure-path diagnostic is itself
unguarded. The existing callback fail-safe meta-test checks only `FileRead`
containment and cannot distinguish a successful COM push from a failed log
append. The nearby bare `DirCreate(udir)` is the same uncaught-filesystem class
on dashboard open and must be handled at its own functional boundary.

**Fix and regression test.** Make COM delivery the sole determinant of push
success and perform success/failure diagnostics through a separately contained
logging seam. With the log seam throwing, require `KLWV_PushPrefetch=true`, one
COM delivery, no retry, and `first_paint_done=true`; with the COM seam throwing,
require `false` and one owned retry. Guard directory creation and report its
failure through the central logger without letting it escape the menu/timer
entry. Mutating either diagnostic back into the delivery `try` must make the
behavioral test red.

#### `AHK5-03` — Monitor-focus telemetry misses real moves and invents topology changes

- **Severity:** Low-Medium.
- **Confidence:** High, source-derived from the classifier and snapshot update.
- **Guarantee:** `G2` missing and wrongly attributed output.
- **Locations:** `static/ergopti_plus/windows/modules/keylogger/keylogger_window_topology.ahk:192-258`.

**Concrete reproduction.** Drag a foreground window from monitor 1 to monitor 2
or use `Win+Shift+Right`. The large coordinate delta always selects

**Root cause and silence.** Monitor membership is treated as a lowest-priority

look like ordinary focus telemetry; the existing topology test checks only
single append, not classification or identity.

**Fix and regression test.** Track stable monitor identity independently and
debounce/emit its transition alongside the move that caused it. Through injected
geometry and monitor seams, two stable ticks moving from monitor A to B must emit
exactly one `window_move` and one `monitor_focus_change`; a pure enumeration
reorder with identical geometry and physical identity must emit neither monitor
focus event nor user-move attribution. Both former `else if` priority and raw
index identity mutations must turn the test red.

#### `AHK6-01` — Bundle extraction corrupts paths containing an apostrophe

- **Severity:** Medium.
- **Confidence:** High for command binding and boot failure; the complete
  compiled first-launch path is source-derived rather than destructively
  exercised.
- **Guarantees:** `G1`; subsequent guarantees are unreachable when boot exits.
- **Locations:** `static/ergopti_plus/windows/infra/bundle.ahk:151-167`,
  `:185-240`.

**Concrete reproduction.** Run a compiled build from a Windows profile whose

stage/verify/rollback order, but never execute or semantically parse the built
command; deleting all escaping would remain green.

and double every apostrophe in `ZipPath` and `DestDir` before interpolation, or
prefer a parameterized `-File` transport as the hardened onboarding sibling
does. Add a behavioral command-builder test with apostrophe, space, and
backslash vectors which recovers the exact original arguments, plus a normal
path control that remains byte-for-byte compatible. Run that command against
a harmless temporary archive through an injected runner and require success;
removing the quote doubling must make the test fail. The repository-wide
PowerShell search found no second live inline path interpolation of this form;

### `AHK-001` — Deferred terminal hotstrings commit before output exists

- **Severity:** High
- **Confidence:** Confirmed by source and behavioral seams; physical live repro
  still recommended.
- **Locations:** `static/ergopti_plus/windows/infra/hotstrings/hotstring_dispatch.ahk:107-131`,
  `:532-565`, `:639-684`;
  `static/ergopti_plus/_shared/modules/timings/constants.toml:206`.
- **Guarantees:** `G2`, `G3`, `G5`.

**Concrete reproduction.** In a recognized Windows Terminal/OpenTUI host,
register a fixture hotstring, type its trigger and completing character, then
type `q` inside the configured terminal delay of at least `20 ms`. The
completing callback returns before `_HSE_RunTerminalTransaction` starts and
`BlockInput("Send")` is acquired. The visible `q` can therefore land before the
fixed backspace count and be erased or splice into the replacement. A second
deterministic reproduction injects a scheduler that accepts the runner, then
invokes it with an emitter returning false: scheduling reports success, all
buffers commit, and no replacement appears.

**Root cause and silence.** `_HSE_BeginTerminalTransaction` returns true when
`SetTimer` is merely armed. The caller interprets that as an emitted fire,
updates last-character state, applies `HSE_ApplyExpansion` to `HSE_Buffer`,
mirrors the effect to the LLM context, resets the preview, and schedules
suppression release. The later sender can only log refusal; it has no owner,
target HWND, input generation, lifecycle epoch, or rollback authority. The fire
therefore looks successful in state and logs even when the screen is unchanged
or corrupted.

The current tests do not contradict the finding.
`tests/unit/test_terminal_hotstring_pacing.ahk:125-156` deliberately proves the
empty scheduling gap and rejected scheduling, but not an accepted timer whose
sender later fails or a physical key in that gap.
`tests/meta/test_expansion_burst_atomic.ahk:146-170` protects only the paced
runner. `tests/meta/test_deferred_hotstring_lifecycle_guards.ahk:26-33` does not
enumerate this new callback. `tests/unit/test_hse_send_failure_transaction.ahk`
tests synchronous branches.

**Fix.** Introduce one terminal transaction owner spanning
schedule → target/input/lifecycle revalidation → send → canonical commit. Capture
foreground HWND/PID, input generation, suspend generation, and registry
generation. At the runner entry, abort if any changed. Commit `HSE_Buffer`,
`_PrefixBuffer`, LLM context, metrics, and the fire log only after the sender
returns success. Sender refusal must leave all canonical state unchanged.
Removing the defer is not an acceptable shortcut because the current terminal
render-order tests require the completing callback to return first.

**Regression test.** Add
`tests/unit/test_terminal_hotstring_transaction_owner.ahk`. Its fake terminal
surface must:

1. capture a scheduled transaction;
2. insert physical `q` before running it;
3. assert final screen is `replacement . "q"`, never a lost `q`;
4. change HWND, suspend generation, and registry generation in separate arms
   and assert zero output/commit;
5. return false from the accepted emitter and assert `HSE_Buffer`,
   `_PrefixBuffer`, LLM context, last-character state, metrics, and fire queue
   are byte-for-byte unchanged.

The test fails before the fix because the scheduling result is currently the
commit verdict.

**Current-`dev` residual after `c6d081890`.** The original precommit was
replaced by `_HSE_TerminalOwner`, but the complete transaction is still not
owned. `_HSE_RunOwnedTerminalTransaction` snapshots `TrailingText` before
`_HSE_SendTerminalPaced` acquires `BlockInput("Send")`; that helper restores
`BlockInput("Default")` before `_HSE_CommitTerminalOwner` runs. A physical
character can therefore arrive outside the snapshot before protection, or
between visible send and canonical commit. The existing owner test injects its
suffix before invoking the runner and cannot exercise either boundary.

Two sibling ownership failures must be fixed in the same commit. First,
`_HSE_BeginOwnedTerminalTransaction` publishes `_HSE_TerminalOwner` only after
an injected scheduler reports success. An inline scheduler therefore runs a
transaction that cannot be current, then leaves it published and pending; a
throw while arming the native timer similarly lacks a complete rollback. The
caller already created `DeferredOwner`, so its `finally` also mistakes a
rejected/throwing admission for an owner and withholds both suppression
releases. Second, `_OnPrefixChar` calls `HSE_FeedChar` while an owner is pending
and then returns after appending the physical suffix. If that character itself
completes another star hotstring, its `HSEMatch` is discarded forever.

Extend the regression matrix at the actual ownership boundaries: inject a
physical suffix from `BlockFn("Send")` and `BlockFn("Default")`; run inline,
refused, and throwing schedulers; assert suppression/synthetic ownership is
balanced in every arm; and queue a suffix that completes a second star trigger,
then assert that expansion fires exactly once after the first owner commits.

### `AHK-026` — Navigation eligibility and execution use different tooltip owners

- **Severity:** Medium
- **Confidence:** Confirmed by source and the AHK hotkey execution model; the
  specified two-phase scheduling seam has not yet been implemented or run.
- **Locations:**
  `static/ergopti_plus/windows/ui/menu/menu_llm/tab_accept.ahk:166-188`,
  `:311-315`, `:495-527`;
  `static/ergopti_plus/windows/ui/tooltip/llm.ahk:538-579`;
  `static/ergopti_plus/windows/ui/tooltip/helpers.ahk:421-432`.
- **Guarantees:** `G2`, `G3`; class `F`.

**Concrete reproduction.** Present prediction record `A` with seven slots and
press physical digit `7`. The navigation `HotIf` snapshots `A`, returns true,
and the physical key is suppressed. Before the posted hotkey callback runs,
publish a different prediction record `B`. With seven slots, the callback
rereads and navigates `B` to index seven even though `A` owned the decision. With
six slots, it returns without navigation after the original key has already
been lost. A following acceptance can therefore accept an unintended `B`
suggestion, or the digit can disappear with no visible output.

**Root cause and silence.** The predicate's short `Critical` ends after it
returns a Boolean. Although its snapshot contains the exact record, the bound
callback retains only the integer index. `_LLM_Nav_Jump` and
`LLM_TooltipSetActiveIdx` later reread the current surface. Detached tooltip
construction deliberately leaves the old record acceptable until a final
pointer swap, so this owner replacement is a normal render ordering, not an
exception. `_LNHT_FirePhysical` calls predicate and callback synchronously on
adjacent lines; the `AHK-025` range matrix never interposes a publication and is
false-green for this temporal class.

**Fix and regression test.** Conditional suppression needs one event-time
owner. At the keyboard-hook boundary, validate and reserve navigation against
the exact current record, then return either `SUPPRESS` with an immutable
receipt or `PASS` while the original physical event still exists. A deferred
paint may consume only that receipt and must never reread `B`. A late synthetic
replay is not equivalent: it cannot preserve physical ordering, layout,
modifiers, input-buffer observation, and recursion safety. Add a two-phase hook
decision/paint seam for `A7 -> B7` and `A7 -> B6`, including delayed, duplicated,
and omitted callbacks. Every event must terminate in exactly one of
`{exact-record navigation commit, native pass-through}` and must never mutate
`B` accidentally.

**Remediation (`9650984`).** A hardened x64 low-level keyboard owner now makes
the terminal decision while the original event still exists. It validates the
published navigation plan and exact tooltip token/index under one native lock,
then returns `PASS` or records an immutable `SUPPRESS` receipt. The AHK bridge
applies and completes each receipt exactly once against its retained record;
deferred painting never rereads a replacement surface. Tab acceptance uses a
native compare-and-detach operation, so either navigation wins first or the
accepted owner is removed before text injection.

The same owner contract spans key-up latches, modifier provenance and menu
disguise, receipt FIFO/overflow, tooltip render identities and deadlines,
suspend/quiesce, stop/restart recovery, and stale repaint debt. The tracked DLL
is built reproducibly from the committed C source, checked as x64 with
ASLR/DEP/CFG, 15 exact exports, no dynamic compiler runtime, and a source/recipe
fingerprint before bundling. Hook-free native tests passed `23/23`; the AHK
navigation-owner suite passed `60/60`; full `run_all` passed `4721/0`, e2e
`5/0`, the complete `Ahk2Exe` include graph compiled, all `1221` AHK files
retained BOM+LF, JavaScript passed `177/177`, and the 338-file static bundle
embedded the verified DLL. This closes the tooltip-owner race without a late
synthetic replay; profile-order ownership remains `AHK-029`.

### `AHK-027` — A global trigger collides with navigation and profile variants

- **Severity:** Medium
- **Confidence:** Confirmed by source and native variant precedence; no live
  physical-key probe was run.
- **Locations:**
  `static/ergopti_plus/windows/ui/menu/menu_llm/menu_settings.ahk:649-653`;
  `ui/menu/menu_llm/trigger_shortcut.ahk:42-55`, `:1004-1005`;
  `adapters/hotkey_registrar.ahk:396-411`;
  `ui/menu/menu_llm/tab_accept.ahk:166-218`;
  `ui/menu/menu_llm/menu_profiles.ahk:925-960`.
- **Guarantee:** `G2`; class `F`.

**Concrete reproduction.** Configure `trigger_shortcut="Alt+7"` and
`val_modifiers="alt"`, display six prediction slots, and press physical
`Alt+7`. The navigation predicate correctly yields because slot seven is
absent, but AHK then selects the eligible unconditional trigger variant. A new
prediction starts (or its callback returns for missing context/dependencies)
instead of the focused application receiving `Alt+7`. With seven slots, the
same physical chord selects slot seven, so one saved chord has two unrelated
meanings based only on result cardinality.

A second supported configuration is `trigger_shortcut="ctrl+5"` while profile
navigation remains enabled and a custom profile occupies slot five. The
eligible contextual profile variant wins over the configured global trigger and
selects that profile; the requested prediction trigger is silently shadowed.

**Root cause and silence.** The trigger transaction owns a global variant while
navigation and profiles own contextual variants of the same native hotkey.
Contextual variants have precedence when eligible, but the global variant is
the fallback when a contextual predicate returns false. All three owners accept
their configurations independently. `LLM_Menu_NavOwnsSpec` arbitrates only the
profile/navigation pair; the trigger owner checks neither published contextual
plan. Existing tests model each surface separately and therefore never execute
native cross-owner precedence.

**Fix and regression test.** Define one transactional cross-feature collision
policy before native registration. Either reject every ambiguous overlap before
persistence, or publish one explicit priority owner that accounts for trigger,
navigation, and profile eligibility. Test both configuration orders for
trigger/navigation and trigger/profile collisions, including eligible and
ineligible contextual variants. Every physical chord must terminate exactly
once in one of `{navigation, profile selection, trigger, native delivery,
visible rejection}`.

**Remediation (`c7f3406`).** One physical-identity policy now freezes the
captured registration-layout identity of the global trigger and inventories the
static `Tab` owner plus every latent or published `Ctrl+1..9` profile and
navigation plan before accepting it. Trigger replay and live edits reject
overlaps before native reservation or durable mutation; conversely, profile and
navigation publication reject the active or recovering trigger before
installing a contextual variant. Exact owner generations survive replay,
recovery, WAL reconciliation, rebind, and rollback, so an ineligible contextual
variant leaves the original event to Windows instead of falling through to a
global trigger.

Behavioral tests cover both configuration orders, eligible and ineligible
variants, boot/live/recovery paths, strict native aliases, and one captured
registration-layout identity; independent meta guards pin the static `Tab`
owner plus wildcard pointer and raw clipboard owners. `run_all` passed `4656/0`,
e2e `5/0`, the complete `Ahk2Exe` include graph compiled, all `1219` AHK files
retained BOM+LF, and JavaScript passed `177/177`. This closes only the
cross-owner collision root. At `c7f3406`, temporal tooltip and profile-order
ownership remained `AHK-026` and `AHK-029`; `AHK-026` was later remediated in
`9650984`.

## 5. Tooltip fidelity (`G5`)

`HSE_Buffer` is the canonical bounded engine context; `_PrefixBuffer` is the
current-word projection used to schedule/render the tooltip. Byte-for-byte
equality is neither required nor desirable after a terminator. The invariant
audited here is stronger and semantic: both must describe the same focused
screen and the preview decision must be the engine's answer for that state.

### Duplicated prediction logic

No current second decision engine was found:

- `_PrefixCollectCandidates` at
  `infra/hotstrings/hotstring_inputhook.ahk:2234-2260` asks
  `HSE_PreviewNextDecision(HSE_Buffer, nextChar)` for both completion routes.
- `_PrefixDecisionDisplayText` at `:2160` formats the returned decision; it
  does not rematch triggers or reapply gates.
- `_PrefixWordBoundaries` at `:165` delegates to
  `_HSE_WordBoundarySet` rather than caching a second character set.
- `_PrefixIndex` and `_TriggerSet` are analytics/boot/near-miss indexes. The
  live tooltip decision explicitly does not read them.

The remaining fidelity defects are therefore transactional, not two competing
predictors: `AHK-001` publishes the canonical answer before the screen
transaction, and `AHK-002` selects the physical sender from optional metrics
state. A regression test should compare the actual fake text surface with
`HSE_Buffer` and the preview after every transition, not merely assert that the
two in-memory buffers derive from shared helpers.
