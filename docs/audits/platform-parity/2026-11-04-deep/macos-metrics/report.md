## Confirmed actionable findings

### MM-001 — User Metrics pause still records window activity and backfills pointer travel

Severity **high** for identifying window metadata; confidence **high** for observed mechanics. Expected broad collection-pause semantics follow the menu label “Pause collection” / “Suspendre la collecte” (`_shared/data/locales/en.json:1472`, `fr.json:1472`) and the cross-driver design; that design's enumerated minimum explicitly mentions typing/clicks/scrolls, so distinguish this from a claim that its text explicitly enumerates every sensor.

`keystats/init.lua:suspend_collection` at `:1382` flushes typing then sets `CoreState.collection_suspended=true`. Keyboard/synthetic sinks consult this through `privacy_context.lua:18`; tracker and sensor producers use only the **global script pause** predicate. Consequences observed while the user Metrics pause is active:

- `context_tracker.lua:update_private_status :1012` guards global pause only; `:1053–1063` appends `window_switch` with both old and new title. Actual probe records `next_title='PAUSED SECRET'` while `collection_suspended=true`.
- `watchers.lua:109–114` hardware gate similarly omits user collection pause; actual spaces callback still appends `space_change`.
- `watchers.lua:poll_mouse_distance :152–159`, invoked by maintenance `:318`, keeps accumulating mouse displacement. Probe seeds a position, pauses collection, moves 1000 pixels and resumes. The exact `log_manager.lua:_detach_buffer_snapshot :571–597` subsequently snapshots that **paused movement** into the next admitted typing entry. Mouse position is not reseeded at suspend/resume.

Downstream does not rescue this: real `log_manager.lua:append_log :722–730` accepts any entry into FIFO; `_drain_deferred_logs :697–706` calls Rotation without privacy admission. Probe executes those exact functions and sees the paused title reach Rotation. Actual `rotation.lua:299–326` JSON-encodes/appends the entry without an admission filter; `sqlite_writer.lua:_builders.window_switch :556–564` copies both titles into native SQL; `log_manager.lua:2150–2154` builds it and `:2186–2188` walks it. The title is therefore on a production persistence path, rather than merely an internal cached observation. Existing pause source test passes because it covers the scalar state and typing/synthetic gates; the tracker pause regression injects **global** pause, not `collection_suspended`.

Windows equivalent is stronger: design `docs/design/metrics-suspend-and-reset-session.md` declares `KL_AppendLog` gate for every entry, and its interval owner also invalidates intervals across collection boundaries. This report makes no claim that Linux privacy coverage is perfect.

Suggested regression: actual `suspend_collection` → browser title change/app switch/spaces callback/mouse movement → resume → first typing flush. Assert no new identifying activity entries and no paused displacement, while allowing durable closing records owned before the pause. Do not indiscriminately discard accepted FIFO work or pre-pause session closure.

### MM-002 — Measured sleep/lock durations never reach macOS aggregate KPIs

Severity **medium**; confidence **high**. Probe drives actual `caffeinate_cb` through a simple 60,000 ms sleep/wake and 30,000 ms lock/unlock. Actual walker result is `sleep_ms=0, locked_ms=0, passive_count=2`.

`watchers.lua:551–562` emits `wake` without duration, then emits `passive_period(kind,duration_ms)`; unlock does the same at `:578–587`. `log_manager.lua:926–929` preserves the measured duration in the passive row. But `aggregator/events.lua:178` merely increments passive count for that row; `:179–180` credits duration only on `unlock`/`wake`, whose producer never supplied it. `aggregator/sql.lua:325–332` writes these zero fields. `sqlite_reader.lua:441–447` publishes `_system`; shared `ui/metrics_apps/state.js:279–281` and `main.js:970–982` display the incorrect zero durations alongside nonzero count.

This persists through cache reconstruction and foreign import: `log_manager.lua:1653–1660` rebuilds events_system metadata with the same walker; live ingest uses it at `:2189–2190`. Raw durations remain available, so a corrected cache revision/rebuild can recover historical simple intervals.

Important refutation: Windows' similar-looking walker is **not evidence of a shared defect**. `windows/.../keystats_reader_db.ahk:1540–1553` independently sums `passive_period.kind=lock/sleep`; `keystats_walker_sql.ahk:259–262` explicitly leaves these fields SQL-owned. macOS has no equivalent refresh. Linux sleep approximation was already known and is not a new finding here.

Suggested regression: producer → raw builder/replay → walker → aggregate flush/manifest, with both simple intervals, not pre-filled fixture KPI rows. Do not add duration to both edge and passive record then double-count it.

### MM-003 — Keep-awake accounting is produced but never aggregated

Severity **medium**; confidence **high**. `modules/shortcuts/actions/system.lua:449–461` and `:490–501` publish `passive_period(kind='awake',duration_ms)` plus `awake_focus(app,duration_ms)` on auto/manual keep-awake stop. This is expressly intended to make the dashboard account for the keep-awake period (comment at `:450`). `log_manager.lua:926–934` preserves both.

Actual `aggregator/events.lua:173–180` initializes `awake_ms=0` but has no duration branch for either record, and no `awake_focus` app attribution. Probe feeds the **complete pair** for 120,000 ms and still obtains system `awake_ms=0`. Full tree search finds no other macOS owner incrementing it. Raw replay repeats the same omission. Shared `ui/metrics_apps/state.js:282` reads machine keep-awake duration and `:343–352` subtracts per-app awake duration from foreground work by default; missing attribution makes the keep-awake counting toggle ineffective for those macOS intervals.

Windows' SQL refresh at `keystats_reader_db.ahk:1548` includes passive kind `awake`. Linux's similarly named `awake_ms` is incremented for ordinary unlocked sampled time (`system_metrics.lua:349`), not proven equivalent keep-awake usage; it must not be advertised as semantic parity solely because the field exists.

Suggested regression: actual keep-awake completion pair → live/replay aggregation → system and app payload → toggle; credit the global duration once, not twice, and define app attribution when the foreground app changes mid-session.

### MM-004 — Nested lock/display-sleep/system-sleep overwrite interval ownership

Severity **medium**; confidence **high** for the accepted callback sequence; actual native event ordering was not measured on a Mac.

`watchers.lua:caffeinate_cb :535–591` stores only one `passive_started_at/passive_kind`. Every lock, screen sleep, or system sleep blindly overwrites it (`:541–542`, `:568–569`); the first wake clears it (`:560–561`), leaving a later unlock with no lock owner. Duplicate screen/system sleep resets the start without closing the previous segment.

Probe executes legal callback inputs at 1-second increments: lock → display sleep → system sleep → system wake → display wake → unlock. It emits **one** passive interval, sleep duration 1000 ms; both initial lock and post-wake lock portions, plus the earlier display-sleep segment, are lost. Even fixing MM-002 will not reconstruct those missing raw durations. This also distorts passive_count independently of display rendering.

Equivalent Windows implementation `keystats_system_intervals.ahk:43–64` retains `Locked` and `Sleeping` independently, emits a completed interval only on kind transitions, and gives sleep precedence while still locked. That is explicit non-overlap policy, not evidence that macOS' overwrite is intentional. macOS comments contain no such design rationale.

Suggested regression: nested/repeated sleep and lock edges with exact partition totals, including lock→sleep→wake→unlock and both display/system edge duplicates; no overlap or lost pre/post-sleep lock segment. Also define partial interval shutdown and pause invalidation.

## Persistence/replay/error pass and refutations

- FIFO append refusal does **not** immediately lose detached typing: `_drain_deferred_logs :667–714` advances only on exact Rotation true; the identical operation/entry remains, and ingest retries if timer acquisition failed. Rotation retains exact serialized receipt (`rotation.lua:299–333`). This rejects an initial concern about blanket snapshot loss.
- Local SQLite commit precedes SQL ledger append, but committed `DATA_SQL_OUTBOX_KEY` is written in the same transaction (`log_manager.lua:2217–2228`); `_flush_local_data_sql_outbox` is retried before new local ingest (`:2114–2119`). No new ordinary append-failure data-loss claim established.
- Ingest rollback restores event IDs and ngram context (`log_manager.lua:2229–2245`), rather than retrying with already mutated continuity state. Recovery restore and foreign-only saved local context were inspected at `:1560–1693`. No confirmed duplicate-credit bug established here.
- Foreign partial SQL is bounded to verified complete COMMITs (`export.lua:638–664`), callback failure defers watermark (`:675–686`), failure attempts rollback (`:699–703`), and the wrapper at `log_manager.lua:1875–1895` turns refused sync into a logged empty device list. The apparent `#nil` hazard is refuted by that wrapper.
- Recovery progress commits with row batches and resumed cursor; no finding is made solely from long rebuilds. Battery pacing and runtime reload behavior are explicit existing decisions in routed memory. Native recovery timing and actual SQLite contention were not executed here.
- Session reset at `init.lua:1409–1429` queues history before clearing live windows; user pause remains independent of secure filters. No new typing-loss reset finding established. Reset refuses when metrics stopped despite a broader code comment saying “disabled”; the design requires paused/secure support, so this is not promoted as feature failure.
- Windows-only raw sensor families, Linux missing ledger, inert night_wake KPI, pointer-unit disparity and CPU sampler gap are **already-known baseline**, not new findings.

Inspected production start wiring, global/user pause admissions, native tracker title/app watchers, hardware callbacks and passive ownership, snapshot/FIFO retry, Rotation append acknowledgement, raw SQL dispatch, local ingest rollback/outbox, foreign partial-batch receipts/watermarks, raw recovery with same system walker, aggregate SQL and manifest/dashboard fields, session reset and stop. This is not certification of exhaustive runtime parity: physical capture/producer streams and detailed ergonomic walker internals are separate modules, and native Accessibility behavior, real caffeinate edge order, asleep-clock semantics, day/DST crossings, SQL transaction fault injection and browser private-mode title support remain unexecuted on macOS. No assertion that every legal OS timing interleaving is now verified. Suggested CI extension: producer-to-dashboard fixtures for passive/awake system intervals, user-pause metadata closure and pointer boundaries, run alongside the declarative parity inventory to distinguish availability from actual measurement correctness.
