## New confirmed actionable finding

### LM-001 — excluded collection spans remain inside typing sequences and durations

Severity: medium. Confidence: high. Guarantees: G5 (truthful metrics/preview). This is aggregate integrity failure, **not evidence that excluded characters are persisted**.

Reproduction executes real Linux collector and shared walker with the repository's synchronous fake SQLite transport and isolated canonical preference port. It runs five public exclusion mechanisms (collection pause, private-window signal, secure-field signal, suppress/unsuppress, persisted metrics disable/enable), in both one pending snapshot and across an acknowledged fake-transport COMMIT:

1. Record `a` in `test-app` at 1000 ms.
2. Optionally flush (the across-COMMIT variant).
3. Enter an exclusion, attempt `X` at 1100 ms, leave the exclusion.
4. Record `b` at 1200 ms and a space at 1300 ms, then flush.
5. All ten cases produce a word `ab` count 1, bigram `ab` count 1 with delay 200 ms, and `typing_time_ms=300`. The raw source is `ab ` with the 200 ms delay bridging the unobserved interval; `X` is correctly absent. The aggregate cannot establish that a and b were consecutive characters in the actual input stream (`aXb `).

Evidence and root cause:

- `linux/modules/keystats/keystats.lua:417` `may_record()` correctly rejects the excluded key.
- `:1644` `settle_capture_policy()` retires hold/focus/title ownership but leaves typing cursors, pending runs and walk context continuous.
- `:1809` `suspend_collection()`, `:1838` `set_enabled()`, `:1859` `set_private_window()`, `:1868` `set_secure_field()` use this policy settlement; suppress at `:1789` has the same result.
- `:782` `_typing_last_key_at` gives b the interval from a; `:845` `record_app_key()` similarly credits the last-key interval, including excluded time.
- `:2246` copies the committed walker contexts; `:2295` walks each buffered run without an exclusion marker; `:2624` adopts the successor context on COMMIT.
- `linux/modules/keystats/aggregate_walker.lua:184` computes the next real-time gap and `:196` feeds the shared walker; a short excluded interval is indistinguishable from continued typing.

Required fix direction: carry an explicit exclusion boundary through immutable buffering and committed walk ownership, settle/reset sequence/word/correction/finger/burst continuity as appropriate, and invalidate the relevant inter-key timing cursors. Do not clear pending source or discard pre-exclusion history. The regression must run both before and after a pending flush and retain correct source ownership when that flush fails/retries.

Other OS comparison: macOS `modules/keystats/init.lua:1382` flushes existing text before collection pause; this is a materially different producer boundary. It is **not sufficient evidence** that its derived walker cannot bridge the same gap. Windows/macOS outcome equivalence for LM-001 is unverified in this Linux-specific audit; parent OS-module audits should check it independently rather than reporting a proven Linux-only defect.
