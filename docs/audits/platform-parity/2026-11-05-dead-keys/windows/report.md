This contradicts the explicit row policy that an off row belongs to the OS layout on every level. ## DKW-001 — Pending composition bypasses disabled rows

`_KLE_BaseCriterion` returns true for every registered continuation whenever `KLE_State` is pending, before evaluating `LayoutRowIsEmulated`. That admission is needed to settle the pending accent, but `_KLE_OnKey` then selects `_KLE_Emit` whenever the global base layer is desired on and the digit layer does not own the key. It never checks the individual row. `_KLE_Emit`, `KeylayoutEmulation_Press`, and the replay-route capture do not restore that missing policy. The existing native-character composition path is used when the global base is off, demonstrating the intended mechanism already exists.

Source reproduction: select registry `ergopti_plus`, native US keyboard layout, base desired on, home row enabled, top row disabled. With no modifiers, SC02B (Backslash, macOS code 42, home row) enters `s1_circumflex`. Press SC012 (KeyE, macOS code 14, disabled top row). The selected layout resolves this physical key as `o`, hence pending composition requests **ô**. The native US character is `e`; the registry's native-character composition table maps `e` in this state to **ê**. `data-probe.lua` executes the original parser and row policy and asserts these shipped-data relations. Native US `e` is an explicit scenario assumption, not a measured DLL result.

The actual registrar binds `_KLE_BaseCriterion` and `_KLE_OnKey`; entrypoint boot registers registry bindings before builtin layout hotkeys. The neutral row-off path correctly declines the key. The failure is specific to the pending-state callback. Existing row-policy tests exercise neutral criteria and row/digit policy; the native dead-key test calls `KeylayoutEmulation_PressNative` directly with global base off. Neither covers the actual callback with global base on and one row off. Therefore their expected success does not refute this path.

Severity: medium (wrong user text under a supported per-row configuration). Confidence: high for source routing and shipped-data distinction; Windows native delivery requires confirmation. Regression direction: through the original registered callback, arm the home-row dead key, retain global base on, disable top row, use an actual installed US HKL, and verify the follow-up uses native-character composition. Include a neutral row-off control, enabled-row control, Shift continuation, and native-dead-key fallback. Do not substitute a direct call to `PressNative` for the callback.

## Two Windows implementations and their contracts

The builtin Ergopti `DeadKey(Mapping)` API is a bounded InputHook transaction. Public layer dispatchers and `_ErgoptiDeadKeyOrChain` feed its generated maps. It captures one Unicode scalar (two UTF-16 units permitted), maps it or emits the base plus unmapped scalar, and emits the base after a two-second timeout. It rejects invalid scalar captures and stale ownership; suspension is checked both before capture and after settlement. Critical ownership covers registration and output while the blocking wait releases Critical. Reentrant layer dead-key producers emit their chain literal rather than starting a second capture. Generated builtin maps explicitly refuse stateful `Next` transitions; this is a limitation of this API, while registry emulation supports chains.

Registry `KeylayoutEmulation_*` reads the canonical keylayout action machine, supports chained states, derives native-character compositions for independently disabled base layers, and resets state on successful canonical layout replacement or unload. Invalid candidate loads are constructed before publication and preserve the old canonical cell. Retained replay recipes intentionally retain their admitted old model and event-time modifier data; they are not new native ownership. Reset-observer metadata fences source/function/cohort identities and explicitly declares metadata-only, incomplete native admission. A partial registration does not publish a valid cohort.

Registry pending state has no two-second deadline. Its scan-based reset observers cover Backspace, Escape, Enter, Tab, Delete, arrows, Home, End, PageUp and PageDown. Shortcut handling clears pending state before forwarding the command-level character or physical fallback. Scan-code identities are the already-fixed solution to computed-name hotkey shadowing: this audit does not report that historical bug again.

The synthetic `ê` hotstring family is a third producer, not a second InputHook. Vowels use explicit case-sensitive/case-conform registrations. Other circumflex entries use contextual word-start/time checks, with the configured magic key excluded by non-regex membership. Deliberate exceptions leave `êe`/`êE` to rolls and `êt`/`êT` typable. Preparation reports the proposed edit without output; actual output returns a successful buffer transaction only when `SendNewResult` succeeds. These deliberate rules are not missing general composition support.

## Intentional differences, duplicates, and unresolved policy

- Builtin fixed tables preserve documented Ergopti-specific compatibility deviations: numeric symbol mappings, the historical star mapping, Greek glyph choices/suppressions, R mappings and angle brackets, and subscript/superscript overrides. These are explicit golden compatibility overlays, distinct from registry source action tables.
- Builtin two-second base flush and registry indefinite pending state are different implementation contracts. A common cross-platform expiry requirement is not established.
- Registry native-character tables require a unique pending result for a neutral printable character. Ambiguous custom layouts are rejected rather than arbitrarily choosing a state result. The shared role checked all six shipped registry layouts and found no ambiguity; this role does not count a shipped defect from that conditional restriction.
- `DeadKey` forwards named controls using the bare name and loses original modifier identity. This is already included in **OSW-001** from the previous one-shot audit; no new finding is counted here.
- Registry pending state survives pause/resume and category/navigation gating unless another explicit reset occurs. Prior **OI-001** already documents the pause path as a policy hypothesis. No common discard-on-pause/focus rule has been established; the legacy InputHook transaction, by contrast, is stopped through lifecycle/SIHO ownership.
- Reset observers register plain `~SC...` names rather than wildcard/modifier variants. Whether Shift+Tab/Ctrl+Arrow should cancel, and whether the installed AHK variants receive them, needs a real Windows matching/focus test. This is retained as a native/policy gap, not counted as a second proven defect.
- Registry state advances before output. Production `SendNewResult` catches and logs send exceptions and avoids ring advancement; legacy composition also ignores the returned boolean. A test-only hook can refuse output, but that alone does not prove a silent production failure or a required state-retry policy. No new finding is counted.
- Windows legacy/registry unmapped fallback preserves a terminator/base plus the continuation. Linux CANCELLED behavior intentionally discards the earlier accent in its existing source contract; cross-OS fallback semantics belong in parity documentation and require product policy if uniformity is desired.

## Evidence and limits

`coverage.json` inventories bounded producer, transition, lifecycle, ownership, and test paths. `source-receipts.json` binds 33 actual source/test/data files to both pinned Git content and current disk bytes. `source-contract.py` is a lexical witness with controls for missing/empty/duplicated/unclosed bodies, strings, line/block comments, and braces. It verifies source relationships; it is neither an AHK parser nor a behavior test. `data-probe.lua` runs original parser/policy owners and emits only the decisive shipped-data witness. `sweeps.json` retains two final dry runs after the finding with exact commands, exit statuses and output hashes. No Windows test suite, native hook, SendEvent, native replay, or foreground delivery was executed. The false-green scan is advisory and does not establish behavioral completeness.
