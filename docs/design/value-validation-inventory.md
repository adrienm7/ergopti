# User-entered value inventory and validation contract

Inventory of every input box, editor field and stored `config.toml`, `tap_hold.toml`,
`hotstrings_config.toml` and `personal_info.toml` value the three drivers and the web
pages read, taken on 2026-11-13 for the TODO item « One validation contract for every
user-entered value ». It records what each place checks today, so the migration to the
shared schema can be followed family by family. Paths are relative to
`static/ergopti_plus/` (`W/` = `windows/`, `M/` = `macos/`, `L/` = `linux/`,
`S/` = `_shared/`); line numbers are those of `dev` at 2026-11-13 22:30 Paris.

## The contract

Each setting is declared once in `S/settings/data/value_schema/value_schema.json`:
its file, type (`integer`, `decimal`, `boolean`, `enum`, `string`, `path`), `min`,
`max` (inclusive), whether decimals are allowed (`integer` refuses them), allowed
values of an enum, `max_length` of a string, and its special values (such as the
one-shot `0` = no time limit), each with the i18n key of its label. The checker
exists three times with one behaviour, pinned by
`S/settings/data/value_schema/value_check_vectors.json`:

| Runtime            | Checker                                                                      | Vector replay                                               |
| ------------------ | ---------------------------------------------------------------------------- | ----------------------------------------------------------- |
| JS (web pages)     | `S/settings/data/value_schema/value_check.js`                                | `tools/test/test-value-schema.cjs`                          |
| Lua (macOS, Linux) | `S/settings/engine/value_check.lua`                                          | `S/tests/lua/value_check_contract.lua` from both Lua suites |
| AHK (Windows)      | `W/infra/value_check.ahk` with the generated `W/_generated/value_schema.ahk` | `W/tests/unit/infra/test_value_check_vectors.ahk`           |

It is applied at three places:

1. **Entry** (`parse_entry`): the typed text is refused with the localized
   `dialog.value_check.<reason>` message, which names the allowed range and the special
   values, and the prompt is asked again or cancelled; nothing is written.
2. **Load** (`check_value`): a bad stored value is reported once (the shared outdated
   entry report on the Lua drivers, the loader warning on Windows), logged, and the
   default applies; never silently.
3. **Consuming boundary** (`require_value`): the value is checked again where it reaches
   the engine (setter, timer, InputHook, Karabiner rule, evdev engine); a value altered
   after load fails fast with an error log line instead of crashing or arming a wrong
   timer.

Refusal reasons are a closed list: `empty`, `wrong_type`, `not_finite`, `not_integer`,
`below_minimum`, `above_maximum`, `not_allowed`, `too_long`.

## Gaps found, to close family by family

- Silent refusals at entry (tap-hold delays, one-shot timeout, chord delay, hotstrings
  window delay and priority, layer `repeat_count`, onboarding trigger character).
- Refusal messages that never name the range (`menu.llm.invalid_input`,
  `numeric_prompt.out_of_range`, `menu.hotstrings.delay_invalid_body`) and prompts that
  contradict the code (temperature 0–1 shown, 0–2 accepted on Windows, 0–1.3 on Linux,
  0–1 on macOS; « blank resets » refused).
- Silent clamping or truncation (hotstring editor priority, hotstrings window negative
  delay, updater `Integer()`, Linux one-shot `math.floor`).
- Load checks that are type-only or silent (`expansion_delay` negative, hotstrings_config
  leaves dropped without a log, unknown enums falling back without a log).
- Boundaries without an upper bound (one-shot timeout, lone tap window, chord threshold)
  or with a hidden substitute value (one-shot ≤ 0 → 2 s).
- Bounds duplicated in each driver instead of read from one source (LLM `IntegerRanges`,
  Linux `BOUNDS`, macOS dialog bounds, priority 0–100 in four places).
