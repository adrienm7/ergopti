## WPMW-001 — Delayed boot Show overrides a newer disable

Severity **medium**, confidence **high**; G2, G3. Owners: `windows/ErgoptiPlus.ahk` deferred post-ready tasks; `windows/ui/wpm/wpm_display.ahk` Show/Hide; `windows/ui/wpm/wpm_config.ahk` Toggle/visible commit; `windows/ui/menu/menu_metrics_actions.ahk` `_ToggleWpmWidget`.

Reachable projected reproduction: start with metrics enabled and widget visibility true. The complete configured tray exists before readiness; `_TrayStartupCommands.NotifyReady()` releases queued actions and `_TrayStartupClick.NotifyReady()` releases navigation. Boot then arms the named one-shot `SetTimer(WPMWidget_Show, -2500)`. During that 2.5-second post-ready interval, open Metrics and disable the widget, successfully committing false. The row is an enabled public checkbox when metrics is enabled. Let the one-shot run after leaving the menu, then type at least two characters. Hide stops only Tick/MouseWatch. The retained Show callback sets `WPMWidget.visible := true`, rebuilds/positions if needed, resets rolling state, and re-arms both recurring timers. Subsequent typing reveals the widget although the last preference commit was false.

This is not a request to run a function before availability: menu publication precedes ready, the delay is explicitly after ready, and the user action is the registered checkbox. Native menus can delay AHK timers while open; that makes a callback run later, not cancel it. A healthy control is boot with no intervening disable; a disable after the one-shot completed also stays disabled. A refused preference write correctly returns before Hide and therefore is not this defect.

Root: the same unrestricted Show function serves both current user activation and an unfenced boot completion. Neither Hide nor the committed false publication revokes the pending boot timer. There is no generation/current-preference check at its execution. It logs a successful Show, so the stale transition has no failure diagnostic. The menu may retain the false check until its next rebuild; a later full save projects the erroneously restored live `visible` field into config, so this can also overwrite the successful disable durably. Reload initially honors false unless another full save intervened.

Regression direction: a genuine isolated AHK startup fixture must receive the actual configured tray disable before the armed one-shot fires, then observe native HWND/timer/state and persisted config after the deadline. Include no-action healthy, refused-write, disable-after-show and repeated activation controls. Revoke/fence the boot obligation; do not make ordinary Toggle->Show refuse its own newly committed true.

Decisive retained proof: `proofs/source-contract.mjs`, `proofs/source-contract.log` section WPMW-001. This is source proof only.

## WPMW-002 — Graph reports success after native bitmap upload refuses

Severity **medium**, confidence **high**; G2. Owners: `windows/ui/wpm/wpm_widget.ahk` `WPMWidget_RenderGraph`, `windows/ui/wpm/wpm_display.ahk` Tick/PrewarmGraph, `windows/adapters/graphics_renderer.ahk` `_GRDrawBitmapRun` and native facade.

Reachable projected reproduction: enable graph and colors, type so the graph has one accepted opaque frame, then let the next graph tick reach a native `UpdateLayeredWindow` returning zero (or a documented zero from GetScreenDC/CreateMemoryDC/CreateDIBSection/SelectObject/GetWindowRect). With upload refused, the OS retains the previous uploaded bitmap; on first frame there is no accepted opaque bitmap to reveal. The adapter returns false after settling its exact GDI cleanup receipt. `WPMWidget_RenderGraph` ignores that result and returns true. Tick executes `GR_Show`, advances its last WPM, and never enters the error/rebuild catch. Persistent refusal therefore produces stale or blank graph output while the widget preference remains enabled. A transient refusal may self-recover on the next successful 200 ms tick; this does not acknowledge the refused frame.

The native facade converts zero to false; it does not throw. Reviewed all lower adapter functions: `_GRDrawBitmapRun`, `_GRBitmapRelease`, `_GRBitmapSettle`, `_GRBitmapDrainDebt`, and `_GRBitmapNative`; none logs, notifies, raises a refusal, or invokes an observer on this false path. The global AHK exception handler has no exception to receive. GDI+ frame status failures are a separate path: they are converted to thrown errors and the WPM tick logs/rebuilds. Startup acquisition also logs failures. These loud controls do not backstop bitmap false. Prewarm has the same receipt loss and logs "Graph window pre-warmed" after a false bitmap return.

Root: a Boolean acknowledgment is dropped at the actual WPM business owner, not a missing WPM-specific log after an already loud lower failure. Cleanup debt remains owned, which is correct and should be preserved. If bitmap cleanup debt cannot drain, later draws also return false and the lost receipt keeps hiding the blocked frame progression.

Regression direction: execute the real AHK RenderGraph->GR_DrawBitmap->\_GRDrawBitmapRun with faithful native facade seams, successful surface geometry/GDI+ frame, and healthy, native-zero-upload, zero-allocation, retained-cleanup-debt and throw controls. Assert a refused acknowledgment reaches the caller and that stale/blank native content is not represented as successful presentation; assert error/refusal visibility and a successful retry. Do not replace the business owner with a JS model, or merely assert the draw callback returned.

Decisive retained proof: `proofs/source-contract.mjs`, `proofs/source-contract.log` section WPMW-002. Native failure occurrence/visual output remains unmeasured.

## Refutations and failure backstops

- Old invisible-surface region targeting is guarded through an owned positive integer HWND, and only proven closed/foreign handles are debug-skipped; a still-owned failure propagates. It is not an unhandled hidden-window search defect at this SHA.
- Hidden startup calls `Show("Hide ...")` without NoActivate. Graph prewarm uploads transparent zero bitmap and hides; Show resets old rolling state. It does not intentionally reveal boot typing. Native visibility still needs replay.
- Graph and compact thrown-render catch branches log and rebuild AND reapply hidden geometry; the historical zero-sized rebuild issue is fixed in source.
- Native drag admission posts before `_dragging=true`, so a rejected PostMessage cannot permanently latch ownership; DragEnd stores compact anchor, restores geometry after refused storage. Existing Windows paired storage durability finding WCF is deliberately excluded, not refuted or duplicated.
- Preference toggles/close persist before applying visible effect, and close returns true to suppress AHK's default hide after refused persistence. Writer refusal is surfaced by ConfigCommitBuilt/ConfigReportPersistenceFailure. No silent refusal finding is claimed on those paths.
- GDI+ acquire and frame resources transfer ownership before status checks, release in reverse order, retain cleanup debt, and gate reentrant init/frame. These native lifecycle paths were read, not executed. Process lifetime GDI+ token is explicit ownership intent.
- Category color resolver is asked before fallback cache on every read; user category overrides are not shadowed by an early empty cache. Current tests meaningfully assert category color values. Section-specific tooltip parity is not established by that coverage.
- Registered source-scan tests prove spelling/guard placement, not all native effects. Existing native-owner tests were inspected and not counted as executed. Root's `false-greens.txt` at this snapshot reports zero mechanical patterns, which does not prove owner boundary coverage.

Two final whole-scope dry source sweeps found no new root after the above; see `proofs/dry-sweeps.md` and `proofs/dry-receipts.json`. Performance, lag and memory are unmeasured. No live configs, clipboard, logs or services were read. WPM scope is complete; no next module begun.
