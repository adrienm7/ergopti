# macOS wrap symbols audit

Audited commit: `7aecd9a25b35efdcff68898919506dc2f6fd02d0`, 2026-11-05. Scope: wrap-on-type, built-in/custom pair catalogue, native menu settings and publication, parameterized wrap action, Text clipboard/synthetic/timer owners, selection capture and lifecycle joins. Three confirmed medium-severity roots. No production or registered test changes. No native Darwin desktop or live clipboard was used.

The evidence runs genuine Lua 5.4 and actual production owners over native seams. Hammerspoon 1.1.1 source contracts were independently fetched and retained with hashes. The multi-item probe additionally executes the exact upstream Lua pasteboard wrappers. A fake native input recorder is not native desktop receiving proof.

## Confirmed findings

### WSM-001 — Checked French guillemet pair has no matching trigger on shipped layouts

Severity medium; confidence high; G2; additional property: truthful menu state. With wrap-on-type enabled and a readable selection, keep the built-in `«  …  »` pair enabled and type either guillemet. The native eventtap passes the key through without reading the selection or wrapping it.

The catalogue stores delimiters `"« "` and `" »"` with ASCII space U+0020. `Text.WRAP_PAIRS` and `build_active_wrap_pairs` use these complete strings as trigger keys. `system.bind_wrap_text_if_selected` looks up `pairs_tbl[e:getCharacters()]` without trigger normalization. The shipped Ergopti and Ergopti+ `.keylayout` outputs are `«`+U+00A0 and U+00A0+`»`; Bépo and Ergol output bare guillemets. Neither form matches the catalogue keys. Native `getCharacters()` is a direct NSEvent characters getter; it does not trim or convert NBSP to ASCII space.

Actual menu proof: the guillemet row remains checked, while the live getter has no bare/NBSP entry. Actual eventtap → Text/broker proof: bare `«`, bare `»`, `«`+NBSP and NBSP+`»` each return passthrough, AX reads=0, writes=0 and pastes=0. A full ASCII-space event `"« "` is a positive control: the same owner consumes it, pastes `« é雪\nline »`, then restores original text+HTML. The parameterized action's parser deliberately accepts bare `«` and returns spaced delimiters; that alternate route works and is an explicit backstop, not a refutation of the physical-symbol failure. A single-character custom pair is another possible workaround.

Root owners: `macos/modules/shortcuts/actions/text.lua:665–674,1930–1951`, `macos/modules/shortcuts/actions/system.lua:1292–1331`; shared `modules/wrap_symbols/wrap_symbols.json` quote group and `static/layouts/registry/{ergopti,ergopti_plus}/*.keylayout:524–525`. No error occurs: a missing lookup is ordinary passthrough, so native acquisition and clipboard cleanup guards cannot diagnose it. The catalogue/menu promise that either endpoint wraps is misleading for this pair.

Regression direction: use actual checked menu state and actual native eventtap with the Unicode outputs of supported layout sources, require guillemet wrapping while preserving the intended delimiter spacing, and keep no-selection/raw-key passthrough controls. Do not solve it by altering unrelated layout spacing or weakening consumed-key guards.

Evidence: `probes/menu.lua`, `probes/menu.log`, `probes/trigger.lua`, `probes/trigger.log`, `probes/layout-guillemet-source.json`, `probes/native-event-contract.txt`, `probes/copied.log`.

### WSM-002 — Wrap restoration silently discards later pasteboard items

Severity medium; confidence high; G2; additional property: clipboard integrity. Start with two pasteboard items: item 1 contains text+HTML, item 2 contains a unique PNG representation. Wrap a readable selection with `(` and `)`. Text accepts, pastes the wrapped selection and reports successful restoration, but only item 1's representations survive. The PNG is lost. No second borrower, external clipboard write, focus change, timer refusal or concurrent callback is required.

`capture_text_clipboard` treats `hs.pasteboard.readAllData()` as a complete snapshot. In the shipped Hammerspoon 1.1.1 host, this wrapper explicitly reads **only the first pasteboard item**, iterating `contentTypes()`, whose native implementation selects `[pasteboardItems objectAtIndex:0]`. `restore_text_clipboard` calls `writeAllData(snapshot)`, which first clears the entire pasteboard and writes only those saved representations. Stable changeCount, native true acknowledgments, native paste grace and exact transaction cleanup all succeed while the incomplete snapshot loses later item data. `allContentTypes()` can expose the multi-item shape but is never consulted by this owner.

The retained probe executes the actual Text, SyntheticInput and TimerScheduler owners **and the exact downloaded upstream `pasteboard.lua` readAllData/writeAllData wrappers**, over item-aware primitive seams derived from native source. Single-item text+HTML control survives intact; two-item reproduction finishes with no later PNG, zero item-count probes, and zero error diagnostics. It also reproduces through the copy-based `wrap_copied_selection` route with no selection: no paste occurs, yet the original two-item clipboard is reduced to the first item's data during cleanup. Its matching single-item/no-selection control preserves the original first item's types.

Root source: `macos/modules/shortcuts/actions/text.lua:482–503` and `320–361`, used by physical `wrap_selection` and copied-selection `do_transform`. This is separate from prior MCP-001 (Apps overwriting a newer generation), MCP-002 (independent families borrowing a temporary payload), and MCP-003 (delayed transforms crossing destination focus). Each of those may have other effects; none is required here. The generic `adapters.clipboard.save` has the same first-item assumption, but no additional finding or unexecuted borrower claim is counted.

Regression direction: execute the actual upstream wrapper with an item-aware native seam, including first-item text+HTML and a different representation solely in item 2. Require exact item/representation preservation, or explicit refusal before any mutation when a complete snapshot/restore cannot be provided. Test no-selection cleanup, empty board, failed restore and a foreign generation. Preserve the existing ownership guards. Native Darwin acceptance should additionally cover actual multi-object pasteboards; this audit does not claim that acceptance.

Evidence: `probes/multi-item.lua`, `probes/multi-item.log`, `probes/upstream-pasteboard-1.1.1.lua`, `probes/upstream-pasteboard-provenance.txt`, `probes/native-pasteboard-contract.txt`.

### WSM-003 — Disabling lower double quotes removes the still-enabled curly opener

Severity medium; confidence high; G2; additional property: truthful menu state. Leave `“ … ”` enabled, then disable only `„ … “` in the quote group. The refreshed menu still checks `“ … ”`, but typing `“` no longer wraps a readable selection. Typing its closing endpoint `”` still wraps with `“ … ”`.

The shared catalogue contains both pairs in that order. At module load, Text flattens both endpoints into a single table; the latter pair's closing `“` overwrites the former pair's opening `“`. Later `build_active_wrap_pairs` filters the already-flattened map by the surviving pair's left endpoint. Disabling `„` removes the only retained `“` key. The earlier enabled opener was already discarded and is never reconsidered. Correct preference persistence cannot restore the lost mapping.

Actual menu proof invokes the real per-pair action and WrapMutation owner, checks refused-save rollback, then accepts the save. On refresh, `“ … ”` remains checked and `„ … “` is unchecked, but the live getter's `“` key is nil. The actual eventtap proof then passes `“` through with AX reads=0/pastes=0, whereas `”` still pastes `“é雪\nline”` and restores rich clipboard state. Both-enabled default `“` produces `„é雪\nline“`; which pair should win that ambiguous default is unknown intent and is not itself the finding. The confirmed failure is removal of a still-enabled opener when the competing pair is disabled.

Root: `macos/modules/shortcuts/actions/text.lua:665–674,1930–1941`; menu row truth is independently keyed by opening delimiter in `ui/menu/menu_shortcuts.lua:346–361`. No exceptions or native failure occur. The alternate closing endpoint or parameterized wrap action are backstops. Regression direction: filter enabled catalogue pairs before collision resolution, define/document overlap precedence, and test each colliding pair disabled independently through actual menu → active getter → eventtap effects. Do not merely assert that a table exists.

Evidence: `probes/menu.lua`, `probes/menu.log`, `probes/trigger.lua`, `probes/trigger.log`; the shared role independently confirmed the per-left default-enabled policy and recorded sibling Linux effects without duplicating this macOS finding.

## Coverage, refutations and intentional differences

- **Configuration and first key:** `ui/menu/init.lua:997–1007` installs the WrapMutation-aware live getter during boot, before lazy menu construction. `Bindings.get_live_wrap_pairs` is stable indirection; menu rebuilds replace the getter without tearing down the native owner. Shared WrapPreferences owns optional `[shortcuts.wrap_symbols]` state/custom data and preserves source shapes, metadata and unknown neighbors. The namespace's macOS-only persistence declaration is explicit; it is not a missing Linux/Windows implementation finding. Exact-file publication/load and eager-boot registered cases were examined and executed.
- **Menu changes:** actual `menu_shortcuts.build`, actual shared template rows and WrapMutation are exercised in `menu.lua`. The surrounding provider selection/native renderer and preference writer acknowledgment are seams. Refused ACK leaves the old live input view and state in place; successful ACK publishes the candidate. Custom add requires exactly one valid Unicode scalar; empty closing input means symmetric. Custom deletion and restore are source-reviewed and registered tests exercise source-preserving round trips. Restore clears custom pairs and per-built-in state; defaults mean built-ins enabled. Global “Uncheck all” only changes built-in checkboxes; custom entries have delete, not checkboxes, so no extra global-control failure is asserted.
- **Physical entry:** actual native tap factory and synthetic provenance classification execute in `trigger.lua`. Cmd/Ctrl combinations pass before AX. Alt remains allowed for Ergopti symbol layers. Unmatched/empty characters, disabled pairs, nil/empty AX selection, rejected clipboard write and an admission guard returning false all pass through. A diagnostic after rejection is not silent success. Actual all-type single-item restore is observed; a refused first restoration retries and retains ownership. Deleted native tap callbacks do not mutate again.
- **Selection and alternate action:** physical symbols use `read_ax_selection`, so an app without AXSelectedText gets normal typing. The explicit `wrap_selection` action resolves a binding's stored catalogue/custom parameter and calls copy-based `wrap_copied_selection` under its parent; no selection produces no paste. This is an intentional access-path difference, not a missing Electron guarantee. `copied.lua` executes the actual parser/Text/broker path for `**|**` and observes `**SELECTED WORDS**` plus text+HTML restoration. Unicode/newlines in selection survive the physical Text path; native grapheme/caret integration was not measured.
- **Consumed-key and completion:** wrap returns true only after restore timer admission, clipboard payload publication and accepted SyntheticInput emit/seal. Exact broker completion establishes the final host paste-grace deadline; queue admission alone is not native output. Snapshot/write/timer/producer refusal rolls back or retains cleanup debt. A failed action may intentionally pass the original physical key; do not relabel fallback typing as a new failure. Actual broker registered tests retain the wrapped payload across delayed handoff, pause, terminal/key-up handling and timer false/nil/throw cleanup debt.
- **Lifecycle and races:** Text scopes are parent-owned and serialize their four slots plus sibling Text parents. Pause advances generation before canceling; timers retain exact handles and mark discard before cleanup; stale/double timer delivery is fenced; restoration debt blocks successors. Bindings inventories Text, Apps and raw tap children; System's exact tap owner fences a retired callback. Source-reviewed ownership does not establish cross-family clipboard serialization: prior MCP-002 already owns that gap. No duplicate-init or reload regression was confirmed here.
- **Keymap/security/ignore boundary:** wrap is a separate shortcuts tap consuming native layout characters, not a Lua keymap remap action. Exact owned/unreadable provenance and older returned-event fences are handled before selection reads; native synthetic echoes do not become wrap commands. The binding admission guard reflects shortcut delivery/pause. The Text owner does not implement a general app-ignore/private-field filter. Keymap ignore state is a different owner; no unsupported claim that it should disable all user-configured shortcuts is made. Secure Input/AX availability, disabled native taps, TCC permissions and actual protected-field behavior require Darwin qualification. Existing nil-AX fallthrough and explicit pause guards remain preserved.
- **Stale menu hypothesis:** index-captured custom delete callbacks could be interesting under successor changes, but no native reachable duplicate/stale selection delivery was established beyond current mutation ownership; not confirmed. No artificial reentrant menu callback is counted as a native user action. The original hypothesis that disabling `„` would restore the enabled `“` opener was rejected by actual execution and led to WSM-003.
- **Prior audit search:** reviewed TODO, routed macOS clipboard/wrap/timer/synthetic memory, previous 2026-11-04 flows macOS clipboard report/findings and prior wrap tests. No earlier multi-item/guillemet-trigger/collision root was located in repository audits or memory. Cross-platform shared role coordinates catalogue/policy findings; Windows native input paths remain the Windows role's evidence, not this report's execution claim.
