# Owned remap source validation

The fixed source factory composes the owned Console, Core and CLI routes with the genuine pinned source. The full-tree builder retains the pristine input, materializes its complete tracked image and canonical overlays in a separate owner, and runs the real version generator before native compilation. Compilation is unsigned; installation, signing, native authentication and capture stay unqualified.

Run portable preparation and closed receipt controls from the repository root:

```bash
python3 tools/build/remap_runtime_build_test.py
PYTHONOPTIMIZE=1 python3 tools/build/remap_runtime_build_test.py
```

The existing macOS XCTest target discovers `HS274OwnedRuntimeCompilationTests`. Its portable41 case uses the SDK30/35/10 guardian. Its native case waits for an actual fresh baseline with candidate:null to finish and retire before invoking the fixed owned builder in another empty owner. Each compilation keeps its own native300/guardian305/cleanup10 bounds. Closed output and receipt metadata never replace native process completion, source currentness or actual dual-architecture products.

Run the real callback retirement/source controls against a genuine pristine checkout at commit9312593e1a3bf72b94c63c524ebabe2637442e8a with its declared recursive submodule pins. Use the checkout retained by the source owner, before any version or instrumentation changes:

```bash
python3 tools/build/remap_runtime_auth_transport_test.py --source-root /absolute/pristine/source
PYTHONOPTIMIZE=1 python3 tools/build/remap_runtime_auth_transport_test.py --source-root /absolute/pristine/source
```

These21 controls execute genuine pqrs dispatcher/Asio/threads, retained channel debt, stored callback destruction and actual filesystem source transforms. Native identity, signature, UID, watch and serial MAIN leaves are explicitly modeled. They are not native authentication or physical input proof. The new Swift compilation case currently does not invoke these21 controls. They require a separate source-control registration; portable41 is not a replacement and SDK30 is not enough for the complete C++ control run. Do not silently skip them or enlarge that SDK budget.

The independent original26 role/UID corpus and additive22 hs274 operation corpus remain literal checked-in fixtures. They are not derived from the new policy. Run each against the current combined policy, using separate absent output directories:

```bash
python3 tools/build/remap_runtime_auth_test.py tools/build/remap_runtime_auth_policy.hpp tools/build/fixtures/remap_runtime_auth_policy26.json /absolute/absent/original26-result
python3 tools/build/remap_runtime_auth_hs274_test.py tools/build/remap_runtime_auth_policy.hpp tools/build/fixtures/remap_runtime_auth_hs27422.json /absolute/absent/hs27422-result
```

Each policy runner compiles and executes its frozen expectations at C++O0 and O2. Policy results alone give no Security/socket/capture qualification. Original26 and additive22 are separate coverage. Preserve the old corpus and its expectations when updating source.

A dependency-only check can inspect the exact released source dependencies without source/build authority:

```bash
python3 tools/build/remap_runtime_build.py /absolute/repository /absolute/empty/owner --ready --budget 300
```

Actual macOS compilation uses the same fixed entrypoint and reviewed finite native phase owner:

```bash
python3 tools/build/remap_runtime_build.py /absolute/repository /absolute/empty/owner --compile-owned --budget 300
```

The optional `--upstream /absolute/pristine/source` consumes an explicitly retained genuine pristine input. It does not accept modified staging as original source. Without it the native entry performs its own fresh fixed acquisition. Generated upstream trees, version files, products, bytecode and diagnostic receipts belong in private build owners, not committed source. Production enablement remains separate from this compilation evidence.
