# Adversarial audit — Windows AHK driver — 2026-08-08

## 1. Executive summary

### Verdict

The Windows driver is not yet able to guarantee `G1`–`G5` for every reachable user action. This pass reports **34 findings: 1 critical, 17 high, 14 medium, and 2 low**. The most fragile boundaries are UI Automation on AutoHotkey's single thread, failure propagation from output and persistence adapters, keylogger privacy/projection integrity, and state that crosses `Suspend`, asynchronous callbacks, or the 32-bit `A_TickCount` rollover.

The suite being green is not a safety proof here. Several tests assert only that a token is present, cover one sibling while the same invariant has several consumers, or actively pin the unsafe implementation. The strongest examples are `tests/meta/test_uia_poll_segment_bounded.ahk`, `tests/meta/test_persist_result_not_discarded.ahk`, `tests/meta/test_keylogger_prefetch_worker.ahk`, `tests/meta/test_tooltip_expiry_anchored_at_request.ahk`, and `tests/meta/test_logger_pairing.ahk`.

## 2. Findings

Findings are ordered by severity. Confidence is separate from severity. “Measured” means re-derived from the cited artifact; “code-confirmed” means the reachable behavior follows from source and a deterministic seam but was not forced against the maintainer's live desktop.

### `AHK-01` — asynchronous password detection fails open

- **Severity:** Critical
- **Confidence:** Code-confirmed; real UIA failure observed; sensitive capture was deliberately not attempted
- **Location:** `modules/keylogger/keylogger_password.ahk:57-62,123-177,182-231`; misleading backstop at `infra/metrics/metrics_filters.ahk:281-300`
- **Guarantee:** `G2` and privacy invariant
- **Reproduction:** Focus a Chromium/Electron password field whose control is initially unknown; make UIA fail, for example by crossing integrity levels or using an unresponsive provider; type one character to schedule `KL_AsyncPasswordDetect`; continue typing after its callback. The first unknown verdict is seeded secure, but the callback commits `false`, so subsequent text is eligible for persistence.
- **Root cause / silence:** `KL_DetectPasswordFor()` catches UIA failure and returns the same `false` used for a conclusive “not password” result. `KL_AsyncPasswordDetect()` then unconditionally publishes that boolean. The fail-closed `true` in the outer metrics filter catches only thrown failures, but the detector swallowed the exception first. The real line `ErgoptiPlus_2026-08-07.log:38591` records `UIA password probe failed` at the same timestamp as a failed selection probe, proving the unknown branch is reachable.
- **Contradiction search:** `tests/meta/test_metrics_filter_secure_field_fails_closed.ahk` checks the caller's seed/catch but not the detector's swallowed error; `tests/meta/test_secure_field_probes_focused_element.ahk` checks target selection; `tests/meta/test_async_password_detect_suspend_guard.ahk` checks lifecycle only.
- **Fix:** Return a tri-state `{secure, ordinary, unknown}` or propagate probe errors. Only a conclusive ordinary verdict may relax the cache; `unknown` must retain `true`. Log the failure without field content.
- **Regression test:** Add `tests/unit/test_keylogger_password_fail_closed.ahk`. Stub the UIA adapter to throw, execute the real async completion, and assert `KLPasswordCache.last_val == true`, no typing row is queued, and a later conclusive ordinary result can still clear the cache.

### `AHK-02` — same-thread UIA polling has no enforceable 60 ms bound

- **Severity:** High
- **Confidence:** Measured and code-confirmed
- **Location:** `modules/keymap/layout.ahk:588-844`
- **Guarantee:** `G4`
- **Reproduction:** Focus an application with a slow or failing UIA provider, remain physically idle long enough to arm the selection poll, then type while `GetFocusedElement`, `GetPattern`, `GetSelection`, or `GetText` is blocked. AutoHotkey services the `SetTimer` callback and keyboard hook on the same thread.
- **Root cause / silence:** The 60 ms budget is checked only between synchronous cross-process COM calls. It cannot interrupt the call already in progress. The poll is described as background work, so structural tests accept it even though AHK has no background execution thread.
- **Evidence:** Retained logs contain 321,731 slow `UIA.SelectionPoll` samples, maximum `681.79 ms`, threshold-censored mean `15.338 ms`, and 378 samples above 100 ms. `ErgoptiPlus_2026-07-31.log:131594` is the retained maximum. Current-code-era examples include `ErgoptiPlus_2026-08-06.log:3316` at `182.58 ms` after its own budget warning and `ErgoptiPlus_2026-08-07.log:38593` at `253.94 ms`.
- **Contradiction search:** `tests/meta/test_uia_selection_background_poll.ahk` acknowledges the single thread but treats the idle gate as sufficient. `tests/meta/test_uia_poll_segment_bounded.ahk` and `tests/meta/test_uia_probe_bounded.ahk` assert post-call checks, not an enforceable bound.
- **Fix:** Move UIA to an out-of-process worker with IPC and a killable deadline, or use UIA events whose callback only publishes a precomputed snapshot. Bind every snapshot to HWND, control, and input generation.
- **Regression test:** Add a fake worker that stalls beyond 60 ms and assert the keyboard dispatcher completes within 5 ms, the worker is canceled, and no stale selection is published.

### `AHK-03` — tap-hold synthetic-key ownership and lifecycle are incomplete

- **Severity:** High
- **Confidence:** Code-confirmed with deterministic failure seams
- **Location:** `platform/remap/constants.ahk:345-398`; sender behavior at `adapters/text_sender.ahk:186-219,472-510`; suspend cleanup `infra/lifecycle.ahk:290-293`; missing shutdown parity `infra/lifecycle.ahk:410-417`
- **Guarantee:** `G1`, `G2`, `G3`
- **Reproduction A:** Configure a tap-hold to own `Ctrl+Shift`; make `{LCtrl Down}` succeed and `{LShift Down}` fail through the sender seam; then make an `Up` fail during release or suspend cleanup. The caller reports/records both keys, the screen owns only part of the combo, and failed release ownership is erased, leaving a modifier logically down with no retry owner.
- **Reproduction B:** Hold a modifier tap-hold until its synthetic Down is active, then click tray Quit before releasing the physical key. The interrupted `KeyWait` never reaches its finalizer; `Ergopti_OnShutdown()` omits `TapHoldReleaseSyntheticKeys()`, and no successor process exists to release the OS modifier.
- **Root cause / silence:** Down counters are incremented before injection succeeds. Scalar calls bypass `TextPressKey`'s array rollback. Final Up and suspend cleanup delete/clear the ledger before checking the boolean result, while `_TextSenderSendInput` catches the OS exception and returns `false`. Lifecycle parity exists for Suspend but not Shutdown. A suspend callback can also interleave between ledger publication and injection because the same ledger has no short atomic owner.
- **Contradiction search:** `tests/unit/test_text_sender_sendinput_failure.ahk` covers the adapter's direct array path; `tests/unit/test_taphold_synthetic_refcount_combo.ahk` injects only success; `tests/meta/test_tap_hold_suspend_boundary.ahk` and `tests/meta/test_hold_modifier_release_bounded.ahk` are presence checks.
- **Fix:** Build the 0→1 transition as one transactional array send, publish counts only after success, roll back partial downs, and retain failed 1→0 keys as release-pending. Protect only the ledger/send commit window with `Critical`; never include waits or I/O. Call the same bounded cleanup early in Shutdown as well as Suspend.
- **Regression test:** Extend `tests/unit/test_taphold_synthetic_refcount_combo.ahk` with fail-on-second-Down and fail-on-Up vectors. Assert rollback order, false verdict, no fictional counts, and that suspend/shutdown cleanup retains and retries every failed release. A class meta test must require OS-down cleanup parity between Suspend and Shutdown.

### `AHK-04` — hotstring send failures become fictional expansions

- **Severity:** High
- **Confidence:** Code-confirmed with existing sender seams
- **Location:** `infra/hotstrings/hotstring_send.ahk:116-251`; `infra/hotstrings/hotstring_dispatch.ahk:271-289,360-383`; `infra/hotstrings/hotstring_inputhook.ahk:755-785`; `modules/hotstrings/hotstrings_helpers.ahk:124-156`
- **Guarantee:** `G2`, `G5`
- **Reproduction A:** In Windows 11 Notepad, type an end-char hotstring and force `SendInstant()` to return `false`. No replacement lands, but the dispatcher updates the ring, applies `HSE_ApplyExpansion`, resets preview, logs a fire, and returns `true`.
- **Reproduction B:** Select text in a UIA control, force the clipboard write/paste to fail, and type a wrapper. The path erases the typed symbol before ignoring `SendInstant(false)`, resets both buffers, and may leave the selected content unrecoverable.
- **Reproduction C:** Trigger `...` → `…` or an `ê` raw callback while `SendNewResult()` returns `false`. The callback still returns `{Bs, Ins}` and `_HSE_DispatchRawCallback()` applies the effect to its model.
- **Root cause / silence:** A recent adapter hardening made the send primitives return meaningful booleans, but stateful consumers retained fire-and-forget assumptions. The catches are inside the sender, so callers see no exception.
- **Contradiction search:** `tests/meta/test_wrap_selection_clip_fallback.ahk` covers the correct sibling in `modules/keymap/layout.ahk:916-919`, not the UIA/hotstring paths. Existing atomicity tests assert that `SendInstant` appears but do not inject `false`.
- **Fix:** Make output, ring update, engine mutation, metric, and preview commit one status-bearing transaction. Do not erase selection/symbol state until the clipboard payload is ready. Raw callbacks must return `{ok, Bs, Ins}` and describe only bytes proven to reach the screen.
- **Regression test:** Add `tests/unit/test_hse_send_failure_transaction.ahk`. Fail each send stage independently and assert a false fire verdict, no ring/engine/preview mutation beyond the actual screen effect, no fire metric, and a lossless UIA fallback.

### `AHK-05` — raw LLM Tab acceptance bypasses focus and modifier policy

- **Severity:** High
- **Confidence:** Code-confirmed and reachable
- **Location:** raw primitive `ui/tooltip/tooltip_llm.ahk:177-192`; all-keys hook `infra/hotstrings/hotstring_inputhook.ahk:1024-1118`; bridge caller `modules/keymap/llm_bridge.ahk:230-249`; locally safe sibling `ui/menu/menu_llm/tab_accept.ahk:173-195`
- **Guarantee:** `G2`, `G3`
- **Reproduction:** Show a prediction, then press `Ctrl+Tab`, `Alt+Tab`, `Shift+Tab`, or `Win+Tab`. The InputHook reaches the raw accept primitive although modifier state is not part of its policy. Alternatively show in app A, change focus to app B while the row remains, then use a remapped `LAlt`/`RCtrl` acceptance path; the source-HWND guard exists only in one hotkey wrapper.
- **Root cause / silence:** Visibility/text/reentrance are checked centrally, but source HWND and “bare Tab only” are caller-local. Multiple raw callers bypass the one safe wrapper. Acceptance is logged as success, so normal navigation beside the injected prediction masks the defect.
- **Contradiction search:** `tests/meta/test_llm_menu_tab_source_hwnd.ahk` covers only the wrapper. `tests/meta/test_tab_accept_cancels_timer.ahk` pins a raw bridge call instead of enumerating policy conformance.
- **Fix:** Put source-HWND, current-control generation, and physical modifier validation in one canonical accept function. Fail closed if focus cannot be verified; every acceptance site delegates to it.
- **Regression test:** Add a behavior table for bare Tab versus each modifier chord and stale versus current HWND, then a meta assertion enumerating every production call site. Only bare Tab in the originating control may inject once.

### `AHK-06` — `Ctrl+F` and `Ctrl+L` carry a trigger into another control

- **Severity:** High
- **Confidence:** Code-confirmed
- **Location:** `infra/hotstrings/hotstring_inputhook.ahk:1024-1054`
- **Guarantee:** `G2`, `G5`
- **Reproduction:** Type `ia` in an editor or page; press `Ctrl+F`, or press `Ctrl+L` in a browser; release Ctrl and press Space in the new Find/address control. The engine still ends in `ia` and injects the backspace/replacement burst into a control where `ia` was never typed.
- **Root cause / silence:** The watcher resets for `Ctrl+A/X/V/Z/Y/Backspace` only. It tracks neither focused HWND/control generation nor other chords that relocate focus without `OnChar`. The preview and engine can agree with each other while both describe the old screen context, which still violates the tooltip truth contract.
- **Contradiction search:** `tests/meta/test_prefix_keydown_ctrl_backspace_reset.ahk` pins only the enumerated group. No `Ctrl+F`/`Ctrl+L` context test exists.
- **Fix:** Bind both buffers to a focused-control generation and invalidate on generation change. A chord allow/deny list alone is weaker and must not confuse AltGr's synthetic Ctrl state with a genuine Ctrl chord.
- **Regression test:** Seed `ia`, dispatch `Ctrl+F` and `Ctrl+L`, change the focused-control token, then feed Space. Assert no match, no backspace burst, and no preview row.

- **Location:** tooltip expiry `ui/tooltip/core.ahk:207-220,411,563-617`; tooltip/UIA caches `ui/tooltip/helpers.ahk:817-834`; hotstring gate `infra/hotstrings/hotstring_builder.ahk:267-283`; selection caches `modules/keymap/layout.ahk:562-575,770-804,841-864`; screenshot timers `modules/gestures/screenshots.ahk:100,124,244,269,292,306`; note timer `modules/shortcuts/win.ahk:145,172`; crash fallback `modules/diagnostics/crash_reporter.ahk:396-398`; spotlight `ui/spotlight/init.ahk:183,215`; keylogger clocks including `modules/keylogger/keylogger_hook.ahk:249,261`

### Duplicated prediction-rule search

No independent hotstring predictor remains in current source:

- Candidate specs are resolved through engine-owned by-trigger indexes, not a second linear matcher.
- Winner ordering delegates to the engine comparator `_HSE_Beats`.
- Case/suffix/boundary decisions delegate to `HSE_SuffixMatches`, `_HSE_WordBoundaryAllows`, `_HSE_WordBoundarySet`, and `HotstringsResolve`.
- Personal-information preview/output fields share `_PIPreviewFieldsForTag`.
- `_PrefixBuffer` is a UI projection of the current word tail; it does not decide expansion output.

Accordingly, no “two copies happen to agree today” finding is reported. The remaining `G5` defects are transactional (`AHK-04`), context-generation (`AHK-06`), and timebase (`AHK-07`), not duplicated business rules. Runtime comparison tests remain preferable to structural common-source tests because they exercise the final values.

- This pass now includes local remediation for `AHK-14`, `AHK-30`–`AHK-34`; it does not claim the other findings are fixed. No source test was weakened and no push was performed.
