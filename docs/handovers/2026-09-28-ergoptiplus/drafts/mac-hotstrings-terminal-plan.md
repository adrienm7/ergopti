# Mac hotstrings terminal scope (private work in progress)

Root is the only source writer. All candidates are generated from current root into JSON/string overlays and patches under D:/ewt/\_scratch. Delay8 and its three-path followup are immutable and integrated. No menus are published until terminal scope tests pass.

Selected architecture:

1. Existing runtime inventory (keymap list_groups/get_sections) selects canonical config.toml groups/modules. Manifest owns recommendations; hotstrings.languages owns corpus/manifest name matching. Dynamic section descriptors explicitly identify their feature paths. Missing registered sections are not invented.
2. Existing HotstringsConfig gains an owned delay-reset participant, consumed immediately by the Hotstrings scope. All 38 current manifest timing operations are deletes even for recommended mode; no absent secondary file needs to be created. Existing file contents are backed up, known selected delay fields removed losslessly, unknown fields preserved, and exact original bytes retained for conditional compensation.
3. Existing ScopedPreferences/config_scope_transaction remains the coordinator for config.toml, ordinary-save checkpoint and inverse debt. Its runtime capture/apply/restore ports retain the delay participant; refusal of main publication restores secondary source and runtime, with failed compensation still pending.
4. Actual keymap/preview/native properties require strict snapshot/readback and exact setter acknowledgments. No menu-state shadow may stand in for runtime success. AI preview consent preserved on recommended and revoked on clear. Personal-info uses newly integrated strict native owner.
5. No root writes, native AHK, shared generators or full suites. Private causal tests, real owner APIs, uniquely owned temporary fixture directory.

Open hazards: config_scope_transaction intentionally only publishes its primary file; secondary participant must remain rollback-capable until that publication. All current timing ops delete, so absent secondary path remains absent. If future recommendation adds a non-neutral stored delay, fail explicit contract until absent-file rollback is owned. Existing legacy state.delays must be removed only for exact known runtime keys, preserving unknowns.
