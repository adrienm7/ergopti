# Linux dead-key runtime audit

Audited `f2c3ea43542c985fb20e5f0887976f1c02525341`. One new root: **DKL001**, consumed follow-up keys erase an earlier forwarded Compose prefix from the daemon's semantic reader. Production and registered tests were read-only. This is a runtime capture finding, distinct from Shared's converter/native Compose finding DKS001 and the previously recorded one-shot findings.

## DKL001 — semantic Compose advances before key disposition

Configure the real public tap assignment `number_row_right_1 = "screen_capture"` in a private actual TOML file, with shortcuts active. On the generated Ergopti Plus map, send physical BKSL43 (dead circumflex), Minus12 (assigned tap), then D32 (letter e). The original Reader drains these events through the original Hook. Original TapKeys validates the assignment against the real action catalogue and queues it using original EventLoop.defer. No action executes during this drain.

Hook forwards the first dead key and the final e, suppressing both edges of Minus. An independent original Capture adapter, backed by genuine libxkbcommon, processes only acknowledged raw emissions and produces **ê**. Hook's semantic callback instead produces **e**. The raw ACK trace is `43 down/up, 32 down/up`; the deferred count is one and executed count zero. The mismatch is assertively reproduced in `public-compose.lua` and both final sweeps. This demonstrates divergence in the original owners and native component over controlled transport; it does not certify text received by a desktop application.

`adapters/xkb_capture.lua:1306` feeds Compose while resolving a press, including destructive reset after composed/cancelled status. `adapters/keyboard_hook.lua:1640` resolves that press before invoking onConsume; its consumed branch around1799 then unconditionally resets Compose through `_cancel_capture_compose` at514. This correctly clears a consumed _first_ dead key, but also destroys pending state established by an earlier forwarded press. Simply removing the final reset cannot repair cases where resolution already completed or cancelled a sequence. The fix needs transactional disposition or replay of acknowledged state, with modifier/source currency preserved.

Reachability is supported by unchanged daemon wiring (`ergopti_hotstrings.lua:2047`, `:2287`, `:3105`), the actual TapKeys consumer (`modules/shortcuts/tap_keys.lua:277`) and original defer scheduling (`adapters/event_loop.lua:260`, `:324`, `:476`). Healthy active/context and transport ACK are controlled ports. The full daemon callback priority and idle ordering are source-traced, not a full daemon startup or screenshot execution. The controlled original Hook test entry supplies the real Reader decoded-event path and a controlled modifier broker; no evdev/uinput/Wayland/X11 authority is claimed.

Impact: subsequent hotstring/shortcut/text state can disagree with forwarded native Compose after an assigned tap consumes a continuation. Candidate priority medium. Regression should compare semantic state against an independent native owner fed acknowledged raw events **and emitted text/output history**. Preserve old pending state when the second key is consumed, clear it when the first dead key is consumed, and cover repeated consumed presses, ignored modifiers, public shortcut refusal/inactivity, source changes, and stale capture generations. Tests of only isolated consume/reset operations miss this history-sensitive distinction.

## Counterexamples and limits

The seven public cases cover assigned/unassigned second key, inactive assignment, rejected defer, consumed first dead key, assignment without a prior prefix, and plain composition. The first-dead control explicitly relocates a dead symbol to the public tap position in native data; it is labelled and does not change a Lua body. The decisive assigned-second case uses unchanged converter-produced symbols/types/Compose. System evdev keycodes and complete compatibility are used to assemble a full component keymap. This is explicit component data, not the active desktop keymap.

Ten genuine native Capture controls cover plain composition, unmapped continuation, space termination, repeated dead key, pure peek, explicit cancel, reset, successful reload, and empty/malformed reload refusal retaining the old prefix. Malformed input intentionally logs a native parser diagnostic. Six unchanged registered test files pass **122 cases under Lua 5.4 and 122 under LuaJIT**. They mainly supply controlled adapter backends; they are not native-device evidence. `selected-tests.lua` identifies their exact names. The false-green scanner reports zero against a zero baseline, which does not establish semantic completeness.

Unmapped ordinary fallback is explicit local policy: the cancelled branch preserves the current ordinary character and emits no prior dead-key terminator (the `%e` control). Windows registry fallback differs; native macOS behavior was not measured here. It is neither counted again as DKL001 nor presented as an unavoidable Linux constraint. Shared owns registry/converter semantics, chained Compose, shipped magic-key limitations and DKS001. The previously fixed chained-key/one-shot roots are deduplicated.

Source inspection additionally follows startup refusal without live capture, atomic map candidate publication, Hook restart/reset, successful source reacquisition resetting capture and replaying retained modifier owners, failed acquisition retaining old state, and the separate native row commit path. These are qualified source coverage, not an executed matrix of hotplug, pause/resume, reload and desktop races. Chained registry tables are covered by Shared rather than duplicated here. This module audit is bounded; it is not a proof that all OS features have parity.
