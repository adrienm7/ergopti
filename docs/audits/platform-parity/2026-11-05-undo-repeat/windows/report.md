# Windows: expansion recovery and repeat audit

Audited commit: `b17e47ed3bb92c106703d3e3482b3c2973f5bc1e`.

Two source-confirmed findings: a private programmable expansion can donate its last scalar to a public repeat, and deferred output classifies repeats differently from ordinary output. Neither finding was executed in AutoHotkey or a native Windows editor. The retained Python program authenticates 19 exact files and checks 18 lexical relationships; it does not interpret AHK, simulate its runtime or certify desktop receipt. There is no G4 measurement. Only synthetic example strings are used; no user files, clipboard, secrets, logs, processes or keyboard were accessed.

## Owners and public behavior

`infra/hotstrings/hotstring_inputhook.ahk:_OnPrefixChar` admits a physical completed scalar under the current focus/lifecycle/generation receipt, rejects pause, feeds the registry, then tries personal multi-field combinations, programmable suffixes and finally `HSE_TryRepeatKey`. A registered mapping that exists but whose dispatch declines does not fall through into a doubling. These precedence rules matter: a repeat is a last fallback, rather than a low-priority registration.

`infra/hotstrings/hotstring_engine_main.ahk:HSE_TryRepeatKey` reads the complete scalar before the configured magic-key suffix and its predecessor. Both must satisfy the live word-character/boundary policy, the repeated scalar must differ from the magic key, and an unknown buffer start cannot license a doubling using its first scalar as predecessor. Repeat enabled, suppression depth and registry-rebuild/transition fences are live inputs. It returns a transient literal Spec whose trigger is previous-scalar plus magic key and whose replacement repeats that scalar twice.

The regular expansion dispatcher owns output and commits the actual effect only after its sender verdict. Windows therefore erases/retypes both the scalar and magic key; Linux's corresponding fallback erases just the magic key and emits one scalar. This is a source-derived implementation difference, not an established intentional product policy or a claim about native application Undo grouping. Terminal pacing and native Notepad transactions retain their own original destination and output receipt; ordinary hosts use an atomic SendInput burst. A scheduling receipt is not a successful fire.

`_OnPrefixKeyDown` sends plain Backspace through `_PrefixFeedBackspace` -> `_PrefixCommitBackspace` -> `HSE_FeedBackspace`, decrementing the matcher/preview by one complete scalar. No driver-specific restoration of the previous hotstring trigger is on this Windows path. Modified Backspace resets according to word-delete/unknown-context policy; Ctrl+Z/Y are application-owned shortcuts with configurable word reset. Linux has a separate explicit immediate-Backspace expansion receipt. This capability difference is actionable parity debt, not evidence that Windows cannot use its application's native Undo. No driver provides a general certificate for native application grouping, rich formatting or application redo.

## URW-001 — Repeat declassifies a private programmable output's last scalar

Severity: medium. Confidence: high for the source chain; native Windows execution unavailable. Named additional property: `private_derived_output`; no G1–G5 claim.

Reproduction derived from the production source:

1. Enable hotstrings, the repeat fallback and a programmable user-code suffix. Configure an isolated source containing one suffix, `audit`, whose actual callback returns synthetic literal `SYNTHETIC_CANARY_Z`; leave no registered or programmable competitor for the later `Z` suffix. Use an ordinary nonsecure editable control, stable focus and unchanged source.
2. Type `audit` then the magic key inside the configured user-code delay; let the genuine worker result be accepted and the dispatcher finish. `_UserHotstringsCommit` (`modules/dynamic_hotstrings/user_code.ahk:424–448`) builds `OnlyText: true, IsPrivate: true` and does not set `FinalResult`. `HSE_ApplyExpansion` (`hotstring_engine_main.ahk:1106–1157`) retains that nonfinal literal output in `HSE_Buffer`. The initial canonical AI effect clears private content from the AI context, as intended.
3. After suppression releases, but before idle expiry or any other input/context change, type the magic key again. The suffix has no ordinary/user-code owner, so `HSE_TryRepeatKey` reads the retained `Z`, preceded by `_`, and constructs `Z<magic>` -> `ZZ` (`:1193–1270`). Its returned Spec has no `IsPrivate` property.
4. Successful repeat dispatch marks its synthetic burst public and constructs `IsPrivate=false` in its canonical effect. `_HSE_MirrorCanonicalEffectToLlm` (`hotstring_dispatch.ahk:905–936`) therefore inserts `ZZ` into an active AI/agent context rather than clearing it. `_OnPrefixChar` (`hotstring_inputhook.ahk:1628–1667`) also queues public `Z<magic>`/`ZZ`. `KL_LogHotstring` (`modules/keystats/keystats_hotstring_log.ahk:112–129`) writes those unredacted characters to trigger, replacement and tag if normal metrics admission is enabled.

Root cause: privacy belongs to the current Spec only; a later repeat synthesizes output from an earlier private matcher value without inheriting its classification. The retained `_PrefixPrivateResidue` diagnostic flag does not classify a repeat; `_PrefixPostFireDecision` checks only clear-all and boundary state. This is a derivation from previously protected output, not freshly typed private characters or a claim that all ordinary typing must be excluded from analytics.

Visibility: all sender/queue/logger/AI calls can succeed. No exception or refusal announces the declassification. The leak established by this source chain is the last scalar, repeated, and its trigger—not the entire original secret. The protected local metrics row may itself subsequently be encrypted according to selected policy; that does not repair the missing privacy label or the in-memory AI-context admission. No actual network request, durable write or editor receipt was measured here.

Counterexamples: the shipped personal-info `@` and phone/SSN/IBAN-prefix registrations set `FinalResult=true`; final-output forgetting prevents the same direct personal-field -> repeat sequence. Personal multi-field key payloads also clear the matcher. The genuine nonfinal private producer here is the supported programmable output owner, not an invented private test-only registration. A user-code output ending in a delimiter, an intervening reset, disabled repeat, idle expiry or a competing registered suffix also prevents the exact reproduction.

Regression direction: execute genuine AHK user-code commit -> actual expansion effect -> physical suffix fallback -> real dispatcher -> actual analytics/AI owners over recording native boundaries. Assert a classified private scalar never becomes public output, fire row/tag, synthetic typed event or AI-context text. Include ordinary public repeats; final private personal fields; nonfinal private outputs; Unicode scalar; intervening physical public characters; idle/focus/pause/rebuild/reset; both native deferred hosts; failed output. Decide a clear buffer/privacy inheritance rule without marking every future physically typed word private forever or weakening focus/sender fences. Native editor delivery remains a separate receiving qualification.

## URW-002 — Deferred repeats acquire magic-key WPM coloring

Severity: low. Confidence: high for the source chain; no native Windows execution. Named additional property: `truthful_live_repeat_classification`; no G5 preview claim.

Reproduction derived from the source: with metrics initialized, WPM widget visible and repeat enabled, type an unmatched mid-word sequence such as `po<magic>` in an ordinary atomic-output host, then in an admitted Notepad/native-literal host or paced terminal host. The same fallback Spec is emitted in all cases. The synchronous caller normalizes `IsRepeat` to `MenuCommand.REPEAT_KEY` (`hotstring_inputhook.ahk:1653–1667`). Both deferred owner constructors instead copy `Spec.Category` directly (`hotstring_dispatch.ahk:624–653`, terminal owner around `:1463–1507`), where the fallback sets `Category="magickey"`, `Section="repeat_corrections"`. Deferred completion (`_HSE_FinishNotepadCommit`, normal terminal commit) queues these unchanged values.

Root cause: a classification override lives in one synchronous caller, while host-specific deferred owners use a different source. `KL_LogHotstring` forwards category/section into `WPMWidget_Push` after successful canonical row acceptance. The shared `[neutral_sources]` explicitly includes `repeat_key=true` and excludes `magickey` (`_shared/modules/wpm_widget/constants.toml:188–193`). `WPMWidget_Push` (`wpm_display.ahk:221–255`) clears the hotstring flag for neutral repeat_key, but leaves magickey true and stores magickey/repeat_corrections as the live last-hotstring category/section. The same doubling can therefore color the live widget as a magic-key correction only in deferred hosts.

Visibility: valid metadata flows through successful calls, so exceptions do not expose the mismatch. DEBUG diagnostics can show it. The canonical JSONL hotstring row does **not** persist category or section; do not infer durable category corruption from this finding. Existing neutral-category tests and repeat corpus/preview tests do not exercise this cross-host metadata chain.

Regression direction: run actual transient repeat Spec through atomic, Notepad and terminal successful owner completion, capturing the genuine fire-log/WPM sink arguments. Require equivalent neutral repeat classification for each host, while a real repeat-corrections mapping remains a colored registered correction. Cover refusal, pending/success exactly once and paused/stale completion. Do not remove output acknowledgments or infer successful delivery from owner scheduling.

## Intentional differences and limits

Correctness/receiving still depends on native environment.                                                                                                                                                                                                                               |

## Counterchecks and test trust

The root should rerun `python3 <artifact-dir>/source-contract.py <repo-root>` and inspect the quoted production owners independently. It verifies source SHA equality to the pinned commit and the lexical chain only. The repository false-green baseline was run by the parent; this reviewer additionally read the real repeat corpus and no-repeat-preview tests. They assert meaningful fallback, scalar, fence and withheld-preview behavior, but neither turns private user-code output into a repeat nor completes both native host owners into WPM classification. No registered AHK test was executed in this Linux container; Wine was not present. No existing test was modified or weakened.

Rejected hypotheses: direct private personal-field repeat leakage (real final-output barriers); repeat escaping rebuild (fallback checks both registry fences); punctuation or first-letter repeat after a known/unknown boundary (both scalar checks plus start flag); malformed surrogate fallback output (complete-tail-scalar guard); repeat-correction mappings hidden as doublings (cache IsRepeat=false and loader metadata agreement); a declined winning mapping being replaced by a doubling (fallback is taken only before dispatch, on no match); native Ctrl+Z promised as Ergopti trigger restoration (application-owned and unmeasured); durable category field corruption (the row has no such fields).

Two complete bounded dry sweeps after the final new root revisited every coverage axis, including public entry, all output host completions, ordinary/modified Backspace, idle restoration, scalar boundaries, custom delimiters/magic source, preview oracle, settings publication and failure retention, repeated/stale/pause/focus/rebuild dispatch, initial private producer and analytics/AI sinks. A and B authenticated the same 19 source files and reran all 18 lexical checks. Neither sweep found another distinct confirmed root; this is closure of this Windows module's bounded source review, not proof of exhaustive repository or native correctness. Receipts are in `dry-sweeps.json`.

Memory watch-list: repeat Spec and native owner lifetimes are generation/suppression owned; no measured leak, growth or latency is asserted. Real AHK parse/runtime, keyboard hooks, user-code worker admission, actual SendInput/clipboard/native literal transaction, native terminal deletion, private metrics persistence, AI request receiving and editor Undo/redo remain unexecuted gaps.
