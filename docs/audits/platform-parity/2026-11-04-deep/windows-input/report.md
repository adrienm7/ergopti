## Confirmed actionable findings

### WI-001 — LAlt configured with Tab tap and None hold still activates navigation

Severity **medium**, confidence **high** by direct source/configuration proof. Configure via the supported tap-hold picker: left Alt tap `tab`, hold `none`. This is a valid state, not a missing/invalid setting: `tap_hold_writer.ahk:_TH_BuildHoldCandidate :830–842` deletes both hold fields and writes `hold_modifier=''` for None. `tap_hold_loader.ahk:295–302` explicitly evicts inherited `hold_layer` when that user field is present. Shared recommended LAlt layer therefore does not reappear on reload. Equivalent TOML:

```toml
[tap_hold.keys.left_alt]
tap_action = "tab"
hold_modifier = ""
```

At `platform/remap/lalt.ahk:127`, the special Tab criterion checks only tap is Tab, hold modifier is empty and layer inactive. It **does not check hold_layer**. Its body at `:132` unconditionally calls `TapHoldOwnImmediateLayer`. That helper (`infra/nav_layer_helpers.ahk:128–178`) activates navigation before waiting and makes a long hold ineligible for tap. `_LAltIsSpecialTap` at `lalt.ahk:62–68` excludes Tab from generic tap-only branch `:341`; there is no later correct fallback for the configured None hold.

Manual native scenario (not run): restore recommended layers.toml, choose those two settings, hold LAlt longer than 200 ms and strike a navigation-bound letter before release. Actual source selects the navigation action even though the picker shows no hold. A long isolated LAlt also emits no Tab. Without layers.toml the hidden layer still toggles, though the changed output may be less obvious.

Negative controls checked in source: configured Tab+nav intentionally enters the same helper; configured Tab+Ctrl fails this special criterion and enters generic hold-modifier `lalt.ahk:294`; `right_ctrl`'s Tab-only variant explicitly checks both empty hold fields (`rctrl.ahk:102`). Default LAlt is Backspace+nav, so shipped defaults and same-default parity tests miss this custom configuration. This is not an intentional natural Alt hold or an action catalogue vocabulary difference: it activates a non-native navigation layer despite an explicit empty hold.

Suggested Windows regression: register/capture the actual criteria for LAlt across tap Tab × hold None/nav/Ctrl; invoke winning handler through native ownership seams and assert None does not call ActivateLayer. Extend to every special-tap × hold combination, including the custom RCtrl+LAlt variant at `:143`, rather than pinning only the presence of timeout/minimum guards.

### WI-002 — Composer Save-and-use reports success before the selection reload commits

Severity **medium**, confidence **high** from an explicit asynchronous receipt mismatch. Scope is the **not currently selected** composed layout; already-selected refresh has a different, correct completion path.

`ui/layout_manager/composer.ahk:_LayoutComposer_OnInstalled :380–388` calls `Deps['select'](Id)` and immediately publishes `composerResult(ok=true,used=true)` when that returns truthy. Production `select` is `LayoutManager_Select` (`composer.ahk:330`), whose implementation at `ui/layout_manager/init.ahk:356–358` returns true for **either pending or committed** selection receipts.

Actual selection uses `ConfigScopeCommitOperations` (`init.ahk:383–384`). `infra/config_scope.ahk:187–200` sets `Receipt.status='pending'`, starts the successor and returns while the live driver still owns its old admitted layout. The later refusal callback `:105–113` rolls the configuration back. Composer did not retain the receipt or subscribe to terminal completion, so that later rollback has no composer failure/result callback. Shared `ui/layout_composer/composer_page.js:592–609` marks the editor no longer busy and `composerState.active=true` when it receives the premature success.

Manual native/fault-injection scenario (not run): keep another layout active; Save-and-use a valid composition; allow successor launch but refuse its later lifecycle/terminal handoff. The resident driver retains the former layout and configuration rollback runs, while composer already reports the composition active. This is distinct from successfully saving the installed composition: the claim `used=true` is false.

Negative controls: if select refuses synchronously, lines `:383–385` report failure; if composition is already selected, lines `:390–407` await `Deps['after'](...,Reloaded)` and report its terminal answer once. A Save without Use while unselected may truthfully report installation success without active use. Existing host fixture `tests/unit/modules/keymap/test_layout_composer_host.ahk:46` stubs select as immediate true; its tests at `:223–228` encode exactly that assumption, while late refusal regressions at `:332–368` cover the already-selected branch only.

Suggested regression: unselected Save-and-use with actual pending selection receipt and later refusal, later success, and immediate refusal. Keep `pending=true` / `used=false` until terminal acknowledgement and preserve one result owner across rollback. Shared page already accepts `pending` in its result schema.

## Challenged hypotheses kept out of actionable findings

**OI-001 — Registry dead-key state survives tray pause/resume.** Source fact: `keylayout_emulation.ahk:511–516` advances process-global KLE_State; reset keys are keyboard-only at `:54–56`; lifecycle suspend/resume contains no reset/unload of this state. Full production symbol search found writes confined to load/typing/reset in the emulation module, and the LLM adapter only captures a snapshot (`adapters/llm_nav_event_owner.ahk:3140–3149`). A mouse tray pause can therefore leave a pending accent in the model across native Suspend. Source assertions confirm absence of a lifecycle reset. However a **requirement to discard registry composition on pause is not explicitly documented**; the analogous one-shot/hotstring resets are not sufficient proof of that product contract. Native delivery and focus-change effects are untested. Record this as a state-policy/native-test gap, not a confirmed unwanted output defect. A useful negative control is a reset keyboard key before pause or successful Load/Unload, which does clear state.

**OI-002 — Pending simultaneous-chord keys are replayed while suspended.** Initial hypothesis was “timer injects after pause, therefore defect.” Actual `KeyCombinationChordTick :1377` intentionally includes `A_IsSuspended` among reasons to flush an undecided original key; `_KeyCombinationChordFlush :1311–1323` describes replaying that original key as a held press or tap. Production port `:1090` calls raw SendEvent. With hotkeys suspended that can be a native pass-through of already suppressed physical input, **not a new feature action**. No unwanted transformation or ownership violation was proven; it is excluded from findings JSON. Custody-preservation rationale is **inferred from the explicit replay behavior/comment**, not a recorded cross-driver policy decision. The related typing-roll path instead guards replay against pause (`tap_hold_roll.ahk:299–314`), so pause-drain policy deserves an explicit shared contract and native regression; equal catalogues do not prove equality here.

**Multiple simultaneous navigation owners:** direct boolean ActivateLayer/DisableLayer first suggested an owner-count issue. Actual tap-hold #HotIf criteria include `not LayerEnabled`, preventing ordinary second layer activation while the first is active; pair admission likewise gates layer ownership. No reproducible multi-owner defect established. Do not file by inspecting the helper alone.

**Registry partial hotkey registration:** `_NavLayerRegistrationAttempted` prevents retry and `_NavLayerRegistered` keeps partially acquired variants dormant; registration builds callbacks before first Hotkey and resets HotIf in finally (`nav_layer_table.ahk:246–276`). This is deliberate containment, not proof that partial native registrations are rolled back. No second registration bug established.

**Failed registry source replacement:** load prepares an admitted model before publication, and `_KLE_Activate :1247–1255` expressly retains prior source on failure. Canonical publication at `keylayout_emulation.ahk:1736` publishes model/id/state together after preparation. No claim that a rejected layout unconditionally destroys the old one.
