## Intent, parity and proof limits

Nonblocking desktop commands are explicitly required because Linux owns the grabbed keyboard (`system_actions.lua:16–18`). This justifies asynchronous execution, not dropping successful repeated toggles or hiding launch/completion errors. GNOME color-scheme differs from macOS System Events appearance and Windows Personalize registry+broadcast. EWMH/DPMS and active-window signals explicitly require X11; chooser/notification backends vary by desktop; their limitations are documented. No equivalent race-free claim was made for other OS. Repeated-toggle coalescing was not documented in inspected code/catalogue; calling LDS-002 intentional would be unsupported inference.

No native evdev, actual desktop session, real device, target process, clipboard, trash or mount mutated. Pause checks verified before dispatch do not promise cancellation of a shell already launched. No independent native crash/PID-reuse/permission/dialog qualification, job-leak measurement, or G4 latency measurement. Existing report's G4 disclaimer remains valid. This final countercheck changes no JSON IDs itself; root owns integration of already confirmed LDS-002.
