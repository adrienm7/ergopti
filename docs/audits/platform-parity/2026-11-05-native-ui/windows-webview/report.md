## Confirmed findings

**WVB-001 — medium, high confidence, G2/G5.** `_HsEdWeb_ShowSaveFailure` at personal_toml_editor_webview.ahk:391 double-quotes a complete JSON string literal from `_HsEdWeb_JsStr` (:632). Open via `OpenPersonalEditor`, initialize, suspend, save an edit: shared persist(:1417) posts save and displays common.saved immediately. The suspended bridge path (:275) schedules only the broken failure-toast script. Writes correctly remain blocked, but the user receives a false Saved indication. Ordinary commit failure also invokes a separate notifier; this mitigates that ordinary path and does not repair the paused path. The shared script observer explicitly documents native completion is not application success. Exact emitted scripts and corrected semantic controls are in logs/refusal-script.json. Regression must assert DOM error content, zero writes under pause, and distinguish native submission/completion from JS application acknowledgment.

**WVB-002 — medium, high confidence, G5.** Shared settings `bindDelay` at script.js:198 assigns `input.value = ms || defaultMs`.0 means unlimited in the actual Windows engine: native serializer `_HCWWeb_FieldsJson` preserves0 (:553), resolver preserves it, and `_HotstringsDelayLine` (:445) serializes delay_unlimited=true. Reopening a0-delay category/section, or the state push after setting0, therefore shows the positive default (normally750). The probe's explicit change dispatch additionally demonstrates how subsequent user changes use that displayed value; no browser-generated change from a programmatic assignment is claimed. Shared root affects all three hosts, and Lua serializers at macOS init.lua:358/382 and Linux bridge.lua:174 also supply numeric0. Source path and state origins are confirmed; native UI execution remains outstanding. Regression must assert0, absent and positive effective/default delays through the real renderer and physical reopen.

## Ownership, URL and native receipts

Same-window replacement: personal editor and HCW focus their exact current GUI; action picker replaces the prior picker, verifies epoch after retirement and never overwrites a successor admitted during close. All three keep event subscriptions alive. Opening constructors publish the GUI before Show and check exact epoch/window around browser acquisition. Close/reset captures retired references, revokes owner/source/epoch before native callouts, and releases subscriptions before controller. Hide is a generic WebViewHost pending-build close mechanism; these named nonretained editor hosts destroy on completed close. Reopen constructs a fresh controller/session rather than keeping the old document. Existing 10/28 fixes/tests already cover these startup/replacement roots; not duplicated here.

URLs use configured local virtual-host mappings and per-open cache-busting URLs. Named hosts subscribe by AHK session epoch; they do not validate Args.Source, NavigationId, navigation success, or an application-level ready ACK. No page link/open command or ordinary same-controller document replacement path was found in the bounded pages, so arbitrary foreign navigation remains a hypothesis, not a confirmed finding. Retained metrics hosts have stronger document fences elsewhere; those are not proof these editors have them. Navigation failure currently lacks verified native fallback receipt; not reported without reachable independent failure injection.

`WebView_RunScriptAsync` returns submission+observer acceptance and reports native completion only; its comments make this explicit. `_HsEdWeb_InitSourceSettled` turns positive native completion into source.ready, but not a DOM acknowledgment. No destructive save was proved from a failed/partial init: invalid/missing initial data gives no ordinary user-reachable editor action. This is an evidence gap, distinct from confirmed WVB-001's exact syntax failure.

Profiles: GUID+PID paths and ownership maps distinguish private sessions; confirmed BrowserProcessExited PID or owned-job ActiveProcesses=0 authorizes retirement. A failed startup without terminal proof retains its profile. Cleanup requires exact owner, exited+retired, receipt bytes and no reparse-point directory, and retries bounded sharing failures. Prefix/age alone never authorizes deletion. Shared persistent environment profile is deliberately separate; no actual user profile was opened. Warmup retains real HWND until pending controller terminal callback, uses promise identity, and preserves failed-close capability for retry. Native process-tree exit and disk cleanup semantics remain Windows qualification gaps.

## Rejected hypotheses, memory/performance and exclusions

- Strict-case box loses exactness: rejected by actual shared strict-case gate and current executeSave/persist flags; this is the recent fix, not new work.
- Double-close frees a controller twice / old startup closes replacement: bounded source review finds ResetDone, detached aliases and epoch checks; read existing actual-owner tests. Native behavior not requalified here.
- HCW throws away every failure receipt: refuted by strict WriteBatch outcomes, failed indices, reconciliation and notifier. Partial batch durability is explicit; atomic rollback is not promised.
- Paused configuration still writes: save/SavePref/dispatch/confirm have delivery-time pause gates plus physical transaction authority. WVB-001 is failure visibility, not a pause-write bypass.
- Picker confirmation callback throws unhandled: `_ActPickWeb_Confirm` catches/logs and clears offered parameters; failure can close ordinary picker by design, but slot refusal stays open.
- Provider stale resolve assigns to a successor: exact epoch/session checks and captured provider owner refute the simple hypothesis. Discovery inventory/native execution depth belongs to runtime/action audit.
- Profile deletion from age or arbitrary prefix: current terminal receipt and path validation refute it; no real profile filesystem operation performed.
- Native eval completion proves JS success: explicitly false per owner contract; only WVB-001 has exact executed-JS failure evidence here.

Memory watch-list: unset globals and Map missing keys reviewed on bounded callbacks; shared environment reentrancy and late promises reviewed; callback retained lifetimes and teardown inspected. No new memory-growth measurement. Cycles, native COM lifetime, shared-profile process retention, shutdown timing and actual activation/input capture are unmeasured, not certified. Performance: no production logs inspected, no timings attributed to driver, no G4 finding. Native browser startup/hook/input/registry/network/provider launch and arbitrary external document security are excluded from execution.

## Final failed-save / automatic-close countercheck

No WVB-003 retained. The shared `saveEntry(false)` shortcut branch can post save followed by independent close before a physical-save acknowledgment. However, the ACTUAL Windows `_HsEdWeb_InitDataJs` hardcodes `open_mode:"menu"` (:604), and its launcher documents DefaultSection as advisory rather than carrying a shortcut mode. Therefore an automatic-close draft-loss reproduction is unreachable through this Windows opening owner. Private `probes/autoclose-reachability.cjs` extracts the actual native init mode and executes actual shared saveEntry/persist: even with auto_close enabled Windows emits ONLY save; the explicitly synthetic shortcut-mode control emits save,close. Receipt:logs/autoclose-reachability.json. No AHK or physical write was simulated or claimed executed.

`_HsEdWeb_Close` itself has no pending/failed-save veto and does destroy the draft/controller and clear OpeningSource. Thus an explicit user close after a failed physical save can discard the displayed draft; source inspection alone does not establish that deliberate close is a new automatic-loss defect. No durable-success/live-reload failure is used to infer physical data loss. The hardcoded menu mode also means shortcut-target selection/auto-close equivalence with other OS hosts is not proved; calling this a missing feature requires the public shortcut caller/product contract, not merely helper presence. This countercheck adds a refutation and no new root; the two final dry sweeps remain after the last new root WVB-002.
