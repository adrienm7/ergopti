## MH-001 — Programmable preview metadata is incorrectly interpreted as output tokens

Severity **low**, confidence **high**. A programmable hotstring can declare static preview text containing braces. macOS changes that text before displaying it, although both the programmable owner and actual callback output preserve it as literal text.

Example: `preview = "Literal {Left} {U+0041}"` renders as `Literal  A`: the key-looking fragment vanishes and the Unicode-looking fragment becomes A. A callback returning the same string types `Literal {Left} {U+0041}` literally. Static descriptions need not equal the callback output, but their bytes are still declared display metadata: changing them is a display contract defect, and a description made entirely of `{Left}` can become empty.

Production caller/effect evidence:

- `_shared/lua/dynamic_hotstrings/user_source.lua:11`: example explicitly describes preview as static metadata and runs callback only after a matching magic key. `user_code.lua:40-49` validates/copies `preview` as a string; `owner.preview` at `:214` returns it unchanged.
- `macos/modules/dynamic_hotstrings/user_code.lua:107` projects the row's `preview` unchanged; `rules_engine.lua:376` returns that preview when no builtin rule owns the suffix.
- `macos/modules/keymap/llm_bridge.lua:413`, `provider_plain`: unconditionally calls `km_utils.tokens_from_repl(raw)` then `plain_text`; at `:850` the provider record takes this transformed value as `plain_repl`; row construction at `:1016` displays `masked_for_preview(m)` from that value.
- The actual programmable commit in `macos/modules/keymap/init.lua:1163` calls `km_utils.emit_text(replacement)`; `utils.lua:1052` emits text literally, so no corresponding token projection happens to callback output.
- Narrow counterpart source comparison: Windows `modules/dynamic_hotstrings/user_code.ahk:569-580` builds the preview spec with `Replacement: Rule["preview"]` and `OnlyText: true`; Linux `modules/dynamic_hotstrings/manager.lua:573-581` carries `replacement = user.preview` without this Mac provider projection. Neither source authorizes treating a static descriptor as Send/TOML token syntax. Native Windows/Linux rendering was not run here.

The probe reuses original fixture constructors by loading their source prefixes, without modifying production modules. Phase 1 runs the actual programmable source factory/owner, real keymap dispatch and deferred callback/output path, with native Hammerspoon input/AX/timer doubles. It asserts that preview does not evaluate the callback, callback runs exactly once after the physical magic event and output is literal. Phase 2 feeds that exact preview value through the actual bridge, registry and expander into a captured real row-builder result. The canvas sink is replaced to observe the text; no Mac window is claimed to have appeared.

Silent failure: no error is raised and the callback still works; only the advertised description is silently altered. Regression coverage should include braces/key-looking and Unicode-looking text in a real programmable provider descriptor, assert the exact displayed string, and keep ordinary static TOML output-token previews covered separately. No intent or native constraint justifying this descriptor transformation was found. A fix should identify static provider text as literal instead of changing the shared TOML output grammar.

## Pass 2: adversarial follow-up and refutations

- **Preview may execute a user callback:** refuted for exercised native owner. The MH-001 probe and 58 native tests verify callback count stays zero during source loading while disabled and during preview; physical magic dispatch schedules it, then it executes once. Source factories are executable at explicit enabled load/reload, which is a different operation.
- **A source/focus/pause change after callback return can still type queued text:** no reproduction in actual programmable/native-boundary tests. Receipt checks survive callback completion, re-check final AX owner and exact source bytes, and retain clipboard/scheduler cleanup. This is not a native TCC/event-stream qualification.
- **Private text returns to remote prompt via preview mirror:** refuted in 8 composed real registry/expander/dynamic/bridge/prediction cases with a captured remote HTTP transport, including subsequent typing, Backspace and head trimming. `mark_private_context` records the private boundary, and the bridge applies the shared `after_private` rule at reads. No new private-data leak established.
- **Masking corrupts the text actually typed:** refuted by real display-only/private injection tests. Masked tooltip strings stay separate from full replacement strings; personal multifield output and its logical telemetry remain distinct from Tab navigation.
- **Partial dynamic startup leaves callbacks enabled:** no reproduction. Six dynamic-core startup and nine rules-engine startup cases test rollback of already mounted siblings; eight resolver-lifecycle cases revoke results when resolver/policy callbacks stop/reconfigure their own owner.
- **Failed clipboard snapshot or restoration overwrites another clipboard writer:** no reproduction in 13 snapshot and 14 restore-ownership cases. Exact change-count ownership, stale timer/source replacement, restoration debt and retry paths are exercised; no native pasteboard execution here.
- **Terminal deletion blocks inside an event tap:** five dedicated cases pass. Paced collector and target-bound serializer perform the output after callback handoff; the completing physical event is consumed. The native application's actual character processing/paste timing still needs a Mac field test.
- **Registry change claims success before native/preview publication acknowledges:** 36 exact-commitment and 31 dynamic-category transaction cases pass for the exercised mutations, in addition to 30 scope and 17 override/config transaction cases. No new failure was established from rereading their call sites.
- **Raw private buffer passed to keystats.set_buffer is automatically a new persistent leak:** not established. That function merely assigns its transient tracking buffer (`modules/keystats/init.lua:1435`); private persistence has an independent redacted `notify_synthetic` path. No persistence claim was made from the transient call alone.
- **Deferred callbacks run on a worker thread / are time-bounded:** false assumption. Mac's consumed-input action leaves the eventtap but still invokes Lua via pcall on the runtime loop. The code provides cancellation/receipt guards, not preemption of already executing user Lua. This architecture difference is documented below; no artificial infinite-loop probe was run.

They do not certify that every application accepts those requested events identically.
