# Undo and repeat — shared and cross-driver review

Audited commit: `b17e47ed3bb92c106703d3e3482b3c2973f5bc1e`.

Two actionable metadata findings are confirmed at that commit: the generated inventories have no declaration for Linux's specialized Backspace restoration, and the English inventory headings/legend translations are inert text inside a comment. Neither is a claim that the existing generator promised semantic exhaustiveness. The first is addressed by a separately reviewable supplementary behavior catalogue; implementation status must remain separate from this immutable source review. No production input behavior was changed.

## Findings

### URS001 — Linux's specialized Backspace restoration has no generated behavior declaration

The shared settings manifest cannot describe always-on conditional behavior without inventing a setting. At the audited source, all four website inventory JSON projections omit specialized expansion restoration, although Linux Main contains an owned restoration receipt. The generator reads no independent behavioral source. The root TODO's manual typing check mentions Backspace without declaring which implementation exists. This is a coverage property of the product inventory, not G2/G5 or a native output guarantee.

Regression direction: a supplementary authored behavioral register must explicitly declare every OS and reason/qualification, name real reviewed source owners, feed both website and documentation, and reject stale/missing/invalid source receipts. Whole-file hashes are deliberately conservative review prompts. Passing them cannot establish semantic exhaustiveness, native receiving, or automatic detection of undeclared features.

### URS002 — English inventory UI translations were inserted inside JSDoc

`src/routes/ergopti-plus/locales/en.js` contains the new inventory translation mappings between the JSDoc placeholder opening and closing text, before `export default`. Actual Node module import returns `undefined` for the inventory header and legend while `Pour qui ?` returns `Who for?`. The page's actual gettext accessor falls back to French. This is an ancillary localization defect discovered at the module's public inventory consumer. No unrelated existing translation was moved during the metadata addition.

Regression direction: inspect the exported dictionary object, not source substrings. Assert every static inventory heading and legend actually resolves to English. New strings belong inside the real exported dictionary.

## Evidence, controls and limits

`source_probe.py <repo>` reads exact Git blobs at the audited commit, authenticates eighteen files, and actually imports the pinned English module from a private temporary `.mjs` file. `source-observation.json` retains the hashes, known-missing keys and positive control. It never reads user configuration, logs, input or clipboard.

From the macOS driver directory, `lua tests/run.lua --only=tests.unit.modules.keymap.repeat.test_repeat_feature_arm_time` executes 30 registered cases, including all 19 repeat corpus vectors, the custom-terminator refusal and the two-codepoint French magic-event control. Real Expander/SyntheticInput logic runs over the repository's native doubles; these are not native desktop edits. From the Linux driver directory, `luajit tests/run.lua --only=repeat-key-corpus` executes 19 cases through actual `RepeatKey.resolve`. The same Linux corpus was also run on Lua 5.4. The corpus itself explicitly covers common single-repeat decisions. It does not test Main's post-commit state publication and therefore cannot refute the Linux consecutive-repeat defect.

Two initial invocations used the repository root instead of the driver working directory and failed harness path assumptions. A later broad Linux `--only='magic-key repeat'` invocation selected zero cases. All three outputs are retained as diagnostic failures/zero coverage, and none is counted as a passing module audit. Corrected invocations above select nonzero cases and assert their counts. The false-green detector reports zero mechanical baseline debt; that is not proof against mock contract or oracle-scope defects.

After the last new metadata root, two bounded whole-scope dry sweeps revisited every row and replayed the pinned source/JS observation plus the actual Mac 30 and Linux 19 cases. `dry-receipts.json` records the exact commands and both zero-new-root outcomes.

No native Windows AHK, macOS application, real evdev/uinput device, clipboard owner or application Undo behavior ran. No G4 latency or memory measurement is claimed. There is no observed module-specific memory growth; retained source receipts and transactions remain a source-only watch point, not a leak finding. Native field/grapheme deletion semantics, app-specific Undo grouping, and actual desktop restoration remain explicit receiving gaps.

## Rejected or non-new hypotheses

- The missing metadata is not proof that Linux alone implements application Undo: Ctrl/Cmd+Z is a separate action/shortcut family and may be implemented in the target app.
- A single repeat corpus pass does not prove consecutive repeats retain context. The root belongs to Linux Main's commit publication, not the pure rule.
- No repeat bubble is deliberate policy, not a missing preview feature. The shipped correction entries remain separately previewable mappings.
- Windows deleting two scalars while Linux deletes one is not itself a wrong-output finding: both construct the same visible result on their intended accepted path.
- Readable fallback declarations, registered corpus names and `--only` success do not prove cases executed; nonzero selected counts are retained explicitly.
- Prior canonical report/TODO review found no earlier specialized Backspace declaration or exported-dictionary-comment finding. Existing manual native Backspace checks are retained rather than closed.
