## WDG-001 — Primary and fallback crash workers leave invalid canonical JSON after partial write refusal

Severity: **low**. Confidence: **high** for the unchanged production writer mechanism and actual PowerShell/private-file result; the native Windows disk-full trigger is source-derived and unexecuted. Additional guarantee: **Crash artifact completeness — a failed write must not leave a normal report filename containing a partial document.** No G2 false-success allegation is made.

Reachable public path: an uncaught error reaches `infra/error_net.ahk` → `_ErgoptiDeferredCrashReport` → `CrashReportWorker_Start`; its primary or isolated fallback process invokes `Write-CrashDocument` and prints `OK:<path>` only if that function returns. Both `vendor/ergopti_crash_worker.ps1:63` and `vendor/ergopti_crash_fallback_worker.ps1:37` open the final timestamp `.json` with CreateNew, then execute `try { stream.Write(...) } finally { stream.Dispose() }`. Neither catches write/close failure to retire or separately classify the incomplete artifact. The direct AHK sibling `modules/diagnostics/crash_reporter.ahk:275` explicitly delegates to a durable owner whose comment requires short-write partial JSON removal; its native-failure tests do not exercise these two PowerShell writer bodies.

Concrete safe reproduction executed:

```bash
export ERGOPTI_AUDIT_SOURCE_ROOT=/workspace/worktrees/parity-2026-11-05/windows-runtime
python3 /workspace/scratch/parity-native-ui/windows-diagnostics/probes/crash-partial.py
```

The runner creates only its own temporary directory, ignores SIGXFSZ and sets an actual Linux per-process file-size limit of 1,024 bytes. It AST-loads each genuine `Write-CrashDocument` unchanged. A small valid JSON write succeeds, a second same-timestamp write gets a distinct suffix and preserves the first, then a 16,397-byte document attempts a third canonical filename and encounters a real filesystem write refusal. No business function, file-stream implementation, return value or failure branch is mocked.

Decisive output from `logs/crash-partial.txt`, repeated in both dry passes:

```text

{"worker":"ergopti_crash_worker.ps1","write_refused":true,"exception":"System.ArgumentOutOfRangeException","canonical_json_retained":true,"retained_bytes":1024,"intended_bytes":16397,"valid_json":false}
PASS ergopti_crash_fallback_worker.ps1 healthy JSON + no-replace duplicate
{"worker":"ergopti_crash_fallback_worker.ps1","write_refused":true,"exception":"System.ArgumentOutOfRangeException","canonical_json_retained":true,"retained_bytes":1024,"intended_bytes":16397,"valid_json":false}
CONFIRMED both unchanged production crash writers retain truncated canonical JSON after actual private-file write refusal
EXIT 0
```

Windows repro for later native acceptance: in an isolated private report directory backed by a bounded test volume, make free space insufficient partway through the encoded document; trigger a synthetic error through the actual retained crash worker; inspect the timestamp `.json` after write refusal. This audit did not mount a volume or force a real Windows crash.

Actual visibility: the writer throws, the primary worker may cause an isolated fallback attempt, and eventual failure is logged by the error-net completion owner. The `OK:` success line and saved notification are not emitted for the failing write. The defect is the retained, normally named invalid artifact and possible additional suffix left by fallback, which appear beside genuine reports. Healthy readback tests and create-only collision tests do not expose this failure boundary. Do not label it silent saved-success corruption or a measured power-loss failure.

Regression: exercise each actual primary/fallback writer at write and close failure boundaries, including a real bounded-volume/private-file partial write; require no incomplete canonical `.json` to remain, no `OK:` acknowledgement, preservation of pre-existing collision files, and recovery via a healthy next write. Cleanup must retain exact created-object authority rather than deleting a replacement by unchecked pathname; an owned staging publication design can satisfy that property. Test full worker fallback sequencing as well as the shared writer decision. The presence or absence of a particular API spelling is not the regression invariant.

Duplicate search: prior `docs/audits/platform-parity` and `TODO.md` were searched for crash/partial/truncated/durable writer roots. Existing migration write-failure, logger privacy and direct crash control-text tests were read; none records this two-worker failed-write cleanup root. No logger plaintext item is reissued.

## Coverage, counterchecks and rejected hypotheses

The bounded sweep covered all healthcheck modules, `modules/diagnostics/crash_reporter`, crash worker adapter and primary/fallback scripts, immediate snapshot/error/error-net/logger callback owners, shared healthcheck/error page, schema, collection and redaction policy. Both dry receipts fingerprint 26 core files. Additional sibling/macOS/Linux sources and registered tests were read for control and intent; the receipt is not a claim every compared file was executed.

- **Native fallback Save silently fails:** rejected as a blanket finding. The Click callback does ignore returned `{ok:false}`, but its actual `LoggerError` reaches `ErrorDialog_OnError`; unavailable WebView error presentation calls `NotifierSend` with the message. Source probe retains both the tempting narrow path and the actual cross-owner refutation. User-disabled/rate-limited error policy is explicit behavior, not proof of unconditional loss.
- **Page can upload arbitrary local paths or canary secrets:** rejected in bounded checks. Action IDs are allowlisted; save/report are rebuilt from typed host projection and exact preview. Shared 43 redaction vectors plus page/model sharing canaries pass. The native ZIP receiver rejects unknown/private fields and free-text numeric values. No claim that these finite vectors exhaust all privacy inputs.
- **Synthetic UIA PASS qualifies the real input driver:** rejected. Actual collector exports `qualified_production=false`, `physical_qualified=false`; named functional scenarios remain UNRUN even with resident state PASS. Page-model/native/physical domains are separate. Actual PS projection controls verify passing generations remain scenario-unqualified and reject native PASS without active native owner.
- **Stale page close/reopen may publish to successor:** source countercheck finds epoch + exact session guards, deferred COM messages and fresh `page_url`; collection deliberately outlives page but publishes only while exact owner and window still match. Existing lifetime/publication fixture owners were inspected. Shared page sequence controls passed; native reentrant windows were not exercised.
- **Worker can archive an approved basename replaced with foreign bytes:** source countercheck finds private identity + byte count + SHA-256 admission for each acknowledged produced file, reject reparse/multiple links, create-only first move, exclusive repeated update. No native file-identity certificate is inferred from a Linux hash test.
- **Cancellation acknowledges native cleanup from progress alone:** source countercheck: host progress is projected with `owner_pending=true`, `archive_created=false`; phase completed becomes retiring until exact task completion. Archive digest and receipt are checked after terminal delivery. UNRUN/SKIP are not promoted by a saved archive.
- **HTTP 200 malformed version body means full model readiness passed:** not retained. These probes measure connectivity and report HTTP 200 if optional version/rate-limit fields cannot parse; owned runtime/readiness/AI enable admission are separate. Intent does not establish a strict API-schema validation requirement for this connectivity row.
- **Missing unavailable-feature explanation:** known TODO, not new finding. **Plaintext local log/crash content:** explicit local-rich versus sharing policy and earlier audit territory, excluded here.

## Performance, memory and native acceptance gaps

G4 timing is unmeasured on the native driver. Snapshot declares a 5 ms phase-A budget and records actual collector costs; deferred configuration parsing still executes on the AHK thread, and a timer is not a worker thread. No large-config or real-log latency measurement was made. Network work is child-owned; CPU sampling uses two native snapshots separated by a timer. No claim of a hard latency bound follows from source scheduling.

Memory watch: day-log input/output has a 4 MiB cap; `_DayLog_State` retains the most recently prepared snapshot/result. Titlebar close clears `_HC_Session` without explicitly discarding that day-log state (the page close action does discard). This is bounded retained-memory/source characterization, with no measured resident growth or privacy leak claimed. Collector task/output/archive sizes are bounded; crash IPC is bounded and mapping retirement debt is retained. Repeated native close/reopen, cold WebView pressure, large error tails and forced worker-write/close cleanup need Windows acceptance.

Remaining native gaps: exact UIA receiver behavior, dynamic assembly cold starts, job/tree retirement on blocked probes, real NTFS identities/hardlinks/share denial, native file-size/full-volume crash-write cleanup, actual desktop fallback notification, clipboard/save/reveal/browser refusal delivery, timers under pause/reload and real guided input. All automatic networking and AI/model-install consent boundaries were reviewed without exercising them. This report makes no final native Windows or all-product parity certification.
