## MG001 — System-gesture preference tasks are prepared but never started

Severity **high**; confidence **high** in the production Lua call-chain defect. Actual macOS preference values and double desktop actions were not executed; the probe uses real owners over native task doubles.

The system conflict detector requests four `/usr/bin/defaults` reads through `ShellRunner.spawn` but never calls the returned handles' `start()`. Real ShellRunner only constructs/prepares and pins the `hs.task`; it does not auto-start. The pending probe therefore never completes, and every later recheck merely joins it. `snapshot_ready` stays false, so all slots initially report `free`, even ones macOS owns. The intended disabled menu rows, suppression and startup warnings cannot derive a real snapshot in this normal production path.

Production caller -> effect:

- `macos/ui/menu/menu_state.lua:348` calls `gestures.apply_all_overrides` during preference synchronization; gesture facade `modules/gestures/init.lua:664` reaches the real conflict owner with committed assignments/enabled posture.
- `modules/gestures/conflicts.lua:411-418`, `apply_all_overrides`: starts a slow settings watcher and calls `refresh`.
- `conflicts.lua:259-296`, `refresh`: sets `pending_probe`, invokes `ShellRunner.spawn` at `:290`, retains its handles and checks `isSettled`, but **contains no start call**.
- `adapters/shell_runner.lua:379`, `spawn`: constructs a task, sets its lifecycle to `prepared` at `:784`, assigns `handle.start = _safe_start` at `:793`, and returns the unstarted handle at `:831`. Native start happens only inside `_safe_start:487`.
- `conflicts.lua:260`: subsequent refresh/recheck joins the retained probe. `slot_system_state:451-456` returns `free` while `snapshot_ready` is false; `slot_held_by_system:463` therefore returns false.
- Gesture `CoreState.system_held` is the actual `Conflicts.slot_held_by_system` (`gestures/init.lua:200`); swipe `engine.triggerAction:451-459` trusts that predicate before dispatch.

Executed reproduction (`probe-conflict-probes.lua`, `conflict-probes.log`): actual Conflicts plus actual ShellRunner, replacing only `hs.task` native objects with recording doubles. It checks all four original handles' `wasStartAttempted()==false` and `isSettled()==false`, then repeats recheck:

```
REPRO: actual ShellRunner constructs4 preference tasks but none starts; repeated recheck joins pending forever; swipe_3_left remains free
CONTROL: starting the exact retained handles and completing native reads changes same slot to taken
```

Control supplies a known enabled `TrackpadThreeFingerHorizSwipeGesture=2` after explicitly starting the exact prepared handles; same owner transitions the slot to `taken` and calls the original waiter once. No external child/process or native action was run: `.start()` in the control invokes the native task double.

Silent failure: `refresh()` returns true; no start failure is logged, no timeout releases the pending probe, and conflicting slots continue to look free. Existing conflict tests supply a misleading spawn double: `test_conflicts.lua:99` calls completion inside spawn; `test_system_gesture_conflicts.lua:27` exposes callbacks without a start phase. Both pass over this defect.

Regression/fix direction: compose real ShellRunner's prepared/start/settlement contract with the conflict owner; require four start attempts, terminal handling for construction/start failures, live recheck and teardown with exact owners. Also gate affected slots while the first asynchronous snapshot is unknown: merely adding start should not introduce a first-frame window in which unknown means free. The latter is a source-level observation, not an additional independently numbered finding.

## MG002 — Tap dispatch bypasses the native-system conflict predicate

Severity **medium**, confidence **high**. This is independent of MG001: it survives a valid conflict snapshot and correct preference probes.

`tap_3` is explicitly in a blocking conflict group because macOS Look up can own it, but tap recognition directly calls `dispatchAction("execute_single", ...)`, bypassing `triggerAction`'s `system_held` guard. A three-finger tap can therefore run Ergopti's action while native Look up is enabled, even when the menu correctly knows the slot is taken. Swipes use the guard and are suppressed.

Evidence:

- `conflicts.lua:120-127`: the `tap_3` group names `TrackpadThreeFingerTapGesture` and its alias, `blocks=true`, with native default-on policy.
- `gestures/init.lua:200`: passes the real system-held predicate to engine state.
- `engine.lua:451-459`, `triggerAction`: checks `_state.system_held(slot)` and refuses the action while the system owns it.
- `engine.lua:300-321`, `multiFingerAllowed`: checks scroll/momentum/cohesion; it has no native-system ownership check.
- `engine.lua:700-716`, tap part of `commitGesture`: after AI and recognition gates, invokes `dispatchAction("execute_single", tap_action, slot)` directly. It never checks `system_held` and never calls `triggerAction`.

Executed `probe-tap-conflict.lua` uses the actual engine, native touch/clock doubles and action recorders, with a system-owned predicate returning true. It feeds three stationary contacts and lift, then a horizontal swipe as control:

```
REPRO: tap_3 dispatches lookup although system_held always true; conflict predicate not queried
CONTROL: three-finger swipe queries same system_held predicate and dispatches no action
```

No actual lookup, click, application or OS action executes. The production table supplies the same true predicate outcome when Look up is enabled; the omitted engine check is confirmed without asserting a physical Mac double-action reproduction.

Silent failure: the tap logs `TAP FIRE`; no conflict rejection is recorded. Fix/regression direction: apply the same system-held admission to tap commit, retaining single-shot semantics, AI gate, dispatch verdict and suspension checks. Include `tap_3` taken/unverified/free cases plus a swipe control; current incremental-conflict engine test covers swipes but not tap commit.

## Pass 2: candidate checks and refutations

1. **Green conflict tests establish the read/engine policy:** refuted by MG001/MG002. Their native process double omits the prepared->start transition, and engine conflict coverage exercised swipe but not tap. The new probes encode both missing seams behaviorally.
2. **Deferred confirmation executes against a new parent after pause/resume:** no reproduction in the real native-dialog callback/lifecycle tests. `Actions.execute_single` retains parent scope and epoch before asking, then rechecks both when the callback returns. Six confirmation lifecycle cases include real aggregate cleanup and sibling-parent isolation.
3. **A slow/read-blocking touch callback performs a settings process call:** no such call in the recognition hot path. Conflict reads are designed to be asynchronous/off-path; the failure is that their tasks never start, not blocking execution. Frame source logs and native callback payload validation remain source-level boundaries.
4. **Two-finger scrolling or click-drag silently becomes a tab swipe:** no reproduction in 16 dedicated scroll/cohesion cases and six drag cases, plus sustained-peak/drop/upgrade tests. The documented thresholds are deliberately tuned from actual maintainer evidence; this audit did not retune them from synthetic fixtures.
5. **Incremental jitter or a reversal repeats a committed step:** no reproduction in the actual frame traces for incremental tab steps, diagonal reversal, retap reversal and finger-count recovery. Mode-specific thresholds and committed-step counts are distinct.
6. **Suspend is only an engine hint, allowing action owner output:** no reproduction in seven suspend-axis cases, four scroll/click-lock quiescence cases, 31 auxiliary-parent pause tests and 58 composite resume cases. Logical fence is published before fallible cleanup; refused cleanup does not reopen action admission.
7. **Failed native watcher stop can be dropped and replaced:** no reproduction in 25 watcher lifecycle transaction cases. Original constructor/start/native stop acknowledgements and tokens remain retained; wake/rebuild cannot acquire a successor until exact cleanup settles.
8. **Confirmation's xpcall boolean mishandles an ordinary nil native return:** refuted as a general defect. Actual `hs.dialog.alert` wrapper normally returns no values; successful xpcall is the appropriate success signal for that native contract. The native-dialog lifecycle fixture explicitly models nil. An artificial alert-return-false stub was not promoted to a product defect.
9. **Conflict watch local stop forgetting its handle necessarily leaks through process teardown:** not established. `stop_watch:527` drops its local reference before ignoring a false timer cancel, but real `TimerScheduler.cancel:355` retains failed native handles and root `init.lua:1079` calls `cancelAll` before final teardown. No production repeated same-VM restore/start sequence causing duplicate work was established. This stays a local ownership concern, not a third confirmed finding.
10. **Simultaneous contacts from two trackpads have been hardware-qualified:** not established. Device callbacks feed one shared engine; multi-device simultaneity is an unexecuted hardware boundary here. No invented reproduction or new defect is claimed from source shape alone.

## Executed checks, artifacts and native limits

Real **Lua 5.4.8** with external dlopen, LuaFileSystem and luv toolchain; tests run in a fresh interpreter per module from the original repository source with its real helpers. Native touchdevices, task objects, clocks, event taps, dialogs and action effects are modelled/recorded. No real action, command, dialog or native desktop output was emitted.

- `run-isolated.py`, `isolated-results.json`: **46 modules / 516 passing cases**, zero failures.
- `run-more.py`, `second-pass-results.json`: **17 further modules / 285 passing cases**, zero failures.
- **63 distinct modules / 801 passing cases**. The JSON registers retain exact module names, exit codes, counts and per-module logs. These are real owner/recognition tests with native doubles, not native hardware execution.
- `probe-conflict-probes.lua`, `conflict-probes.log`: actual conflict owner + ShellRunner prepared/start reproduction and exact-owner control.
- `probe-tap-conflict.lua`, `tap-conflict.log`: actual engine tap bypass reproduction and guarded-swipe control.
- JS guards passed: `test-gesture-defaults-single-source.cjs`; `test-gesture-slots-single-source.cjs`; `test-action-catalogue-shared-projection.cjs` (six Lua projections, run with toolchain PATH/cpath); `test-restore-recommended-no-confirm.cjs` (22 source-owned restore/clear rows).
- An exploratory invocation of nonexistent `test-action-confirmation-contract.cjs` was a command-discovery error, not a product failure; the actual confirmation Lua suites above were run. An initial action-catalogue invocation lacked lua on PATH; corrected environment passed.

Unexecuted boundaries: physical Mac touchdevice frame capture, true Trackpad/Dock preference outputs, native gesture recognition/coexistence in WindowServer, real multi-trackpad simultaneity, wake/sleep hardware, native Accessibility/permissions and user dialogs, and real system action effects. MG001's process lifecycle omission and MG002's omitted Lua gate are confirmed without claiming those native observations. Hardware/native validation should replay both probes' conditions after fixes and verify that a system-owned tap or swipe causes exactly the native action, never both.
