**MVB-001 — action picker silently drops failed initial data delivery (G2).** `ui/action_picker/init.lua:246-261` catches `hs.json.encode` and native `evaluateJavaScript` exceptions without checking/logging failures. Open a real picker, deliver `{name='action_picker_bridge',webView=exact_view,body={action='ready'}}` through its actual registered native callback, and inject an evaluation exception: one attempted evaluation, no central ERROR, still-open view. An encoder exception produces zero evaluations, no ERROR, still-open view. The inner `pcall` prevents the enclosing controller delivery `xpcall` from seeing either exception. No success data reached the page. Both `ready` and navigation use this unchecked owner. Existing `hotstring_editor`, `personal_info_editor` and `hotstrings_config_window` explicitly observe submission/execution failure, so the omission is a missed sibling boundary.

The seven-mode matrix includes healthy, throwing/false/nil evaluation, an async-error-capable completion port, and throwing/nil encoding. Every mode has zero ERROR and an open view. The async-error row demonstrates that **no completion observer is installed**; it does not demonstrate what native Hammerspoon logs by default when no callback exists. False/nil evaluation rows are adversarial port results, not a claim that Hammerspoon normally returns those values. The confirmed finding rests on swallowed encoding/evaluation exceptions. Native stderr, actual WebKit failure injection and real runtime reachability/frequency remain gaps. Private payload contents are withheld from all assertions/logs.

Regression: require a visible fixed-metadata failure for encoding/submission exceptions and rejected acknowledgement; preserve healthy initialization and correct-source confirmation, foreign-source refusal, stale close isolation, and native nil/`{code=0}` success sentinels. Do not merely assert `pcall` succeeded or search source for a logging spelling.

## MVB-002 — auto-close destroys a refused draft

Criterion: **G2 / draft preservation across refused save**, medium severity/high confidence. This finding concerns destroyed editing state after a loud save refusal, not an optimistic toast.

```sh
/workspace/scratch/parity-toolchain/ci-bin/lua /workspace/scratch/parity-native-ui/macos-webview/probes/autoclose-host.lua /workspace/worktrees/parity-2026-11-05/macos-webview /workspace/scratch/parity-toolchain/ci-bin/node /workspace/scratch/parity-native-ui/macos-webview
```

`probes/autoclose-host.lua` loads the actual public macOS editor, actual TOML reader, actual macOS writer shim/shared writer/preservation model. Its native shortcut registrar records the registered callback: `Editor.set_shortcut(...)` → actual callback → `M.open("shortcut")`. Public `set_close_on_add(true)` configures the actual preference. After `ready`, the actual host `initData` JSON carries `open_mode="shortcut"` and `auto_close=true`; the probe passes those exact bytes to `probes/autoclose-page.cjs`.

The Node probe runs the **complete production** shared editor script plus actual DOM utilities. Only DOM, timers and native message transport are ports; `initData`, `showAddEntry`, text serialization, `saveEntry`, `persist`, `toLua`, `closeModal` and rendering are not replaced. Actual `showAddEntry(0)` plus text-node input produces a unique candidate. `saveEntry(false)` emits actual `save` then independent `close` messages; the Lua owner receives those generated payloads in order.

The private source is a real file with a valid old entry. In the CAS case the writer's precheck sees that source, then another private-file write wins at the native publication boundary; the adapter port independently reads disk, compares the actual expected bytes, and refuses. A separate write-refusal case changes no bytes. These are actual macOS host/shared-writer control paths with real Linux file I/O at the port, not Darwin filesystem/lock qualification.

Exact observations in `logs/autoclose.log`, `logs/editor-finalA-autoclose.log`, `logs/editor-finalB-autoclose.log`:

| Scenario                     | Host mode/auto-close | Generated messages | Save diagnostics                    | Native delete | Draft on actual reopen       |
| ---------------------------- | -------------------- | ------------------ | ----------------------------------- | ------------- | ---------------------------- |
| CAS conflict                 | shortcut/true        | save, close        | 2 errors, 1 notification; no reload | Requested     | Absent                       |
| Write refused                | shortcut/true        | save, close        | 2 errors, 1 notification; no reload | Requested     | Absent                       |
| Healthy publication          | shortcut/true        | save, close        | 0 errors, 0 notifications; 1 reload | Requested     | Present                      |
| CAS conflict, auto-close off | shortcut/false       | save               | 2 errors, 1 notification; no reload | No            | Original page/draft retained |
| CAS conflict, menu open      | menu/true            | save               | 2 errors, 1 notification; no reload | No            | Original page/draft retained |

The save alone keeps the failed editor open; the following independent `close` is what retires it. `script.js:1277` calls `persist`, then `:1290-1293` closes without any save acknowledgement. Host `ui/hotstring_editor/init.lua:425-495` logs/notifies refusal but retains no candidate or close veto; `:514-515` unconditionally calls `M.close()`. The newly opened public editor initializes from surviving disk bytes and supplies no attempted draft. Error/notification payloads are explicitly checked not to carry the attempted output: their backstop is not a recoverable copy. No production draft cache/backup path is created by this chain. The audit's own transport files are proof artifacts and are removed after each case.

Regression: join the actual page-generated messages to the public host and real writer, refuse CAS/write separately, and require the draft to remain open/recoverable until exact successful save acknowledgement or explicit user discard. Preserve successful save+auto-close and the auto-close-off/menu controls. A loud failure log is insufficient to pass the preservation assertion.

Counterparts are not automatically affected: Windows `personal_toml_editor_webview.ahk:604` hardcodes `open_mode="menu"`, so this shortcut branch is not reachable through its current host. Linux's trusted shortcut mode can reach the shared branch but its close action currently has a separate no-op issue; it does not demonstrate this Mac draft destruction. Neither is counted as duplicate MVB-002. Native WebKit destruction was not run: the proof observes the exact host delete request and lost draft in the next actual initialization.
