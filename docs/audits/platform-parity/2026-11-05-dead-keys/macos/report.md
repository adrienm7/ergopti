# macOS dead-key boundary and multi-codepoint event audit

Pinned source: `f2c3ea43542c985fb20e5f0887976f1c02525341`.

Two defects are demonstrated in actual original Lua owners over the repository's registered Hammerspoon unit fixture. **DKM-001** misses a two-ASCII-codepoint event when choosing an automatic trigger bucket. **DKM-002** omits the unmatched prefix of a consumed event from its constructed output, although the logical buffer preserves it. Severity is medium for each; confidence is high for these fixture/model observations. Whether a particular physical dead-key combination creates such a payload, and what a real receiving application displays, remain unmeasured.

No device input, user keystrokes, native Hammerspoon session, OS dead-key state, or receiving application was inspected or driven. Event strings are explicit, synthetic in-memory fixture inputs. The unchanged `public-probe.lua` loads fixture construction from the existing navigation regression test and invokes the original registered Keymap keyDown callback. Keymap.add, Registry.mappings_for_tail, Expander.try_auto_expand, and SyntheticInput.leave_callback are checked against their exact original source filenames. The registry tail observer delegates to the original owner. Native event constructors and unrelated LLM/UI ports are repository fixtures; they do not establish physical behavior.

## DKM-001 — Two-ASCII-codepoint event probes the wrong tail bucket

At `modules/keymap/init.lua:1957`, the fast path treats any payload with at most two **bytes** as one codepoint. This is correct for one ASCII or two-byte Latin codepoint, but not for two ASCII codepoints. `run_trigger_checks` then uses the entire payload as the tail-bucket key because the computed character count is one. Registry indexes registrations by their final single codepoint, so the complete trigger is never offered to the automatic matcher.

Through the original registered callback, register strict automatic `^0` → `EXPANDED` and supply a single `^0` event: it passes through, retains buffer `^0`, emits nothing, and the captured tail lookups are `^0` then `0` (the latter is preview work, not a successful automatic expansion). Supply `^` and `0` as separate events: the second event is consumed and returns `EXPANDED`. Single-event controls `€0`, `éà`, and `^00` also expand under the same timing baseline because their byte lengths take the general codepoint-count path. This isolates the two-byte fast path from general multi-codepoint rejection.

Regression direction: through the original registered callback, compare identical two-ASCII trigger input grouped as one event versus two events, alongside one two-byte Latin character and longer Unicode/ASCII payloads. Assert automatic expansion and callback consumption, not just Registry's standalone bucket index. Native dead-key fallback grouping needs a separate real-host test if this is presented as a physical dead-key reproduction.

## DKM-002 — Unmatched prefix omitted from constructed output

Register automatic suffix `0` → `EXPANDED` with `final_result=false`; supply the single event `´0`. The entire event is consumed. The returned native-fixture event table contains 16 events whose keyDown Unicode text concatenates to **EXPANDED** only. The logical buffer becomes **´EXPANDED**. The unmatched prefix `´` is absent from the constructed output. The same discrepancy occurs for the explicitly supported multi-codepoint punctuation shape NNBSP+`?`, with suffix `?` registered. The source comment at `init.lua:1308` explicitly describes Karabiner NNBSP+`?` payloads and handles their tail lookup.

The split-prefix control passes `´` through before the event `0`; only `0` is consumed and the returned text is `EXPANDED`, which is appropriate because the prefix belonged to a different earlier event. In the single-event case that explanation does not apply: the whole payload is consumed in one callback, and no returned prefix is constructed. `try_auto_expand` passes only the replacement to the shared injection plan, clamps erasures at zero when the event is longer than the trigger, and splices the unmatched prefix into the logical buffer. Clamping negative deletes is necessary but does not reconstruct the held-back prefix. The serializer faithfully returns the resulting replacement events; it does not add missing text.

This finding concerns the constructed transaction and logical buffer discrepancy. It does **not** assert that a native application lost text, nor that every native dead-key fallback arrives grouped this way. Regression direction: match a suffix shorter than an admitted event, preserve the event's unmatched leading text exactly once in constructed output, and retain split-event/full-event/Unicode/NNBSP controls. Verify the original callback return and committed buffer agree before testing a real receiver.

## Dead-key boundary behavior and intentional differences

macOS uses native keyboard layouts for dead-key composition rather than Windows' legacy `DeadKey(Mapping)` InputHook. The observed public Keymap callback receives character payloads from `getCharacters(false)`. The retained upstream Hammerspoon 1.1.1 implementation calls `NSEvent.characters` in that mode; its API note explicitly gives Opt-E as an empty character result and Opt-Shift-E as a spacing accent. This establishes API semantics, not the grouping of every composition/fallback or IME behavior.

The fixture controls show an empty-character event does not append text, then a composed single `é` event extends `a` to `aé`. A visible spacing-accent event extends `a` to `a´`; Backspace removes the spacing accent and leaves `a`. In contrast, an empty event followed by Backspace makes the logical buffer empty. That last result is only a **candidate native synchronization concern**: the fixture does not model Cocoa's pending dead state or establish whether the actual receiver deletes visible `a` or merely cancels an accent. It is not counted as a confirmed finding.

Escape and navigation follow their existing prediction/buffer reset policies. The supplied empty-event Escape case retains `a`; the default arrow case clears it. Cmd/Ctrl shortcut and Option+Backspace branches intentionally use different buffer policies; the source treats Option alone as a character-producing modifier, not a generic shortcut. These behaviors are not a universal composition-cancellation contract. Cross-OS expiry, pause, focus, and native pending-state cancellation remain product/native questions and are not inferred from the Windows two-second timeout.

macOS consumes the completing event before output; Linux/Windows normally compensate for characters already delivered. That ownership difference is intentional and explains why a held-back event's prefix requires special care. The shared negative-delete clamp is already implemented and tested; this audit does not report its historical negative-count defect again.

## Timing baseline controls

The original probe inserts one empty-character code-14 event before registered scenarios. This is explicit fixture data, not proof of an OS dead key. An additional wrapper removes exactly that one scaffold line, leaving production and original probe bytes unchanged. With no earlier event, five single-event expansion controls decline because the first callback computes `dt = now - last_key_time` from the initial zero timestamp and the default mapping delay expires. Those first-event declines are retained as a timing control and are not presented as a new bug.

A separate scaffold-only wrapper replaces the one empty seed with ordinary `x` text followed by Backspace. Each registered scenario observes buffer `x` and then an empty buffer before its carrier. All eight registered carrier/control outcomes match the original seeded probe, including both defects. Thus neither logical finding requires a modeled native pending dead state. `no-marker-control.lua` and `ordinary-baseline-control.lua` assert the exact seed line appears once and transform only test scaffolding. `check-record.py` verifies all three 13-case records and this baseline equivalence.
