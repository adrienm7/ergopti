# Shared architecture memory

## Ownership and vocabulary

### project-shared-tree-layout

`_shared/` is a source of truth per layer, not a dumping ground. Drivers may own
adapters and runtime orchestration while consuming shared schemas, constants,
and generated data. Bypassing the shared source creates silent drift.

### project-structure-plan-owns-the-tree-shape

The target tree of every driver and of `_shared` is feature-first (decided by
the maintainer on 2026-11-11) and computed, not typed:
`tools/audit/structure/rules.cjs` maps each tracked file to
`<feature>/{engine,adapters,ui,data,native}/` or to `core/<domain>/` and
`platform/<domain>/`, and `docs/design/structure-plan.md` explains the
choices. Until its phase 2 lands, a new driver file takes the place those
rules give it, and `test-structure-folder-bounds.cjs` (2..20 entries per
folder, 40 in tests, depth-2 folders on every driver) and
`test-shared-literal-inventory.cjs` (hand-typed values per driver and kind)
may only go down. Move files with `tools/audit/structure/apply-step.cjs`, never
by hand: it rewrites the Lua names, `#Include` lines and repository paths, and
refuses a step that would let a driver shim and a `_shared` module answer the
same Lua name.

### project-the-tap-hold-file-is-one-layout-translated-at-the-boundary

`tap_hold.toml` has one layout on every OS (`_shared/tap_hold/SCHEMA.md`):
catalogue key ids, `<first>_then_<second>` pairs, seconds, `+`-joined
modifiers. macOS keeps merging its old Karabiner model in
`platform/remap/config.lua` and translates only at the file boundary
(`platform/remap/tap_hold_file.lua`, `_shared/lua/tap_hold/shared_file.lua`):
a save compares the model it started from with the one it ends with and
writes only the leaves that differ, so another driver's keys, fields and
spellings survive. Every writer stamps `[_meta] schema_version`: an unstamped
file is version 0 and the v0_to_v1 step drops delays equal to the retired
ones, so a macOS file without the stamp would lose a user's 350 ms on Linux.
Change the layout in SCHEMA.md, `shared_file.toml` and the corpus
`_shared/tests/corpus/tap_hold_shared_file/` together; each suite pins its own
writer's corpus file byte for byte and reads the other's.

### project-registry-flows-and-healthcheck-bridges-stay-per-driver

The layout registry store, the shortcuts catalogue, the healthcheck report runner
and the agent learning store are shared (PAR-72), but the layout install and
select flows and the healthcheck bridge stay in each driver: each converts the
layout for its own OS and reaches its own native collectors. Do not move them
into `_shared`; share only their rules and vectors.

### project-a-second-vocabulary-fails-silently

Use the same field names at every boundary. Translating a concept into a second
vocabulary often yields `nil` plus a plausible default rather than an exception.

### project-config-keys-are-generated-constants

Config keys, their leaf names and dispatchable menu command ids are generated by
`tools/codegen/codegen-config-keys.cjs` from `config.schema.json` and
`menu_manifest.json` into `_shared/lua/config_keys.lua` (`KEY`, `LEAF`,
`COMMAND`), `_shared/ui/_generated/config_keys.js` and
`windows/_generated/config_keys.ahk` (`ConfigKey`, `ConfigLeaf`, `MenuCommand`).
Every table raises on an unknown name, because a misspelt string key reads as
nil and lets the default apply silently. `test-config-key-literals.cjs` ratchets
the hand-typed literals per file against
`tools/lint/config-key-literal-baseline.json`: a rise fails, and a migration must
lower the baseline (`--shrink`). Read the constant in new code; build a storage
key from the full `KEY` value, never from a section prefix plus a leaf.

### project-log-reasons-phases-and-tags-are-closed-enums

`reason`, `phase`, `[TAG]` and evidence-record field literals must belong to the
closed enums in `_shared/modules/logger/vocabulary.json`, projected into
`_shared/core/ports/contracts.json` by `codegen-contracts-json.cjs`.
`test-logger-scalars-single-source.cjs` scans every driver with
`tools/lib/log-vocabulary-scan.cjs` and fails on an unknown value; prose or
runtime-built reasons and phases are held to a shrinking per-file baseline in
`tools/lint/log-vocabulary-free-form-baseline.json`. Reuse an existing value
and put detail in the message; adding a value is a deliberate vocabulary edit.

### project-lua-slow-segments-are-one-inventory

The macOS and Linux slow-segment logging (`[HotPath] Slow <segment>`) declares
what it measures once, in `_shared/lua/hotpath_segments.lua`: name, drivers,
reason, and a `slow_ms` only together with the measurement that justifies it.
The shared contract `_shared/lua/test/hotpath_segments_contract.lua` (run by
each driver's `test_hotpath_segments_declared.lua`) fails when a driver emits an
undeclared segment or drops a declared one; the Windows list stays in
`test-hotpath-segments-declared.cjs`. Linux spans in `infra/perf_counters.lua`
are always timed (two `luv.hrtime` reads, no string unless slow); a span that is
not an inventory segment (idle wait, tray, keystats flush) is timed but never
warns. `PhaseStats` bookkeeping is `_shared/lua/phase_stats_core.lua` on both
Lua drivers and its port `windows/infra/phase_stats.ahk`, with the same phases
and evidence line. A new typing-path span joins the inventory, never a private list.

### project-fixed-field-lists-drop-flags

When a record schema grows, fixed allowlists silently discard new fields. Prefer
schema-owned projection or update every serializer, bridge, and test together.

### feedback-loader-target-explicit

AHK loaders and writers that populate a shared `Map` take that map explicitly.
They must not reach through a global with the same conceptual name.

### project-a-path-resolver-must-know-every-layout-that-ships

Path resolution is a product contract. Test packaged, source-tree, installed,
and test-harness layouts rather than assuming one directory depth.

### project-a-depth-cap-is-right-for-a-provider-and-wrong-for-a-filesystem

Depth limits belong to bounded provider APIs, not generic filesystem discovery.
Use explicit roots or cycle-safe traversal for real directory trees.

## Cross-driver UI and data

### feedback-complex-settings-use-a-shared-webview

Reserve native prompts for very simple decisions. Configuration reviews and
long settings lists use one shared WebView on Windows, macOS and Linux, with
bounded window geometry, a scrollable list and a permanently visible action
footer. The obsolete-settings cleanup is the reference: preview every entry,
keep confirmation explicit, and preserve the backup-first transaction.

### project-a-caption-label-is-brandless

The window composer (`WindowTitle`, `window_titles.compose`) is the only place
that adds the product name, and the factories name a manifest window from its
`title_key`: Windows `WebViewHost._CaptionLabel`, macOS `show_webview` with an
`app_id`, Linux `webview_manager.app_caption`. A caller that brands a label, or
a locale caption that already starts with the brand, shows it twice (the
cleanup window and the API-entry dialog both did). The static audit could not
see either: it resolves call arguments, not an option read back later or a
parameter passed through a helper. `(window-title-brand-once)` builds every
manifest window in all 21 locales on each driver; open a new window by its app
identity rather than a translated title.

### project-bundled-apps-are-separate-processes-on-one-container

App Cloner and Encryptor exist on the three drivers and always run as a process
of their own: macOS bundles, Linux `linux/apps/*.lua` under the daemon's
interpreter, Windows `--bundled-app` (`apps/bundled_app_entry.ahk` from source,
the main executable when compiled, dispatched in `ErgoptiPlus.ahk` before the
driver boots, so `BundledApp_Main` must never return). A 600000-iteration key
derivation or a modal dialog inside a driver stalls its keyboard hook. The
Encryptor file is OpenSSL's `enc` envelope declared in
`_shared/data/encryptor/format.json`; change it only together with
`_shared/tests/corpus/encryptor/vectors.json`, which every driver decrypts and
re-creates byte for byte. App Cloner isolation is
`_shared/data/app_cloner/families.json`; macOS's hand-written detection is held
to it by `test-app-cloner-families.cjs`. A Windows program of no family cannot
get its own profile (a shortcut cannot redirect `%APPDATA%`), so its clone is
labelled a second shortcut, never presented as isolated.

### project-a-cloud-provider-is-catalogue-data

A cloud provider is a row of `_shared/modules/llm/api_providers.json`; the three
drivers read it generically, so adding one needs no driver code. Two shapes
carry what a plain key and address cannot: a `base_url` holding `{name}`
placeholders is an address the add-entry form fills (`api_url_template.lua`,
AHK port), and an `auth` block makes the requests carry an access token
exchanged from the key (`api_token_exchange.lua`); its optional `assertion`
block signs an RS256 JWT for a key of the named JSON type (a Google service
account) with the pure-Lua `_shared/lua/crypto/` signer, which a driver must
step through `api_token_exchange.drive` over timer ticks: a whole signature
takes about 0.25 s of Lua 5.4 and would stall the event taps. Every row needs a
thinking-off vector and a recorded listing or its reason
(`test_api_provider_catalogue.lua`); read the provider's own documentation for
each field and name it in the row's `_source`.

### feedback-ui-must-be-i18n

All user-facing text uses the locale system in every supported language. English
is the canonical key set; developer logs remain English.

### project-a-page-that-builds-labels-from-data-waits-for-i18n

`_shared/ui/i18n.js` fills `data-i18n` attributes and stores the active locale
in `window._i18n_strings`, but a page that builds its text from data (the layer
editor's keys, actions and picker) has nothing to read until the locale fetch
lands. Draw again on the `i18n:applied` DOM event i18n.js fires after every
apply; a page drawn once at `init()` keeps raw keys on screen.

### project-layer-editor-legends-are-the-hosts

The layer editor never spells a key's character itself: a registry key sent
by scan code (`ahk_send: null`, the generated data's `character`) shows the
legend its host read from the layout the user types with, and its registry
code when the host had none. Windows reads the layout emulation first (digit
row, registry layout, Ergopti base from its `.keylayout`), then ToUnicodeEx
with flag 0x4 on `KS_ResolveKeyboardLayout`; macOS `hs.keycodes.map` in the
ISO form of `platform/remap/nav_layer.lua`; Linux the daemon's loaded keymap
(`keyboard_layout.base_symbol`). Only Windows emulates a layout. The shared
Lua reads `ahk_send` as `type ~= "string"` because json.lua decodes a null to
a sentinel table. Action: change the contract with
`_shared/tests/corpus/layer_editor/legends.json` and
`test-layer-editor-legends.cjs`, which also pins the Windows tap-hold id to
registry code table the layer-key mark needs.

### project-inline-webviews-cannot-fetch-their-locale

macOS loads every shared page inline (`wv:html`, about:blank origin) and
WKWebView refuses its `file://` locale fetch; WebKitGTK refuses it too unless
`allow-file-access-from-file-urls`, which the Linux driver never sets. Only
Windows' virtual host serves the fetch. The page's strings therefore come from
the host: the macOS and Linux builders seed `window._i18n_strings` (the
`catalogue()` of the locale core: active over en over fr) in the boot script.
The store in i18n.js only merges; a replacing `apply()` let the always-failing
fetch wipe the host's strings and the diagnostics page showed raw keys.

### project-shared-ui-logic-is-a-classic-script

`package.json` declares `"type": "module"`, so Node loads any `.js` under
`_shared/ui/` as an ES module and a `module.exports` branch never runs. Page
logic that Node tests need (the layer editor's `layer_model.js`) is a classic
script defining one top-level `var`; the tests run the page's scripts in one
`vm` context, as the browser does, and read that global from it.

### project-shared-pages-read-host-capabilities

A shared page never compares a platform or driver name
(`tools/test/test-shared-ui-no-platform-branches.cjs` keeps the count at
zero). The host states what differs: a capability in the page's init payload
(`capabilities.diagnostic_collection`, `capabilities.gesture_registration`,
the action picker's `executableSyntax` and `commandIsPrimary`), a value
(`shortcut_menu_path`), catalogue data (`sub_switch.independent`), or a
document-level declaration read through `hostHasCapability(name)` in
`host_bridge.js` (`window.__ergopti_host_capabilities`, which the Linux host
injects with `document_bridge`). A page refuses an init payload that omits a
capability it needs instead of guessing it. Page harnesses that stub
`host_bridge.js` install the real probe with
`tools/test/support/host-capabilities.cjs`.

### project-locale-placeholder-parity-is-not-a-defect

Locale values may reorder placeholders. Validate placeholder sets and types, not
byte-identical order, unless the formatter itself requires order.

### project-one-menu-two-shared-descriptions

Shared menu metadata has one canonical description per action. Drivers own
rendering but must not fork labels or help text.

### project-the-tray-menu-is-defined-in-menu-toml

The tray menu is declared only in `_shared/modules/menu/menu.toml`;
`npm run build:menu` compiles it into `menu_manifest.json`, which the three
drivers read. A driver supplies the DATA of a named `list` provider and the
handlers of declared commands, never a row of its own: the `dynamic` type,
which handed a row back to platform code, is refused by the compiler. Action:
add, remove or rename a row in `menu.toml`; read paths through
`tools/lib/paths.cjs` (`MENU_SOURCE_REL`) or `tools/lib/menu-source.cjs`.
`test-menu-manifest.cjs` refuses a `[menu]` table in the feature manifest.

### project-feature-requirements-are-derived-from-generator-inputs

Each manifest feature's `requires = { macos, linux, windows }` is checked
against a derivation, never against prose. A source scan of macOS modules only
sees shortcuts and bindings: gestures, CapsWord, script chords and the metrics
ledger reach Karabiner through the injected remap facade (`_karabiner`),
`platform.remap.ke_variables` and `karabiner_kc.log`, so the `karabiner` use is
the generator's own `M.REQUIREMENT_STATE_FEATURES` (each `state.<field>` it
reads) plus `M.REQUIREMENT_FACADE_FEATURES`. Linux and Windows uses come from
the source signatures of `_shared/modules/features/requirements.toml`, with
comments stripped (a replaced `xdotool key` still named in a comment is no
use). Action: when the generator reads a new state field or a module starts
calling the facade or spawning a vocabulary program, map it to its features
(or give the plumbing reason), update the `requires` lists the gate names, and
run `npm run codegen:feature-requirements`; a driver-wide need (Hammerspoon,
AutoHotkey, LuaJIT, GTK) or an OS tool (PowerShell 5.1, osascript) is not a
vocabulary id.

### project-a-caller-owned-menu-is-still-the-renderers-to-fill

Owning a native menu object does not transfer content ownership. The shared
manifest remains authoritative for ordering and entries.

### project-action-catalogue-is-generated

No driver parses `_shared/modules/actions/actions.toml`: run
`npm run codegen:action-catalogue` after editing it, and each driver loads its
platform-filtered `_generated/action_catalogue.*`. The macOS and Linux files
only call `_shared/lua/actions/catalogue.lua`, which filters the one shared
`catalogue_data.lua` (every entry lists the Lua drivers that keep it, heading
pruning already decided by the generator) and adds the driver's own extras;
`tools/test/test-action-catalogue-shared-projection.cjs` loads both in Lua and
compares them with the generator's per-driver model. Each driver suite compares
that catalogue with its runnable registry in both directions
(`(action-catalogue-parity)`). On Linux the runnable set is exactly the
executor's tables, so a new Linux action is a row in one of them, never an
`elseif` the parity test cannot see. Actions another module owns (script
control, the shortcuts manager's text actions) are injected at init through
`modules/shortcuts/action_handlers.lua`; the parity test builds the same table.

### project-action-confirm-is-a-dispatcher-gate

A catalogue action with `confirm = true` is asked for by each driver's single
dispatch choke point, never by the action: macOS `execute_single` (non-blocking
`modules/gestures/action_confirm.lua`), Windows `GestureInvokeAction` (deferred
MsgBox), Linux a question of the owned dialog host chained in front of the command of
`modules/gestures/system_actions.lua`. Linux therefore refuses to load a confirm
action that is not one of those commands. Action: declare `confirm` in the
catalogue and add the confirm-gate test case; do not add a second prompt inside
the handler. The question's own window takes the focus, so an action that
acts on the active window must not read it after the answer: macOS reads the
frontmost application before its alert (from NSWorkspace: the accessibility API
cannot read a hung or windowless application) and hands it to the action,
Windows gives the window it was asked from its focus back and, when it cannot,
refuses only an action that reads the active window
(`GESTURE_ACTIONS_ON_ACTIVE_WINDOW`), Linux reads it (`TARGETS`) before the
question. Windows
native calls of system actions go through
`adapters/system_control.ahk`: the modules/infra/platform OS-call ratchet has
almost no headroom left.

### project-text-case-is-one-rule

Selection case conversion follows one rule, pinned by
`_shared/tests/corpus/text_case/vectors.json`, which the three suites replay.
macOS and Linux call `_shared/lua/unicode_case` over a generated Unicode table
(`npm run codegen:unicode-case` refuses any Node but the `.node-version` pin);
Windows calls `infra/text_case.ahk` over StrUpper/StrLower, so ß, the final
sigma and title digraphs are Lua-only vectors. Never case user text with Lua
`string.upper`/`string.lower` (bytes only) or AHK `Format("{:T}")` (a capital
after a digit, none after a hyphen).

### project-api-entry-names-are-computed

Maintainer rule (2026-09-30): the user never names a remote API entry. Every
tray names it `<provider>/<model>`, with the model and base URL its requests
use, adding the host and then the order when two entries share that name:
`_shared/lua/llm/api_entry_names.lua` (macOS `api_panel`, Linux
`llm_backend_rows`) and its Windows port `_LLM_ApiEntryNames` in
`menu_api_entries.ahk`, all replaying
`_shared/tests/corpus/llm/api_entry_names_vectors.json`. The stored name field
(Windows `Name` and Linux `label`, which older builds still require, and the
optional macOS `label`) is written with the automatic name or left as stored,
and never read. Action: a new place that shows an entry names it through the
driver's naming function over the whole entry list, never from a stored field.

### project-a-toggle-is-opt-in-per-driver

A shared setting is not automatically supported by every driver. Add explicit
capability wiring and parity tests rather than inferring support from schema
presence.

### project-a-row-that-opens-a-submenu-is-never-clicked

No tray fires the action of a row that opens a submenu: AppKit never sends it,
appindicator binds `fn` only on leaves, and Win32 sends no command. A category
switch is therefore the manifest `toggle` row, the first row of its submenu,
and every driver that shows it registers its command. Both renderers report a
missing toggle command and a provider row carrying `action` plus a subtree as
errors; `test-menu-toggle-registered.cjs` pins the registrations.

### project-a-setting-with-values-is-one-choice-row

An enum feature shown in the tray is ONE manifest `choice` row (`path` = the
feature, `i18n` = the row label), not one row per value. `build-menu-manifest.js`
projects the feature's `enum_values` into the row's `choices` with label keys
`<i18n>.<value>` and refuses a path that is not an enum feature or a platform
the feature lacks. Both renderers draw it; the driver registers
`commands[<row id>]`, called with the chosen value, and a state getter under
the feature path. The macOS menubar icon (`ui.menubar_icon`) is the first one;
the update channel and frequency rows have the same shape.

### project-a-window-has-no-shortcut-row-of-its-own

Maintainer rule (2026-10-01, « on ne mélange pas les deux »): a menu never
offers its own row to set the shortcut of a window it opens. A shortcut is
assigned in the Gestures or the Shortcuts menu, to the catalogue action that
opens the window (`open_metrics_typing`, `open_metrics_apps`, ...). The
Metrics menu lost its two shortcut rows that way, and its two opening rows
form one group. Action: give a new window a catalogue action for every driver,
never a shortcut row or a dedicated shortcut setting;
`metrics-no-shortcut-rows` holds the Metrics menu.

### project-script-chords-are-active-by-default

An empty configuration alters no input: every `family = "feature"` manifest row
defaults to off (`tools/lib/feature-family-rule.cjs`). The one exception is the
script-management chords. The maintainer decided on 2026-09-30 that they are no
typing feature, since they pause, reload, quit and edit the driver. Such an
entry carries `active_by_default = true`, its `rule_exception` and a default
equal to its recommended value. The builder refuses any other shape, and
`test-defaults-single-source.cjs` pins the approved list. A config.toml that names "none" keeps a chord off, and a
missing key takes the preset. The wizard lists only entries whose preset
differs from their default, so the chords left its Shortcuts page. Action:
never extend the list without a maintainer decision. A clear that must give
the system's behaviour writes the off value explicitly, because deleting the
key restores the preset: such an entry declares it as `cleared`, and the scope
builders (`config_defaults.scope_operations`, `ManifestScopeOperations`) write
it in every clear, the Shortcuts and global ones included. The submenu's switch
(`shortcuts.script_control.chords_enabled`) only narrows what the slots
enable, so it is a parameter that starts on, like the key-combinations switch.

### project-script-chords-are-one-model-on-three-drivers

Maintainer decision (2026-09-30, « On met tout en commun sur les 3 OS »): the
script chords are the same four `shortcuts.script_control.script_altgr_*`
entries on every driver (Enter pause, Backspace reload, Delete personal
shortcuts, Escape quit), with AltGr on Windows and Linux and the right Option
key on macOS. `_shared/modules/actions/script_chords.json` names each slot's
key per driver and the actions a paused driver still runs; Linux and macOS
apply `_shared/lua/script_chords.lua`, Windows `ScriptShortcutSlotRunsAction`,
and `test-script-chords-three-os.cjs` pins the three, the submenu
(`script_control_group`) and the defaults. A chord belongs to the driver only
while its slot runs an action: an unassigned slot or the switch off leaves it
native. The submenu's restore and clear are the Shortcuts scope narrowed to
the chords (`config_scope_transaction` `select`), at once and without a
question. The macOS keys `enabled`, `return_key`, `backspace` and `escape`
became `chords_enabled` and the slots in config schema v7. Action: change a
slot, a preset or the paused actions on the three drivers and in the JSON at
once, never on one driver.

### project-restore-and-clear-read-two-shared-keys

Every row that puts a section back to Ergopti's preset reads
`common.restore_recommended`, and every row that removes a section's settings
so the OS behaves as without Ergopti reads `common.clear_to_system`, whatever
the menu. A new reset or clear row takes one of the two keys, never a per-menu
label; `test-menu-reset-terminology.cjs` holds the manifest rows, the rows
drivers build by hand and the retired keys. Neither asks: each owner backs up
first, and the maintainer retired the restore question, then the clear one
(2026-09-30, per menu and global). The macOS scoped owners and global scope
refuse a `confirm` port; `test-restore-recommended-no-confirm.cjs` rejects a
question in a function given a scope mode or naming either label.

### project-a-clear-can-keep-the-switch

A scope's `clear_exclude` lists the paths its clear leaves as they are, as
`restore_exclude` does for a restore: the planners
(`config_defaults.scope_operations`, `ManifestScopeOperations`) emit no row for
them, in that scope and in the global one that includes it, so each owner keeps
the stored value. The Tap-Holds scope keeps its switch
(`category_enabled.tap_holds` on Windows, `tap_holds.enabled` on macOS and
Linux): the maintainer's rule of 2026-10-01 is that « Tout effacer » empties
every key's tap and hold and the user adds keys from there, and a switch
turned off with them made the next key do nothing. The Gestures scope keeps
`gestures.enabled` for the same reason; its macOS owner then reads the live
switch (no row names it) and leaves the session demotion of that switch, which
only a scope publishing the switch ends. Action: a menu whose clear must keep
its switch declares it there, never in an owner; the
`tap-hold-clear-keeps-switch` and `gestures-clear-keeps-switch` tests hold the
plan and each driver's owner. The Shortcuts, Hotstrings and layout clears
still turn their switches off: ask the maintainer before changing them.

### project-a-settings-menu-opens-with-switch-restore-clear

Every manifest menu that shows a scope row opens with its `toggle` (when it
has one), `scope_restore`, `scope_clear`, then `---`, and shows no scope row
after that separator (the maintainer's rule of 2026-09-30); Configuration
opens with the global pair. The ids are the same in every menu, so each
driver registers `scope_restore`/`scope_clear` on that menu's scope owner.
`test-menu-first-group.cjs` checks each platform's projection; its declared
exceptions are restore-only menus (AI, Metrics: the maintainer said clearing
them means nothing, while the global clear still composes their owners).
Action: add a scope row to the first group of the manifest menu, never below
it and never natively. Every other row belongs in the manifest too (the
maintainer's rule): `test-native-menu-rows.cjs` ratchets the rows drivers still
build themselves against `native-menu-rows-baseline.json`, which lists each
site as file:line; lower it with `--update-baseline` as rows move.

### project-pause-layout-ids-are-per-driver

`layout.on_pause` and `layout.on_resume` hold a layout id in each driver's own
vocabulary: a macOS KeyboardLayout Name, a Linux GNOME source
(`xkb:fr+ergopti`) or X11 group (`fr(ergopti)`), a Windows KLID (`0000040C`,
never the per-session HKL). A config copied between OS therefore names a
layout the other driver does not list; the switch then logs a refusal and the
picker shows the raw id. `""` is « no change ». Which event selects which
target (a quit uses the pause one, only an exact `true` enables) is
`_shared/lua/layout/pause_switch_policy.lua` and its AHK twin, both pinned by
`_shared/tests/corpus/layouts/pause_switch_vectors.json`; change the corpus
first. A reload, a signal or a logoff is not a quit and never switches. A start
applies `startup_event(paused)` once on every driver, unless a pause transition
already switched since init (Linux `pause_layout_switch.on_start`, Windows
`PauseLayoutSwitch_ApplyStartup`, macOS the startup timer in `ui/menu/init.lua`).

### project-quit-refusals-are-one-shared-decision

The tray's Quit follows `_shared/lua/quit_admission.lua` on macOS and Linux
(maintainer, 2026-10-26: the user wants out, so Quit wins). Five facts feed
`decide()`: owner available, an exit owns the process, a reload is in flight, a
global writer is active, a hotstring publication is pending. A missing owner or
an exit already under way is refused with the one `notify.quit_refused` notice;
a running writer or publication is waited for (`await` polls up to the
user-quit deadline, then refuses); a reload in flight is abandoned (macOS: the
coordinator upgrades the reload to the exit and the click gate never holds the
Quit row; Linux: `daemon_restart.cancel` replaces the systemd restart with a
stop job or drops a marker the relay checks). The contract test
`_shared/lua/test/quit_admission_contract.lua` is replayed by both drivers; a new
cause is a new fact there, never a driver-local `if`. Linux reads "a writer is
active" from `infra/scope_registry.lua`, where every scope module registers a
probe over the owner it keeps. Windows ports the decision in
`infra/quit_admission.ahk` and adds one refusal: an OnExit gate can still veto the
admitted exit, which returns from `ExitApp`, so a veto with no retry owner gets the
same notice.

### project-a-typing-key-is-decided-by-the-order-of-the-releases

A tap-hold key takes its hold at key-down, so a chord or a click under it
never waits. For a key struck in the flow of text that rule types the next
letter under the hold: with Shift on the hold of Space, « word, Space, a »
gave « wordA » (Windows, then the space; Linux, no space at all, the other
key cancelling the tap). The keys of `[tap_hold.rollover]` in
`_shared/tap_hold/defaults.toml` (Escape, Tab, Enter, Space, Backspace,
Delete) that keep their own key on a tap and have a hold therefore stay
undecided: a tap when the key comes up first or a second key is struck
before either came up, the hold when the key struck under it comes up first
or the threshold passes. The keys struck meanwhile wait and are replayed in
order, after the tap or under the hold. Such a tap has no minimum duration
and is not cancelled by the keys around it, only by a click or the wheel. A
key whose tap is an action, and every modifier key, keeps the immediate
hold. Linux: `tap_hold_engine.lua` (`roll`, `resolve_roll`), which buffers
events; Windows: `tap_hold_roll.ahk`. macOS is not covered: Karabiner
decides a dual-role key at the next key's press (`to` + `to_if_alone`) and
has no rule on the order of the releases. Action: a new typing key joins the
shared list, and on Windows the block of `tap_hold_roll_keys.ahk`;
`tap-hold-roll-is-a-tap-2026-10-01` holds both engines.

### project-key-combinations-are-ordered-pairs

A key combination is an ordered pair of keys of `[tap_hold.catalog]`, the key
held first then the key struck under it, on macOS (Karabiner, `mod_combos`)
on Windows (`infra/key_combinations.ahk`, since 2026-10-02) and on Linux
(`modules/shortcuts/key_combinations.lua`, sharing the Windows config sections).

ship a recommendation are manifest features; every other pair is an owned key
of those sections (`TomlConfigForeignOwner`). The chord slot is
`[mod_combos.config.<pair>] combo` on all three: a key some chord begins waits
for the second key, so on Windows its hotkey swallows the press and sends it
again when no chord comes (`infra/key_combinations.ahk` section 6). AltGr is no
chord member on Windows, nor LCtrl where AltGr adds a fake one: suppressing
either kills AltGr. Only a key with a chord assigned ever waits. The group's two lists, one
per hand of the first key, and the separator between them are declared in the
manifest for both drivers; a provider returns the pairs only. Each pair also
reads `key_combination_pair_menu`: the shared declaration owns its clear row,
separator and slot list. Native providers supply their supported picker slots;
`key_combination_pair_assigned` disables Clear on an unassigned pair. macOS
attaches the already-rendered child as `submenu`, preserving its command and
disabled state without a second translation/render pass. Action: a new
slot or row of this group goes in the manifest first, and a Windows pair id
never uses a double underscore, which is the separator of a binding id.

The group also declares its bulk commands in this shared menu. Its
`key_combinations` scope owns pair assignments and combination action parameters;
its clear keeps the group switch. Windows inventories valid pair identities
from fresh disk inside the admitted configuration lifecycle, preserving unknown
slots and other shortcuts. macOS uses the same remap transaction as Shortcuts,
restricted to its combination section. Presets still come from the shared
manifest, never from a menu-local copy of the three historical recommendations.

### project-llm-tooltip-chords-are-exact

the bare arrows. `test-llm-nav-chord-contract.cjs` parses those strings and

### project-route-plan-is-for-environment-only-clients

### project-proxy-override-wins-before-the-pac-lookup

The user's proxy override (`_shared/modules/network/proxy_override.json` for
the storage key and default, `_shared/lua/network/proxy_override.lua` for the
value grammar) is empty (automatic), `direct`, or one relay `route_plan.lua`
accepts. `proxy_policy.route` applies it right after loopback, so it wins over
an exported relay and the PAC/WPAD lookup never runs. Linux hands it to every
route through `infra/proxy_policy.lua` (managed HTTP gets the existing
`selected`/`direct` curl selections, the Ollama daemon its `HTTPS_PROXY` or
`NO_PROXY=*`). macOS exports `ERGOPTI_PROXY_OVERRIDE` at the head of every
`network_env.lua` prelude and `network-retry.sh` turns it into the explicit
route before capturing the inherited one; the signed Swift workers resolve
natively and never read it, so an override selects the environment-driven
client instead (opaque prelude, no `install_huggingface_transport`). macOS
`hs.http` requests (update checks) still follow the system settings. Windows
keeps the key in `config.toml`, holds the choice in the driver's memory and sets
`ERGOPTI_PROXY_OVERRIDE` only on the private environment of a network worker
(`ProxyOverride_SpawnWorker`, `adapters/proxy_override.ahk`), where
`Resolve-ErgoptiNativeNetworkRoutes` applies it. It never enters the driver's own
environment: `run_command`, `Run` and opened programs would inherit it. WinHTTP and
HttpWebRequest reach a plain http relay only, so an https relay, a socks5 relay or
credentials in the address go through the loopback hop of that file (C# in the
worker's own process, answering that process only); the owned daemon gets the real
relay in `HTTPS_PROXY`. Action: a new download client on macOS must take its
prelude from `network_env.lua`, a new native worker must read the override before
claiming it honours it, and a new Windows client must route through
`Resolve-ErgoptiNativeNetworkRoutes` or `SystemProxy_*`, start through
`ProxyOverride_SpawnWorker`, and join `test-windows-proxy-override-e2e.cjs`.

### project-metrics-purge-tombstone

A dashboard Purge is one `events_system` row (`action = 'metrics_purge'`) the
owning writer appends to its ledger; `_shared/data/db/purge_schema.sql` (run

### errors-only-log-sink

### project-crash-report-and-log-volume-are-shared-lua

`_shared/modules/paths/app_dirs.toml` is the single source of every Ergopti
data folder: `codegen-app-dirs.cjs` generates `_shared/lua/app_dirs.lua`,
`windows/_generated/app_dirs.ahk` and the launcher's `AppDirs.generated.swift`
from it, and Node tools read it through `tools/test/lib/app-dirs.cjs`. It owns
the folder name (`Ergopti` on macOS and Windows, `ergopti` under every XDG base
on Linux, never "Plus"), each OS root and its purpose folders, each OS default
logs folder, the LogsDirPath key, every log file-name prefix and the old
folder names of the one-time boot migration. One root per OS, named once:
macOS `~/Library/Application Support/Ergopti/` (beside `~/Library/Logs/Ergopti/`
and `~/Library/Caches/Ergopti/`), Windows `%LOCALAPPDATA%\Ergopti\` (the managed
Ollama runtime is `ollama\` inside it, with its own protected DACL;
`Open-OllamaManagedRoot` admits it only below a direct LocalAppData child that
grants no write, delete or re-permission right to another principal, held open
without DELETE sharing), Linux one `ergopti` folder per XDG base.
A new data folder is a purpose folder under that root declared in the TOML,
never a new spelling; `test-legacy-folder-names.cjs` rejects an old spelling
outside the migration tables. The macOS owned Karabiner runtime keeps
`ErgoptiPlus` (`[owned_runtime.macos]`) until its rebuild. Each driver has one
resolver consumers call at the moment of use: macOS `Logger.logs_dir()` /
`today_log_path()` / `today_errors_path()` / `crash_reports_dir()`, Windows
`LoggerLogsDir()` and siblings, Linux `logger_sink.log_dir()` and siblings.
Never cache a dated path: the macOS menu once kept the one chosen at boot and
opened yesterday's file after midnight.
`test-log-file-names-single-source.cjs` rejects a new prefix literal. A
LogsDirPath that is neither the default nor named after the OS folder name
gets that subfolder, because retention (and, on macOS, the owner-only chmod)
must never touch a folder the user merely picked.

### project-diagnostic-snapshot-contract

Each driver logs one post-boot `[Diagnostics] Diagnostic snapshot (...)` line
whose fields come from `_shared/modules/logger/diagnostic_snapshot.json`. Add a
field there, in both formatters and in every collector; the parity test and the
three driver suites fail otherwise. macOS emits it from the menu prime, not from
`init.lua`, and freezes `boot_ms` at the `Boot complete` mark; renaming that
mark turns `boot_ms` into `unknown`.

### project-instrumentation-absence-is-invisible

Missing profiling instrumentation produces deceptively clean output. Assert the
expected segment and boot-stamp inventory before interpreting timings.

### project-profile-label-placeholder-convention

Profiler labels and placeholders are schema. Producers and reports must use the
same exact names so missing segments cannot masquerade as zero cost.

### project-shared-export-schema-is-closed

The shared diagnostic export carries typed technical facts only, in English,
with no raw logs and no automatic upload; local log links stay out of
attachments. A new field needs a schema change and a privacy decision, not a
free-form string.

## Intentional asymmetries

### project-category-gating-ahk-only

Runtime category gating through `CategoryEnabled[...]` is intentionally AHK-only
unless another driver explicitly implements equivalent ownership.

### project-declared-answered-and-absent

Distinguish declared capability, answered query, and absent value. Collapsing
them into false changes fallback and UI behavior.

### project-the-wrong-dialect-is-invisible

Shared data can be syntactically valid in the wrong consumer dialect. Validate
with each real parser, not only a generic JSON/TOML check.

### project-dynamic-places-list-materialises

Dynamic lists become persisted user choices. Preserve stable identifiers and
handle entries disappearing between discovery and use.

### feedback-windows-are-focused-never-topmost

Maintainer rule (2026-09-29): an ErgoptiPlus window is shown, raised and
focused when it opens or is requested again, and never given a level or
topmost flag. On macOS `hs.webview:bringToFront()` does not raise a window: it
SETS the level (floating, or screen saver with `true`), so the diagnostics
window stayed above every app. Present windows with `ui_builder.force_focus`
(macOS), `Gui.Show` for a first open and `WMPresentWindow` for a window
requested again (Windows; `Gui_Create` refuses a topmost option) and
`webview_manager._present_gtk_window` (Linux). Only the overlay allowlist in
`tools/test/test-ui-focus-fix.cjs` (tooltips, previews, WPM widget, spotlight)
may stay on top, each entry pinned to its exact site count; the overlay
adapters are topmost by default, so every file loading one is listed. That
gate scans the three drivers, the shared Lua, extensions and Ergopti's own
vendor scripts.

### project-streaming-multi-polarity

The canonical `llm.display.streaming_multi = true` means progressive display on
every driver. Windows inverts it only at its native engine field
`show_all_at_once`; flipping the polarity anywhere else shows predictions all at
once where the user asked for streaming.

### project-local-reload-command-reports-three-states

The local reload command (`tools/control/request_driver_reload.ps1` on
Windows, `request_driver_reload.sh` on macOS and Linux) authenticates with the
token of a session file in a user-private folder declared by
`_shared/modules/control/driver_control.json`, and is rung by the existing
Diagnostics window-control owner (Windows), a folder pathwatcher (macOS) or
SIGUSR1 (Linux). The driver hands an admitted request to its own reload owner
(`ReloadPreservingSuspend`, `TerminationCoordinator.request_reload_owned`,
the tray's `perform_reload`) and writes `requested` with the successor pid;
only that successor, once ready, writes `completed`. A Windows request carries
a refusal callback, so it is refused as `busy` instead of joining a pending or
deferred reload. Action: never report a launch or an exit as completion, and
change the folders or file names only in the declaration, then in the POSIX
tool, which the Linux suite checks against it.

### project-diagnostics-day-log-attachment

The diagnostics window can save a redacted copy of today's complete log beside
the report, only when the user ticks "Also save a redacted copy of today's
complete log" (unticked at every snapshot; Copy and the Debug menu's Report a
bug never carry it). The collector is `_shared/lua/diagnostics/day_log.lua`
with its AHK port `windows/ui/healthcheck/day_log.ahk`, both replaying
`day_log_vectors.json`; limits (the refusal cap, the preview size, the file
name) live in `_shared/modules/diagnostics/day_log.json`. The host keeps the
redacted text per snapshot (`healthcheck/day_log.lua` on macOS and Linux); the
page only ever receives the first and last redacted lines and the closed record
`day_log_attachment` (included, bytes, lines) of `share_policy`, which a report
contains only when its save or report action asked for the log. Redaction masks
the configuration directory's folder and file names (`config_dir` in the
context, `config_known_names` stay readable) and whole profile folders with
spaces. Nothing is uploaded: the user attaches the file by hand, after which it
is on GitHub (public repositories serve uploads to anyone with the link, and
GitHub's attachment documentation describes no revocation). Action: change the
cap or preview in `day_log.json` only; add a log rule to `redaction.json` and
its vectors, never a driver-local filter; keep any new page action out of Copy.

### project-keystats-query-catalogue-and-shared-walker

Keystats SQL that more than one driver runs lives once in
`_shared/data/db/queries.sql` (named queries, `{{where}}` for the driver's own
filter, `{{text col}}` for TEXT columns); `tools/codegen/codegen-keystats-queries.cjs`
compiles it to `_shared/lua/keystats/queries.lua` (macOS renders the `native`
dialect, Linux the `cli_json` one, which selects text through `json_quote`
because the CLI's JSON mode cuts TEXT at NUL) and `windows/_generated/keystats_queries.ahk`
(`KeystatsQuery`). `tools/test/test-keystats-query-catalogue.cjs` proves every
query on `query_fixture.sql` against `query_results.json` in both dialects, and
the AHK suite replays the same fixture. The typing walk of macOS and Linux is
`_shared/lua/keystats/walker.lua` (ports: `finger_of`, a per-keystroke slot, a
session gap); Windows keeps its AHK walker, and all three replay
`aggregation_vectors.json` (the Lua side through the shared checker
`_shared/lua/test/keystats_aggregation_corpus.lua`, which fails on an expected
key it cannot read). Action: add or change a shared query in `queries.sql`,
regenerate, and update the fixture rows; change walk behaviour in the shared
walker with a corpus vector and its Windows branch in
`test_corpus_keystats_aggregation.ahk`. `node tools/audit/keystats-sql-census.cjs`
lists what is still hand-typed per driver.
