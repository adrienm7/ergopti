## URM-001 — Repeat publishes a secret-derived scalar as public

Severity **medium**; confidence **high**. Named property: `private_output_propagation`. No G1–G5 violation is asserted: this is a privacy guarantee, not a missing-output, concurrency or measured-latency finding.

Enable repeat and personal SSN prefix expansion, use an ordinary permitted field, type the synthetic SSN prefix `28401`, then press the magic key immediately after the private expansion. The actual rules engine expands the prefix to synthetic `2840175123456`, tagged private. The actual public Keymap eventtap then admits repeat and constructs one extra `6` with `is_private=false`. It calls the actual logger boundary with `Repeat feature: repeated '6'.`. DEBUG output reaches the logger boundary; a configured sink accepting DEBUG is a condition for disk disclosure. The actual `keystats.recorded_char('6', false)` returns `6`; its true-privacy positive control returns `•`. This executes persistence-value selection, not an actual metrics database write.

The old private prefix stays protected. The appended scalar is outside `llm_private_mark`: the actual LLM bridge gives AI context `6`. A separate probe adds ` merci pour votre dossier` and requests a prediction through the actual prediction engine; its fake remote HTTP port receives the production serialized request containing `6 merci pour votre dossier`. No network request is sent. The full synthetic SSN is absent from that request. This is precisely one derived scalar becoming public, not disclosure of the entire SSN or its preexisting prefix.

Root: `Expander.try_repeat_feature` reads `last_char` from the existing output buffer and unconditionally passes false as the private argument to `perform_text_replacement` (`expander.lua:1340–1346`); it neither extends the private mark nor withholds the literal repeat DEBUG message. `perform_text_replacement` consequently forwards false to synthetic metrics, and the bridge retains the previous private-prefix mark. The privacy state is present and correct immediately before the repeat, so this is an actual loss of classification at a derived-output producer.

Visibility: repeat itself succeeds, the prior private mapping is redacted, and no diagnostic reports dropped privacy. The existing registered private-context tests all pass because they cover subsequent fresh typing and Backspace, not repetition derived from a secret. The captured logger boundary and actual recorded-value function are independent observers of the lost flag.

Regression direction: run the actual personal rules producer and public Keymap tap into production Expander/SyntheticInput/Bridge/metrics publication. Check that repetition derived from a private span remains private in every persistence and DEBUG sink and remains excluded from both manual and automatic AI contexts. Ordinary nonprivate repetition and fresh public typing after a private expansion must still work. Include deleting within the private span, custom magic keys and refusal/rollback controls. Do not solve this by disabling ordinary repeat or suppressing all user context indefinitely.

Proofs:

- `public-repeat.lua REPO`: actual public Keymap tap, actual SSN rules registration, actual repeat output, literal Logger boundary, actual AI context and actual metrics recorded-value owner; also following corrections and Backspace controls.
- `private-repeat.lua REPO`: actual privacy regression fixture prefix composed with repeat and actual remote prediction request serialization into a fake HTTP port. State append mirrors the caller; public admission is proved separately by the first probe.

Both probes execute fixture prefixes from exact repository test files before their registration boundary. Fixture boundary is asserted unique. `source-hashes.json` pins these input fixtures and the claimed production owners. No probe pretends that the Hammerspoon test stub is an actual CoreGraphics or native editor receipt.

## Verified availability and differences

- Repeat fallback is available, opt-in: shared neutral default is false. A real registry/preferences test proves enable persists true and disabling removes the sparse key. The stale registry-index comment saying opt-out/default true is documentation debt; actual code reads the shared manifest.
- Repeat follows eligible explicit magic actions and end-char mappings. True magic mappings bypass ordinary typing delay; unmatched repeat remains subject to the star delay. Final no-op mappings mask fallback. Real registered eventtap controls cover changed literal magic suffixes and slow explicit star validation.
- Actual shipped `repeatcorrections.toml` rows work after repetition: public `ac★` gives `acc`, then `ê` invokes shipped `ccê → ccu`, preserving `a`, hence `accu`. Public `po★` leaves `poo` eligible for a subsequent separately registered `poo★` mapping. A separately registered enabled word-only `x → z` auto rule leaves both public `po★x` and manual `poox` as `poox`; standalone `x → z` is the positive reachability control. Repeat preserves the actual midword boundary. Corrections are normal catalogue mappings with their own extension/section ownership, not the repeat toggle itself.
- Single-word-start letters, punctuation predecessors, whitespace, double magic and unknown buffer starts are refused by the shared word-character policy. Native output is a transaction with immutable generation; composite NBSP/NNBSP punctuation magic events are recognized by their shared terminator identity.
- A plain Backspace after public `expand★ → EXPANDED` passes through and the tracked buffer becomes `EXPANDE`. macOS has no corresponding Linux-style expansion receipt in the bounded Keymap/Expander/control owner census. This is an observed implementation availability difference; no product decision authorizing absence was located. Native Cmd+Z also passes through (with the configured shortcut buffer-reset policy). Its native editor effect and grouping remain unmeasured.
- Intentional no-repeat bubble: routed text-input memory explicitly says doubling must never appear in a tooltip, as it would be constant midword noise; it still fires. Corrections are explicitly excluded from this doubling definition. Registered no-repeat-preview control passes. This is intentional suppression, not an unavailable repeat feature.
- Intentional private-prefix withholding: actual bridge documentation says private replacements and their triggers stay outside every local/remote prompt, while later fresh user text is allowed. URM-001 does not reinterpret fresh typed public text as private.
- Intentional native ownership: actual eventtap callback collector returns tagged events as one native batch rather than posting/sleeping in the HID callback. Ordinary physical magic is consumed, so normal repeat constructs no Backspace. Ignored-window output helper supports replacing already typed composite events, but live ignored/secure classification refuses before reaching triggers; helper tests do not prove ignored-app expansions are enabled.

## Refuted hypotheses and limitations

The engine-only example `a★ → aa` in the repeat docstring is stale: the actual word-start guard refuses it. This is documentation debt, not an executable first-letter doubling defect. Registered repeat transaction refusal tests assert zero output, unchanged buffer and zero synthetic telemetry; they do not rely merely on pcall status. Same-tick repeats own distinct immutable generations. A disabled repeat emits no synthetic publication in the public control. Actual private SSN expansion initially clears AI context and retains private classification; the finding starts at the repeat producer, not at the personal prefix producer.

No native editor-level custom expansion undo was inferred from successful synthetic construction. No grapheme guarantee is invented from a codepoint corpus. No G4 claim is made. Source review of early pause, event-source freshness, focus-generation and secure/ignored classification found no additional repeat-specific admission root; native focus/device receiving remains an explicit gap. Existing prior clipboard, preview and personal token findings remain separate; no prior canonical repeat-derived private classification finding was located in the earlier audit manifests or root TODO.

Eight exact registered modules run in fresh Lua processes: 53 cases, zero failures, every selected module positive. These cover repeat transaction and arm-time corpus (30+2), neutral sparse configuration (1), public magic timing/resolver behavior (5), no-repeat preview (1), private AI context baseline (8), hotstring chaining (3) and bound sections (3). This is not the full macOS suite or a native Hammerspoon execution.

Two final whole-bounded sweeps A and B reopen caller/producer/configuration/control/lifecycle/output/privacy/intent axes and rerun both decisive probes and all eight isolated modules. Their command receipts and positive counts are retained under `dry-A` and `dry-B`. Neither final sweep surfaced another root. Memory watch: transactions/generations and cancellation were inspected, with no additional leak confirmed; long-running native retention is unmeasured.
