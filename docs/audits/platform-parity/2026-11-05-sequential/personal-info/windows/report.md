## PIW-001 — Eager registered compounds disagree with the working field-wise resolver

Severity **medium**, confidence **high**; G2, G5; additional property: form-field integrity. Root owner: `windows/modules/hotstrings/hotstrings_text_expansion.ahk`, nested `Generate`/`EscapeSpecialChars`/`CreateHotstringCombo`; comparison owner: `windows/infra/hotstrings/hotstring_engine_main.ahk` `HSE_TryPersonalInfoCombo`.

Reachable source-projected reproduction: enable `hotstrings.dynamic.text_expansion_personal_information`, set its supported `pattern_max_length=2`, and retain aliases n=last_name, p=first_name. Shared schema explicitly accepts integer1..16; this is not an invalid/dead configuration. Use synthetic last_name=`LEFT`, first_name=`RIGHT`. From a fresh input boundary type `@np` then the configured magic key. A registered compound wins over the transient fallback. The eager generator joins raw values into `LEFT{Tab}RIGHT`, then calls `SendEscapeLiteral` on the whole combined string. That neutralizes BOTH separator braces, recording replacement `LEFT{{}Tab{}}RIGHT` with OnlyText=false. The final engine sends that interpreted-key payload, which predicts literal `LEFT{Tab}RIGHT` in one field, instead of LEFT, Tab, RIGHT. Its preview metadata retains both complete fields and shows `LEFT ⇥ RIGHT`, promising field navigation the registered payload does not perform.

Healthy control: at the shipped max1, the same two-letter combo is not pre-generated. `HSE_TryPersonalInfoCombo` escapes each value separately, THEN inserts the unescaped `{Tab}` between fields, and produces `LEFT{Tab}RIGHT` with the intended control. Single-field eager registrations carry no inserted separator and do not exhibit this delimiter defect. Values containing literal braces/modifier symbols must remain literal after a fix; removing escaping wholesale is unsafe.

Second manifestation of this same `Generate` assembly owner: clear last_name through the actual editor, keep first_name=`RIGHT`, and use max2. The eager loop includes the empty value, appends separators only when accumulated output is already nonempty, then registers any nonempty aggregate. `@np` becomes just RIGHT and can place the first name into the field intended for the missing surname. Reversing empty/nonempty order can produce a trailing literal Tab marker. The transient resolver instead declines the WHOLE combo on any empty field; masked preview projection also drops a row with any empty value. This is grouped with the separator defect as one inconsistent pre-generated compound assembly root, not two finding IDs.

No refusal/exception occurs: the valid registered Spec is selected and its Send payload is considered successful. Native receiving of that payload has not been measured. The ordinary private-output guards still apply; the finding is wrong output/preview, not secret logging.

Regression direction: exercise actual eager registration and actual transient resolver on identical supported max1/max2 contexts; assert equivalent per-field literal values, inter-field Tab controls, absence of trailing navigation, and whole-combo refusal for missing/empty values at first/middle/last positions. Include `{Tab}` as literal FIELD DATA, braces, `^~+!#`, Unicode and repeated aliases. Keep registration/priority/control semantics in the actual owner. A later private native form must verify field placement and preview receiving; a JS translation of Send is not that proof.

Evidence: `proofs/source-contract.mjs`/`.log`; `proofs/owner-unexecuted.ahk` is an unexecuted genuine assembly/resolver fixture with synthetic values and a faithful recording CreateHotstring registration seam. It does not fake the generator or transient resolver. The Node probe's mutations (whole-string escape removed / escape moved per value) establish source-check sensitivity only, not native behavior.

## PIW-002 — Valid editable TOML fields load as placeholders without a refusal

Severity **medium**, confidence **high**; G2; additional property: known personal-field configuration integrity. Owner: `windows/infra/hotstrings/personal_toml_io.ahk` `ReadPersonalInfoToml`; public source editor: `open_personal_info` -> `GestureOpenIfExists(ScriptInformation["PersonalInfoTomlPath"])` -> Notepad. This is distinct from unreadable-file refusal, editor stale-source protection and generic unknown-key preservation.

Reachable source-projected reproduction: open the personal-info file through that public action, replace a known field assignment with valid TOML `first_name = 'SYNTHETIC'`, retain a valid `[letters] p = "first_name"`, save and reload. A double-quoted `first_name = "SYNTHETIC"` healthy control loads correctly. The literal-string variant is equally valid TOML and the actual shared codec decodes it identically on both Lua runtimes. Windows reader's only assignment regex requires a bare word key and DOUBLE-QUOTED value. It ignores the literal-string assignment, keeps its opening placeholder/default `first_name`, and publishes a source cache with `admitted=true` and the exact original raw bytes. There is no unmatched-known-field diagnostic, parse failure or unreadable-source latch. `@p` can therefore insert the placeholder instead of the configured value. A quoted known key (`"first_name" = "SYNTHETIC"`) has the same omission, with an independent valid-codec control. Literal `[letters] p = 'first_name'` is also ignored; because the explicit section was seen it can clear aliases altogether.

The save consequence is qualified separately: the native/WebView form displays the loaded placeholders, captures the source receipt, and a subsequent explicit Save can successfully replace that unchanged source with the displayed values. This is **authorized form output based on an incorrectly decoded model**, not an unauthorized overwrite or a source-CAS bypass. The exact-byte consent protects against intervening edits but does not certify that known fields in those bytes were interpreted. The original literal value can be lost after that Save. Native form acceptance/save was not executed here; the source chain and distinction are retained.

Root: the source identity admission is raw-byte-aware but field decoding is a partial ad hoc line matcher. Valid TOML string/key spellings outside that matcher silently become missing data and then defaults. No safety requirement documents a double-quoted-only personal-info grammar; the public file and shared schema call it TOML, and Linux delegates it to the real shared codec. This finding is deliberately bounded to valid syntax for a KNOWN field; it does not assume support for arbitrary unknown field keys.

Regression direction: genuine ReadPersonalInfoToml -> admitted editor model -> private save/reload/actual alias output should preserve equivalent basic-string/literal-string/quoted-key/Unicode-escape spellings for every known field and alias, or refuse unsupported input loudly without certifying placeholder data. Retain byte-exact opening consent, no-read=no-write latch, current map identity, source-switch/reload and current-editor fences. Separate initial bad load from later user-authorized Save. Do not weaken the source receipt tests.

Evidence: `proofs/reader-source-contract.mjs`/`.log`; `proofs/reader-unexecuted.ahk` extracts the actual reader and decoder/unescape bodies, using only artifact-local synthetic source files and readonly native file boundaries, but is UNEXECUTED. `proofs/literal-toml.lua` and two runtime logs execute the ACTUAL shared codec over the same three syntactic sources, proving valid equivalent TOML, not Windows execution.

## Masking, privacy and counterchecks

- Shared field policy masks IBAN, BIC, credit_card, social_security_number; phone_number and phone_number_clean are intentionally unmasked, as are date/name/email/address fields. Unreadable/unknown declaration/field must not become permission to reveal. Windows preview masking splits UTF16 surrogate pairs, preserves configured decorative separators and uses the policy's content threshold. Malformed policy/encoding edge cases are bounded source review here, not exhaustively native-tested.
- Every personal literal/compound Spec is private; prefix registrations carry the same marker even though their trigger itself can contain sensitive digits. Logs use PersonalInfoRedactForLog on trigger AND replacement; private output clears prefix/LLM context so later prompts cannot inherit the injected identity. Display's partial head/tail reveal deliberately differs from all-content log redaction. Windows log-redaction length follows UTF16 metrics units; shared Lua follows codepoints—this arithmetic difference is explicit, not an accidental reveal.
- Mac phone-tokenization candidate counterpart is refuted on Windows: `_DynPrivateOpts` omits OnlyText, CreateHotstring defaults it TRUE, transports it into Spec/decision, and `ReplacementPart := OnlyText ? ("{Text}" . Replacement) : Replacement` keeps phone data such as `0123{Tab}45` literal. Direct @tel is also literal. PIW-001 explicitly sets OnlyText=false for intended inter-field navigation and has the opposite whole-string escaping mistake.
- Existing snapshot fixes mean committing new maps before reload does not let a bubble show new data while a registered Spec still emits old data: registration clones PreviewValues and display reads the frozen snapshot. Save advances runtime decision generation and invalidates the visible projection. A refused reload is logged as a post-commit failure; saved durability is not called a completed runtime rebuild.
- IsPrivate is NOT editor permission, at-rest encryption or password-field consent. Editors intentionally show values to the person editing them. This audit does not turn those authorized editor values or native Save confirmation into a preview leak.
- The shared personal_info README's claim "Windows is not wired to this yet" is obsolete: current registration and `infra/personal_info_preview.ahk` are wired through canonical HSE decisions. That documentation drift is recorded separately, not counted as a runtime defect.

## Initialization, consent, failure and lifecycle review

Read/cache publication retains opening map/cache identities across I/O and diagnostic callbacks. A newer admitted reader/writer wins; old parse cannot republish over it. Raw source decoding preserves the native BOM/UTF8/UTF16 contract, including exact-byte witness, independently of the partial TOML grammar in PIW-002. Existing unreadable file latches writes; successful current read clears the latch; absent file materializes defaults through the acknowledged writer. Omitted letters section preserves defaults; explicit empty section clears aliases; unknown targets/duplicate/invalid-length recognized aliases warn.

Writer/editor consent checks exact source bytes, path/configured key, active form/session, resident map identities/content and decision generation. Save writes a private stage, rechecks revocable facts, then guarded replacement/publish. `false`/unknown/malformed source cannot borrow a newer form's receipt. Filesystem witness is optimistic, not an OS-atomic external compare-and-swap; no stronger property is invented. Failed writes/replacement/authorization/publication and reload are loud. Source publication failure after durability is not silently called applied.

WebView opening captures source before constructing the window/controller; callbacks bind session epoch. Save messages defer work but the commit checks pause again. Ready/navigation init pushes the retained form's original snapshot; it does not reacquire a newer identity into the older form. Closing retires the source and epoch, unsubscribes before controller Close and makes duplicate reset a no-op. Native form closes retire their own source; multiple fallback forms cannot save through an already-replaced map/generation. Native navigation/controller cleanup receiving remains a separate limitation; prior native-UI audit owns its existing editor lifecycle findings.

Input hooks/timers bypass native Suspend, so personal resolver/preview is reviewed through engine suppression, registry transition/master feature and final publication guards, not assumed safe merely from hotkey suspension. Retained current-context fire decisions and reload generation protect stale callbacks. Selection/caret/native application consumption, Unicode native output/field navigation and shutdown failures were source-reviewed but not executed.

## Noncanonical observations and observed limits

- **Accepted configuration hazard, unmeasured:** schema permits max1..16 while eager registration enumerates 13 aliases to every length through max. Static cardinality is 13 leaves at max1; 182 at max2; 30,940 at max4; 883,708,280 at max8; 720,867,993,281,778,160 at max16. These are arithmetic projections from the loops, not registrations run, latency, memory or a G4 benchmark. No large enumeration was executed. A future fix should preserve lazy resolution rather than remove safeguards or manufacture a timing claim.
- Alias case/Unicode: Windows loader/writer accept uppercase ASCII alias keys, while transient lookup lowercases tags and then uses exact map keys; uppercase aliases can therefore differ between registered singles and dynamic compounds. Non-ASCII aliases face ASCII key/serialization and UTF16 one-unit restrictions. Shared role found related case behavior on Linux and fixed-schema loading differences on macOS; intent/native replay is unresolved, so not another canonical Windows finding.
- Literal tags precede alias walking; fields with multiple aliases show only one reverse-map hint in editors. This hint is a valid shortcut, not a full alias inventory. No false invalid-hint claim was raised.
- Direct all-fields Save is canonicalizing, not a source-preserving arbitrary-TOML editor. PIW-002 concerns ignored KNOWN field values at load, not loss of arbitrary unknown sections/comments during an explicitly authorized rewrite.
