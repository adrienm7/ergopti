## Full-flow coverage and evidence

### A. Chosen release through artifact admission

`ui/changelog/init.ahk` validates bridge/session/request before install action. `_CLW_InstallDeps` binds live window/list/request owner; `ReleaseInstall_Start` rejects missing tag, busy updater/recovery, source build or unknown/feed-only release. It publishes one operation identity before reports/backups, creates the backup, resolves exact asset then enters the same updater path used by the prompt. Observer epoch and native failure-owner identities are preserved through managed-network failure/retry (`release_install.ahk:142–317`). Retry retains the original backup and authenticated intent, rather than taking fresh consent from the same tag.

`Updater_DownloadAndInstall` rechecks manual request and suspension, acquires asynchronous-action admission, rejects a pending recovery and duplicate download, parses exact repository asset URL/digest/size, applies signature policy, then reserves a monotonic staging epoch. Authenticated size is mandatory before allocation. Parent `_UpdaterStagedArtifactRetirement` owns exclusive newly created native identities; directory/file identities reach the staging worker through private inherited environment, not interpolated source (`adapters/updater_curl_capture.ahk:274–438`, `self_update.ahk:2302–2497`).

The actual staging worker checks directory/output identity, performs owned transfer, verifies content length/minimum/digest, publishes the captured swap worker and refuses READY when cleanup debt remains (`vendor/ergopti_updater_staging.ps1:42–92`). Parent completion requires exact exit0 and READY, current epoch, original observer, valid staged identities, retired capture and non-suspended state (`self_update.ahk:2738–2803`). Deadline enforcement precedes releasing the monitor and is checked at completion as well as periodic monitoring. This is source-backed flow coverage, not execution of HTTP/WinHTTP/Windows file identities.

### B. Swap authorization through true parent exit

`_Updater_StartSwapTransaction:3346` reserves owner before CreateProcess. `_Updater_CreateSuspendedSwapOwner:3125` publishes the shared PROCESS_INFORMATION buffer before the native creation call, retains exact inherited parent/event handles, then publishes process/thread ownership before resume. `_Updater_ResumeSwapOwner:3225` atomically takes resume handles before using/closing them. A failed creation/resume closes the exact child through claimed owner/cleanup debt.

Ready→Commit→Ack does not mutate the executable. `_Updater_PollSwapHandshake:3516` rechecks pause and exact child liveness before publishing exit intent. The synchronous ExitApp invocation is separately owned (`:3692`); OnExit rechecks FinalExit authorization (`:3725`) and final ownership transfer (`:3808`). Swap worker waits for FinalExit **and** its inherited exact parent process handle to signal before any candidate/backup/replacement operation (`ergopti_updater_swap.ps1:25–30`). Ordinary exit or parent death before authorization takes explicit worker exit20/21 paths. A PID alone is not swap authority.

Hypothesis that later recovery handoff refusal can strand a transferred normal update child was rejected for this actual flow: `_Updater_CompleteRecoveryHandoffOnExit:1279` returns true unless `_UpdaterRecoveryExitInvocation`; normal updates are refused while recovery publication is active, so the two constructed invocation owners are mutually excluded. This is not proof for arbitrary mutated globals.

### C. Replacement, boot refusal and rollback

The exact post-parent-exit production statements were extracted by PowerShell AST, preserving the actual five file helpers and all transaction statements. Only `StartReady` is replaced by a recording native process/event boundary. Synthetic exe files are private text, never executable launches. On the real Linux filesystem/.NET implementation:

| Case                                   | Actual outcome                                                                                                                             |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| New executable boots                   | canonical NEW, one boot call, recovery/old backup cleaned, worker exit0                                                                    |
| New boot refuses                       | actual replacement happens, canonical OLD restored, second boot observes OLD, terminal SWAP_ERROR retained, worker exit1                   |
| New and restored canonical boot refuse | recovery-copy third boot observes OLD with AllowLauncherExit=true; exact recovery/claim retained for subsequent real-driver handoff, exit1 |
| Staged executable missing              | old canonical remains OLD, rollback startup uses OLD, terminal retained, exit1                                                             |

`logs/swap-cases.json` records exact observed content, call sequence, path and exit status. Success is asserted on independently read final bytes/cleanup; merely invoking a function without an exception is never counted as proof.

Recovery descriptor validation accepts only the expected GUID `.recovery.exe`, exact target/stage claim and size (`self_update.ahk:974–1025`). Recovery remains a live complete driver while canonical publication is locked, retries atomically, passes inherited boot-ready authority to the canonical driver, and defers cleanup until that driver reaches ready (`:1112–1324`). Native mutex/event handoff and real AV locking remain unexecuted.

### D. Ordinary reload through pending acceptance/refusal

Actual lifecycle integration selects configuration owner, defers only a plain lease-busy reload, prepares paused intent when needed, then calls `ReloadTerminalInvoke` with production successor port. `infra/reload_terminal_handoff.ahk:301–370` returns pending true only after owning a real successor; false before launch leaves bundle with caller. Claim is limited to reason Reload and state pending (`:80`). Durable commit precedes producer teardown (`infra/lifecycle.ahk:1433`); finish happens after terminal acceptance and cannot turn an accepted teardown into a late unsafe rollback (`reload_terminal_handoff:173–232`).

A load-error dialog is deliberately not killed after15s: watchdog logs barrier retention because a close request may be queued. Plain duplicate joins; callback-bearing/borrowed transitions refuse. Deferred OnExit claims have one budget spanning retries, recheck exact successor and wait on an interruptible timer, not an impossible sleep in the interrupted thread (`:454–550`; `reload_deferral.ahk`).

### E. Refusal, exact child retirement, compensation and cleanup

Reload refusal first stops and proves exit of its exact successor, then aborts prepared intent and retracts committed pause marker, then hands callback/bundle back on another thread (`reload_terminal_handoff:552–629,683–748,861–903`). Refusal true can acknowledge stop request; it does not assert physical termination. Ambiguous liveness/close leaves an owned retirement record. Compensation failure is retained/logged, not mislabeled fully reverted. Ordinary Quit supersedes a pending reload only after shutdown gates, with committed configuration retained (`:644–668,795–821`).

Updater cancellation clears old epoch/intent before terminating process/cleanup; staged or native cleanup debt is retained for retry (`self_update.ahk:2572–2643`, `adapters/updater_curl_capture.ahk`). Suspension invalidates an older generation, kills staging work, and late callbacks cannot borrow the current transaction. FinalExit transfer removes the child from cancellation ownership only after actual authorization. Initial failure presentation and deferred inherited swap-error notice are separate terminal receipts.

## Intentional policy, constraint and unknown rationale

- Explicit notify-only policy: schedules notify; only reviewed click callers install. The cross-driver contract guards caller reachability, not just UI wording.
- Explicit source-tree protection: source-mode native rows are greyed and executable replacement is rejected. No source-pull support is inferred from a helper name or generic agent script executor.
- Explicit signing setup: Windows/Linux signature enforcement currently off with empty key; warnings are intentional until provisioning. Their trusted GitHub size/digest still checks bytes; a cryptographic signature requirement must not be advertised as active. macOS native signing/Sparkle is a different trust implementation.
- Explicit distribution ownership: Linux standalone update is supported; AppImage/Flatpak/system/package paths refuse archive replacement. macOS app replacement and Windows running-exe lock constraints explain the native mechanisms. Shared full downloads are a maintainer decision; delta updates were withdrawn (`docs/memory/maintainer-decisions.md:259`).
- Explicit accepted-vs-pending lifecycle: launching a Windows successor is not successful reload acceptance. A stalled loader retains barrier and is logged rather than killed. Paused reload preserving pause is distinct from background download cancellation.
- Explicit failure ownership: native stop/close ambiguity retains record/debt. Refusal may require user/native intervention; source retention is not falsely counted as successful recovery.
- Unknown policy rationale: configuration restore overlays manifest files without deleting subsequent files; no all-or-nothing directory-mirror mandate established. Prior report already characterized this, so no repeated finding.
- Unknown/limited scope: dedicated source-pull or updater tool outside the actual audited callers was not established. This is a coverage boundary, not an invented platform limitation.

## Performance, memory and native limits

G4 is unmeasured for real Windows keyboard dispatch, update dialogs, antivirus locks or process scheduling. Source moves network/hash/swap work to workers and bounds polling; ordinary control-path I/O/backup is explicit user work. No hot-path latency benchmark was executed and no all-green guarantee is inferred.

Memory/ownership watch-list: captured full release JSON/observer closures, `_UpdaterCurlCaptureDebt`, `_UpdaterSwapCleanupDebt`, `_ReloadTerminalRetirements`, full-file FSSameBytes backup buffers, pending configuration bundles and paused intent/recovery descriptors. Retained native debt and stalled successor intentionally extend lifetime; finite fixture controls are not a long-running RSS/leak measurement. No leak confirmed.

Native gaps include AHK cooperative interruption/Critical behavior, Win32 sharing and inherited-handle restrictions, PS5.1 parser/runtime differences, signed exe/CNG, Windows native events/TerminateProcess/CloseHandle failures, production filesystem permissions/AV locks, real mutex wait and new executable boot-ready signal, power loss durability, real display/keyboard behavior, and every external tool/agent registry outside this bounded module pair. Two dry passes close this bounded audit, not every possible OS-module state or native parity claim.
