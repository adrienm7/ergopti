# Owned runtimes: inventory and decisions

Status: decided. The inventory was written on origin/dev 270a137454
(2026-10-27); on 2026-10-31 the maintainer accepted the proposal of every row,
which is now its decision. Where a proposal offered two ways, the first is the
decision and the second is kept as a noted alternative. The State column says
whether the code already behaves as decided (`done`) or the change is follow-up
work (`to do`).

The rows live in `_shared/data/owned_runtimes.json`. The tables below are
generated from it by `tools/codegen/codegen-owned-runtimes.cjs` (between the
GENERATED markers; change the registry and run the generator, never the table),
and `tools/test/test-owned-runtimes-doc.cjs` fails when they drift.

## The rule

Ergopti keeps full control of every third-party runtime it depends on, on all
three OS. It installs and runs its own pinned version whether or not the user
has one, never relies on the user's copy, and never stops or modifies it.

Two readings matter for the decisions below.

- **Runtime** means a program or library that carries Ergopti behaviour or data
  (an inference server, a remapping engine, a Python environment, a web view).
  It does not mean the operating system's own command line tools (`launchctl`,
  `codesign`, `tar`): these cannot be replaced and must not be, and the rule
  for them is "check and refuse clearly".
- **Never relies on the user's copy** has to be tested against three kinds of
  sharing that a pinned copy cannot avoid: a TCP port, a system-wide kernel or
  DriverKit extension, and a user data directory. Section 6 lists the places
  where today's design shares one of them.

Decision vocabulary, used in every table (the registry's `decision_classes`
holds the same definitions):

- **PIN**: ship (or download on consent) our own pinned copy, verified by
  SHA-256, run only that.
- **SYS**: system tool. Check its version at the point of use and refuse with a
  clear message. Never replaced, never modified.
- **OPT**: optional. A feature that uses it is hidden or inactive with a stated
  reason when it is absent; nothing else depends on it.
- **DELETE**: a legacy path or probe that goes away. **NA**: not used, or built
  by this repository.

The Class today column uses the same words plus **SHARED** (our pinned copy
exists but shares a port, an extension or settings with the user's copy) and
**HOST** (the host's or the user's copy is used, at least in one format or
path).

Sources are `file:line` relative to `static/ergopti_plus/` unless they start
with `tools/` or `docs/`.

The macOS and Linux tables are checked against the code:
`tools/test/test-owned-runtimes-inventory.cjs` derives every program the two
drivers start (`tools/test/lib/spawned-tools.cjs` says how) and fails when one
is in no registry row's `programs`. A new spawn therefore arrives with its row
and its decision.

## 2. Top risks

1. **Karabiner on macOS cannot be fully owned while the user keeps theirs.**
   The VirtualHIDDevice DriverKit extension and its daemon are one system-wide
   instance. ADR 011 decision 3 (`docs/adr/011-owned-karabiner-runtime.md:49`, under `static/ergopti_plus/`) makes the owned runtime quit
   any other running Karabiner, which the new rule forbids (it says never stop
   the user's copy). Decided on 2026-10-27 (section 6.1): Tap-Hold on quits
   theirs, Tap-Hold off never activates ours; revised on 2026-10-31: the rule
   follows Ergopti running (section 6.1).
2. **The macOS Ollama path preferred the user's copy; now done.** The
   resolver names only Ergopti's own pinned runtime
   (`macos/modules/llm/ollama_binary.lua`); the stock candidates, the stock
   download and the shared `ollama_install.sh` are gone, and
   `macos/modules/llm/ensure-ollama-deps.sh` only verifies the resolved
   runtime. The managed, hash-pinned runtime 0.40.6 is the one path
   (`_shared/modules/llm/managed_ollama_runtime.json`).
3. **The Ollama port was shared on every OS; now done.** Ergopti's own
   Ollama listens on `llm_ollama_owned_port` = 11435 and 11434, the port of a
   user's own Ollama, is refused (`_shared/modules/llm/defaults.json`,
   `macos/modules/llm/ollama_endpoint.lua`). MLX already used a dedicated port
   3460 (`_shared/modules/llm/mlx_server.json`).
4. **Windows still has a winget path that installs the user-level Ollama**
   (`windows/modules/llm/ollama_deps_checker.ahk:327`).
5. **Linux needs `tar` with zstd support to unpack the pinned Ollama**
   (`linux/modules/llm/ollama_install_files.lua:277`), and no package lists
   `tar` or `zstd`. The assets are 1.4 to 1.6 GB.
6. **macOS `/usr/bin/python3` is a shim.** The App Cloner runs it
   (`macos/apps/App Cloner.app/Contents/Resources/clone_app.sh:552`); on a Mac
   without the Command Line Tools it pops the Xcode installer instead of
   running.
7. **Linux distribution packages depend on the host for almost everything**
   (LuaJIT, curl, openssl, sqlite3, xclip, zenity, lgi, WebKitGTK:
   `tools/build/build-linux-deb.sh:177`). Only the AppImage bundles LuaJIT,
   curl and luv (`docs/memory/linux-web-release.md:584`). Under the rule the
   AppImage becomes the only first-class format, or the other formats gain the
   same bundle.
8. **Windows PowerShell 5.1 runs 18 modules' workers** and cannot be shipped
   (a Windows component); it needs a version gate and refusal, not a copy.

## 4. Linux

What is bundled today: only the AppImage, which carries LuaJIT, curl, luv and
their ELF closure, plus the tray library (`docs/memory/linux-web-release.md:584,632`;
`tools/build/build-linux-appimage.sh:211`). It does not carry glibc, GLib,
GTK, WebKitGTK or the C++ runtime on purpose. The `.deb`, `.rpm`, Arch and
Flatpak builds list the host packages instead
(`_shared/data/linux_native_runtime.json`, `package_requirements`;
`tools/build/build-linux-deb.sh:177`; `tools/build/build-linux-rpm.sh:190`).
Text injection no longer uses ydotool: the daemon writes to `/dev/uinput`
directly (`linux/ergopti_hotstrings.lua:2168`); the only remaining mention of
ydotool is a device-name filter (`linux/infra/device_names.lua:54`).

## 6. Where "own copy" is not enough

### 6.1 Karabiner and the VirtualHIDDevice (macOS)

- The DriverKit extension `org.pqrs.Karabiner-DriverKit-VirtualHIDDevice`
  (`macos/platform/remap/runtime_vhid.lua:26`) and its root daemon are
  registered system-wide. A user who has Karabiner-Elements already has one,
  possibly of another version; only one daemon can serve the virtual device at
  a time.
- ADR 011 solves this by quitting the other Karabiner (decision 3), through
  Karabiner's own quit steps (decision 9). The new rule forbids stopping the
  user's copy.
- Options that were weighed: (a) keep ADR 011 and record it as the one
  declared exception (explicit consent, default-on, reversible); (b) run only
  while no other Karabiner is active and report "unavailable: Karabiner is in
  use" otherwise, which is what the option does when unticked; (c) stop using
  Karabiner and implement the remapping on the app's own Quartz event tap plus
  a self-owned virtual device, which is a different project.
- **Decided by the maintainer (2026-10-27):** when Ergopti's Tap-Hold is on,
  Ergopti quits the user's Karabiner and runs its own pinned runtime; when
  Tap-Hold is off and the user has their own Karabiner, Ergopti never
  activates its runtime and leaves theirs untouched. This is ADR 011 decision 3
  as written (Tap-Hold on means the runtime runs and quits the other
  instance), so the ADR stands; it is the one declared exception to "never
  stop the user's copy".
- **Revised by the maintainer (2026-10-31), superseding the line above:** the
  rule follows Ergopti running, not the Tap-Hold section. Ergopti running (not
  paused) always uses its own pinned runtime and closes a running user
  Karabiner (under the default-on consent row); Ergopti paused or quit stops
  its runtime and restarts the user's
  Karabiner only if it closed it, remembered in a persisted marker so a crash
  is recovered. The owned runtime is the only path: the shared-mode merge into
  the user's `karabiner.json` is retired, with no migration: the only
  Karabiner user starts from a clean state (maintainer, 2026-10-31). Still the one declared exception to "never stop the
  user's copy", and the VirtualHIDDevice stays shared system-wide: a user
  Karabiner with another driver version blocks the owned runtime with a named,
  explained state.

### 6.2 Ollama (all three OS)

- **Port.** Use a dedicated port (the MLX server already uses 3460, an
  uncommon IANA-registered port) and refuse to talk to a server that answers on 11434.
- **Model store.** Keep the managed store in Ergopti's own folder (macOS
  `~/Library/Application Support/Ergopti/ollama`, `ollama_binary.lua:38`);
  never read or write `~/.ollama`.
- **User's copy.** Do not detect, adopt, migrate from, stop, or upgrade it. The
  "migration" machinery that classifies the user's copy as `foreign`
  (`_shared/lua/core/llm/ollama_runtime_choice.lua:7-14`) becomes unnecessary.
- **Size.** 168 MB on macOS, 1.4 to 1.6 GB on Linux and Windows amd64: a
  download on consent, never in the installer.

### 6.3 Python and MLX (macOS)

Already owned: pinned CPython, pinned uv, locked `uv.lock`, own `.venv`, own
port. The App Cloner moved to the managed Python on 1 November (risk 6); a clone
made earlier keeps `/usr/bin/python3` until it is cloned again.

### 6.4 Linux packaging

The rule is not met by `.deb` and `.rpm` while they depend on the host's
LuaJIT, curl, openssl, sqlite3, lgi and WebKitGTK. Decided (2026-10-31, the
LuaJIT, luv and curl rows): give the other formats the same private bundle
directory the AppImage stages; making the AppImage the only supported format
is the noted alternative. GTK, WebKitGTK and glibc stay host-owned in both
(`docs/memory/linux-web-release.md:608-616`); they are system, not runtimes in
the sense of the rule, and the AppImage already refuses clearly when they do
not fit.

The rows in state `to do` are the work; this is the order.
