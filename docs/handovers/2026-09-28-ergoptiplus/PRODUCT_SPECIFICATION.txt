### S1: macOS shortcut preferences survive pause/Disable All (R5)

```text
R5 root cause (report macos-blocking.txt): Bindings.list_shortcuts().enabled reports the live binding (hotkeys[name] ~= nil) instead of the user preference, so every save made while Shortcuts is paused/off persists all [shortcuts.keys] as false, and the Enable-All rollback puts every shortcut in _disabled_set. Fix: list_shortcuts returns enabled = preference (not _disabled_set[name]) plus a separate bound field; Preferences.snapshot keeps writing the preference; audit every consumer (menu_shortcuts checkmarks, healthcheck, global_actions snapshot). Make the stateful test double in tests/unit/ui/menu/test_global_reset_transaction.lua honour Bindings admission so ordering bugs are catchable. Tests: test_preferences_shortcut_keys_survive_pause.lua and friends, failing first.
```

### S2: macOS boot sync isolates failures per feature; never overwrite config with defaults (R5)

```text
R5 (macos-blocking.txt): sync_state_to_modules is all-or-nothing; one refused setter restores DEFAULT_STATE silently (gestures=false, keylogger=false...) and seeds the save transaction from those defaults, so the next toggle overwrites config.toml. Make it per-feature: a refused setter demotes only its own feature in memory, logs an ERROR naming it, and never reverts the whole state; if a full rollback is unavoidable while the file loaded fine, the session becomes read-only for saves with a clear log. Gesture rollback inside the initial sync must not call save_prefs before seeding. macos/init.lua must fail loudly (ERROR + no false 'boot SUCCESSFUL') when menu.start returns nil. Also: the macOS gestures runtime must actually stop when Gestures is disabled (critique.md new finding: boot starts it unconditionally, M.start forces enabled=true, disable_all leaves touch watchers, primer eventtap and the 30 s health-check timer running) and restart when enabled. Tests failing first: test_initial_sync_partial_failure.lua, test_disable_stops_health_loop.lua.
```
