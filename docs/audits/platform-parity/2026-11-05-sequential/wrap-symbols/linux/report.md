## WSL-001 — Typed guillemets never reach their built-in spaced wrap pair

Medium severity, high confidence; G2.

Public path: `ergopti_hotstrings.lua:1993-2028` constructs the actual wrap controller, supplying `shortcuts.get_wrap_pair` and the PRIMARY reader. With wrapping/shortcuts enabled, a pointer selection window opens and PRIMARY changes to a nonempty selection. Type the single character `«` or `»`, including an AltGr-produced symbol. The genuine manager returns nil; the actual controller returns consumed=false before the second selection read or output. The hook's normal fallthrough forwards the physical symbol (`keyboard_hook.lua:1782-1816`). Thus the wrap is missing without warning; in an ordinary editor, the passed-through symbol can replace the selected text. Actual editor reception was not executed here.

Root: the shared catalogue declares the French pair as `left="« "`, `right=" »"` to preserve surrounding spaces. `manager.lua:219-227` stores those exact full strings as lookup keys. `get_wrap_pair:247-250` requires exactly one Unicode character, so neither full stored key is admissible and neither bare glyph exists. The manager's own comment specifically promises multi-byte guillemets. The parameter parser independently trims catalogue endpoints for matching and correctly resolves both bare glyphs to the spaced pair.

Proof: `probes/catalogue-owner.lua` loads the genuine catalogue/manager and production controller. Both guillemets produce `consumed=false writes=0 reads=1`; the actual parameter parser returns the intended spaced pair. Parentheses in both directions wrap `lève\n二😀` with one output and two PRIMARY reads. Unchanged PRIMARY, inactive policy and configuration ABA controls refuse without output. These are actual decision/lookup executions with a recording output port, not native key delivery.

Visibility/backstop: `get_pair` nil is treated as an ordinary non-wrap symbol; there is no warning. The explicit action parameter and menu's spaced guillemet pair remain alternatives. Normal application undo is only a potential editor backstop, not measured evidence.

Why a relevant test passes: `tests/unit/modules/shortcuts/text_actions/test_wrap_on_type.lua:19` constructs its own `PAIRS["«"]`, normalized in exactly the way the real manager does not do. Its Shift+Arrow/AltGr guillemet test therefore proves the controller can use a supplied normalized pair, not that production publishes one. The scanner cannot detect this exported-owner substitution.

Regression direction: feed every actual catalogue pair through the real manager/controller using its single-character trigger while preserving full delimiters for output. Include both guillemets, AltGr, Unicode/multiline selected content and the healthy refusal controls. Separate trigger normalization from output delimiters; do not remove the catalogue's spaces to hide the defect.

## WSL-002 — Flattened aliases remove a declared pair from the genuine menu

Low severity, high confidence. Additional property: catalogue completeness. No G label is forced onto a missing menu row.

Reproduction: load the shipped catalogue and build the actual Linux shortcuts menu with the genuine manager. There are 43 source pairs but 42 wrap rows. `“ … ”` is absent; `„ … “` and `( … )` are present. The standard curly pair is still accepted by the explicit action parser.

Root: `manager.lua:224-227` assigns both endpoint aliases into a single mutable lookup. The earlier standard `“`/`”` pair registers key `“`; the later `„`/`“` pair overwrites that key as its closing alias. `ui/menu/menu_shortcuts.lua:239-242` reconstructs canonical menu pairs by iterating this alias map and retaining only entries whose key equals pair.left. The earlier standard pair survives only at `”`, whose key is not its left endpoint, so it is discarded. This is separate from whether a typed ambiguous `“` should choose one quotation convention or the other: an ordered catalogue already exists and can preserve both menu choices.

Proof: `probes/menu-owner.lua` executes the full actual menu builder, genuine manifest/i18n and genuine manager. It asserts positive controls and missing standard pair, then prints `pair_rows=42`, `CATALOGUE_PAIRS 43`, `EXPLICIT_ACTION standard_curly=true`. No live panel/display claim is made.

Visibility/backstop: menu construction emits no error or unavailable reason; the choice simply disappears. A binding with parameter `“` still resolves `“`/`”`, giving an alternative. Regression direction: build the actual menu from the full ordered catalogue and require every declared pair exactly once, including endpoints reused by another pair; test the distinct trigger-alias ambiguity separately.

## Entry points, effects and configuration

- Typed path: evdev consumption callback runs only in intercept/grab mode, before forwarding; script chords, Magic Key and tap keys can consume first. Shift+navigation, Ctrl+A or pointer press opens a selection window. A changed PRIMARY plus current generation/policy admits output. No-selection/unchanged PRIMARY types the ordinary key once. Re-selecting identical text can intentionally miss a wrap; comments prefer this to stale insertion.
- Output path: Main retains controller generation and secure field publication, then injector prepares ordinary keys or clipboard fallback; its acknowledged result clears `_undoable` and resets the engine only after success. Existing real-owner tests exercise the actual Main construction, actual focus guard/controller/injector/clipboard through recorded native boundaries, including password/focus/pause/ABA changes, successor selection, native failures and restoration failures. Per-DOWN checks remain in RAM. No application-level edit receipt or preserved-selected-range/native undo is inferred from successful uinput commands.
- Selection picker: actual menu rows call `manager.wrap_selection(left,right)`, which copies/transforms/pastes/restores through the clipboard adapter; on `no_selection` it inserts an empty pair. The parameterized `wrap_selection` action uses `transform_selection`, where no selection yields no output, matching the shared action contract. These distinct entry points are not conflated.
- Custom pairs: the shared `left|right` parser rejects empty endpoints, multiple separators and CR/LF in the parameter, supports multi-character Unicode delimiters, and preserves internal side spacing. `gesture_parameters` holds binding-qualified values shared by gestures/keyboard/tap/script action routes. Actual private-file probe commits `【|】`, preserves an unknown TOML leaf, rejects invalid syntax and held-lease mutation, revokes old delivery guards and reloads `OPEN|CLOSE` with `tap_3=wrap_selection` through the real owner/writer. Configuration scope tests include wrap collision preflight, unchanged source, source drift and native refusal fences.
- Linux does not implement the Windows/macOS per-pair enable/disable/custom-add/delete store. This is already explicit in TODO.md:30 and the manifest's macOS-only `shortcuts.wrap_symbols` namespace/reason. Binding-specific custom `left|right` parameters do exist on Linux. No duplicate feature-gap finding is raised.
- Native clipboard: X11 PRIMARY uses bounded xclip, falling back to xsel; Wayland uses bounded `wl-paste --primary --no-newline` and requires compositor support. No reader/failure passes the symbol through rather than probing with Ctrl+C. Explicit actions borrow CLIPBOARD through session-selected xclip/xsel or wl-clipboard and emit owned Ctrl+C/Ctrl+V. Shell success/uinput acknowledgment is not proof that the intended editor processed the edit.
- Pause, ignored/private apps and reload: Main combines the switch/master/config admission, script pause, secure focus and input-capture gate; configuration revisions invalidate old selection windows. Existing tests cover focus/password/pause/config ABA at native boundaries. Reload is process/runtime reinitialization, not a promise that editing catalogue bytes hot-reloads its lookup on each keystroke. Exact source bytes are pinned for collision preflight, while the runtime catalogue loads once. No new stale-source transaction defect was established.
