# menu (shared data)

## Purpose

**The tray menu is defined in `menu.toml`.** Edit it, run `npm run build:menu`,
and commit the regenerated `menu_manifest.json` with it. Every row of every
tray submenu (Windows, macOS and Linux) is declared there: its type, label key,
order, platforms, checkmark and greying conditions, and the command it runs.
Each driver only supplies the **data** of a named `list` provider (installed
models, profiles, applications…) and the **handlers** of the declared commands.
Adding, removing or renaming a row happens in `menu.toml`, never in a driver.

## Key files

| File                          | Description                                                               |
| ----------------------------- | ------------------------------------------------------------------------- |
| `menu.toml`                   | Hand-edited source: every `[menu]` / `[[menu.*]]` table                   |
| `menu_manifest.json`          | Generated by `npm run build:menu`; read by the drivers; never hand-edited |
| `startup_tray.toml`           | Recovery tray policy, projected with the menu                             |
| `startup_tray_projection.ahk` | Generated Windows recovery tray, written by the same build                |
| `row_order.json`              | Shared row-order rules some native menus apply                            |

## Row types

| Type             | What the row is                                                                 | What the driver supplies          |
| ---------------- | ------------------------------------------------------------------------------- | --------------------------------- |
| `toggle`         | A category's master switch, the first row of its submenu                        | the command under the row id      |
| `check`          | A checkbox ticked from `checked_when`                                           | the command and the state getters |
| `command`        | A plain action row                                                              | the command                       |
| `choice`         | One enum setting as one row, its values beneath it (projected by the generator) | the command and the state getter  |
| `group`          | A named submenu                                                                 | optionally a group builder        |
| `list`           | Rows whose contents are runtime data                                            | the provider's row DATA           |
| `section_header` | A disabled header                                                               | nothing                           |
| `label`          | An inert caption inside a template                                              | nothing                           |
| `---`            | A separator (deferred, never doubled or trailing)                               | nothing                           |

`feature`, `action`, `include`, `letter_picker` and `native_content` are older
or specialised types described in the generated file's header. There is no
`dynamic` type: it handed a row back to platform code, and the generator
refuses it. `platforms = ["ahk", "hs", "linux"]` restricts a row; with
`unavailable = "hide"` it is absent elsewhere, with `unavailable = "grey"` and a
`reason_key` it is drawn greyed with the reason.

## Editing rules

1. Edit `menu.toml` (features and their defaults stay in
   `_shared/modules/features/manifest.toml`; a `choice` row names one by `path`).
2. Run `npm run build:menu` (or `npm run build:domain`, which includes it).
3. Commit `menu.toml` and `menu_manifest.json` together; the menu gates
   (`test-menu-manifest`, `test-menu-parity`, `test-menu-action-handler-bijection`)
   check the declaration and that every driver answers its rows.
