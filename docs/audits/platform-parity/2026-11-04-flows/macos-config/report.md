## Confirmed: MCF-001 — rejected locale publication

Severity **medium**, confidence **high**, guarantee **G3** (accepted/debounced operation races with a rejected later operation). `macos/infra/i18n.lua:203` promises that rapid changes cancel the prior reload, retaining only the selected locale. It writes the existing authoritative file row at :210 before cancellation :214, timer acquisition :225 and native persistence :239. Each failure then returns false without reversing the row. `persist_locale`:264–268 repeats the issue and explicitly reports “selection remains unsaved.” Shared `script_config_authority.lua:165–174` commits the original file writer; macOS `script_scope.lua:45` gives that row priority at boot.

Reproducer: `probes/locale-partial-commit.lua`, output `logs/locale-partial-commit.log`. Run with `/workspace/scratch/parity-toolchain/ci-bin/lua`. It uses actual i18n, authority, native scratch-file writer and next-start adoption, with recording timer/hs.settings refusal ports and a recording reload. No real user preferences or native reload touched.

| Controlled refusal                                        | Public receipt | Current locale | File row / next boot | Reload                                          |
| --------------------------------------------------------- | -------------- | -------------- | -------------------- | ----------------------------------------------- |
| Timer cannot arm                                          | false          | fr             | de                   | none                                            |
| Native settings refusal                                   | false          | fr             | de                   | none                                            |
| No-reload persistence refusal                             | false          | fr             | de                   | none                                            |
| Cancel previous accepted de timer fails during en request | false          | de             | en                   | previous accepted timer remains valid and fires |

The final row proves more than an unrefreshed UI: rejected en changes what the previous accepted de operation loads. Existing i18n tests assert native/RAM behavior without the real pre-existing file authority, while authority tests verify the file rewrite independently. A regression must join both real owners and replay next boot; require truthful saved-intent receipt or an atomic refusal, including cleanup-debt case. This is not the old onboarding MC-001 compound-Finish root: the standalone language owner itself splits even without wizard/config-directory changes.

Maintainer evidence: `docs/memory/maintainer-decisions.md:142–152` explicitly requires config row authority and rewriting row first. That justifies authority ordering, **not** accepting a later rejected locale or leaving “unsaved” false receipts. Windows `infra/i18n.ahk` I18nSetLocale accepts canonical saved intent and explicitly distinguishes saved language from refused reload. Linux `infra/i18n.lua:233–237` has a same-policy candidate under independent Linux config review; parent deduplicates.
