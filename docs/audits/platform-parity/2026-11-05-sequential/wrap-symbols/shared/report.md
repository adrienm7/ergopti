## Full catalogue and actual consumption

Actual shared parser rule: trim the stored parameter; reject empty/newline/non-string; search every opening symbol first in catalogue order, then every closing symbol; otherwise accept exactly one `|` with nonblank sides and retain the inner side whitespace. ## Declarations, defaults, UI and alternatives

Two distinct feature rows intentionally expose the same behavior under different native names: Windows/Linux `shortcuts.wrap_text_if_selected`, macOS `shortcuts.keys.wrap_text_if_selected`. Both default false and recommend true. Their localized reason text explicitly explains the macOS namespace. Linux's master Shortcuts switch and its input/injection readiness also gate consumption; macOS binds an event tap and Windows gates PrefixWatcher interception. Keeping all built-in pair choices enabled does not override the feature switch.

The macOS optional canonical `shortcuts.wrap_symbols` section stores `states` and ordered `custom` pairs. Windows has a separate `wrap_symbols.toml`. Linux does not consume that section. The reason text states this difference. The schema permits nonempty string state keys with Boolean values, and custom pairs with exactly one Unicode scalar per endpoint plus retained future fields. The shared projection/prepare owner validates the actual TOML array/dictionary kind, refuses obsolete collisions, and preserves unowned neighbors. Management custom pairs and action `left|right` parameters deliberately have different expressiveness; multicharacter action parameters do not imply that the scalar-only editor is broken.

Windows/macOS expose7 management commands: enable all, disable all, restore, enable group, disable group, delete custom, add custom. Built-in rows are toggles, not immediate selection-wrap actions. Global/group operations address built-ins; custom pairs remain active until deletion. Restore clears both overrides and custom additions. Custom opening and closing endpoints overlay native built-ins in array order. The prompts allow an empty closing response to mean symmetry and retry invalid scalar input. A native GUI/persistence or stale menu closure result is not certified by this shared role.

Linux instead exposes immediate wrap actions from its picker, with no per-pair management store. Its direct menu `manager.wrap_selection` inserts an empty delimiter pair on `no_selection`. The parameterized `wrap_selection` action uses a different handler through `transform_selection` and has **no** empty-pair fallback. The shared action's “nothing selected: nothing happens” promise applies to that binding handler; conflating the picker function and binding handler would create a false finding.

## Selection safety, previews and keyboard pass-through

The action catalogue declares `wrap_selection` on all platforms with the `wrap_pair` parameter. The actual dispatch is Windows GestureWrapSelection/transform, macOS gestures→wrap_copied_selection, Linux manager action handler→transform_selection. Invalid parameters warn before output. Their parameter prompts describe the complete ordered list through the shared `describe` rule; localized prompts and validation messages exist in every locale. Pair rows display literal Unicode endpoints with an ellipsis; group/control labels are translated. This is caption/data coverage, not native visual preview proof.

Typed-symbol selection wrapping is a separate path. Windows uses UIA selection and canonical input-context checks; macOS uses AXSelectedText and an eventtap lifecycle/admission fence; Linux uses a PRIMARY baseline and context generation. All three require successful native output acknowledgment before consuming the raw key. No selection or refused output continues the ordinary symbol path. macOS allows Alt because Ergopti symbols live on the AltGr layer but passes Cmd/Ctrl. Linux passes Ctrl/Alt/Meta rather than taking a command chord. These distinct native modifier/workflow choices are visible in the matrix; physical keyboard parity was not measured here.

Linux explicitly refuses unchanged PRIMARY after the selection window opens, even if the user reselects identical text. Its module documents the intentional tradeoff: a missed wrap is safer than restoring stale text. Pointer/Shift-navigation/Ctrl+A open a bounded selection window; other input closes it. This is an explicit safety policy, not a regression to silently remove. Source traces retain privacy and destination ownership guards; none were weakened. Prior flow reports already own ClipboardAll versus rich pasteboard versus text-only Linux clipboard restoration and PRIMARY versus clipboard routes. They are deduplicated rather than re-reported.
