## Shared-file ownership

Shared manifests, schema, locales, independent corpora, generators and workflow
files are not owned by an OS worker. Before changing them, describe the exact
paths and contract to the coordinator; serialize changes to the same paths.
Keep policies and data in shared code; OS folders chiefly implement native ports.
Use the real owning generators and regenerate after integrating upstream changes.
Never merge generated bytes by hand or derive independent expected results from
new production inputs. Workers may update only their own TODO item blocks.
The coordinator resolves concurrent TODO edits item by item, preserving every
other group's progress and removing only genuinely completed items.

## Delivery and CI

Workers create their necessary `feat/<group>` branch from the actual current
`origin/dev`, commit one coherent fix or feature at a time, and push immediately.
Fetch regularly and merge upstream without reset, clean, stash or force-push.
Cancel every automatic workflow for each exact pushed SHA, including branch and
PR events; leave manual validation running. A worker provides its branch, exact
SHA, changed paths, tests and pending native requirements to the coordinator.
Do not merge into `dev` or move `codex/ci-validation` from a feature worker.

The coordinator reviews and integrates a completed slice, runs its selected
`verify-change` gates, pushes `dev` immediately, cancels automatic workflows for
that exact SHA, then advances the single `codex/ci-validation` ref without force.
Inspect `ci.yml` before dispatch: Release / Publish must remain push-only and be
skipped for manual runs. Use `workflow_dispatch` with `os_lanes` set to the
actually affected drivers. Supported values: `all`, `windows`, `macos`, `linux`,
`windows+macos`, `windows+linux`, `macos+linux`; default `all`. Shared checks always
run; selected OS lanes include their unit, E2E, package and installation gates.
A shared behavior change affecting all drivers selects all three. Documentation
and saved inactive candidate patches do not justify new native OS runs.

```sh
gh workflow run ci.yml --ref codex/ci-validation -f os_lanes=macos
```

Record run URL, exact SHA and terminal outcomes. Unit green with packaging or
installation skipped/failed is not full acceptance. Do not cancel a manual run
when another commit advances the CI ref: dispatch concurrency includes run ID.
Delete only the group's temporary feature branch after successful integration;
retain `main`, `dev`, necessary publication branches and existing active agents.

## Delta updates decision

Item 22 is withdrawn by maintainer decision, not marked implemented. The
maintainer reports current release downloads below 20 MB. Full signed,
checksummed downloads keep one installation/rollback path and avoid delta-base
selection, patch reconstruction and additional failure/fallback surfaces. There
is no measured current transfer benefit sufficient to justify that complexity.
Reconsider only if release size or measured repeated-download cost materially
increases. This decision does not remove archive compression (36), signature and
checksum admission, installed rollback, or enterprise-network work (62).
