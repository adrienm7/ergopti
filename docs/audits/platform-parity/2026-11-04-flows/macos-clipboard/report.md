## MCP-001 — Apps selection capture restores an obsolete clipboard over a newer copy

Severity **medium**, confidence **high**. Violates **G2/G3**.

`copy_selected_path` in a normal text application routes to `Apps.copy_or_open_path`: it borrows the whole clipboard, copies the selection, reads it after native handoff, restores the old snapshot and opens/searches the result. Unlike other current macOS borrowers, its restore/retry owner never checks the native clipboard generation. A newer user/application clipboard write is overwritten by the old snapshot. A write arriving before its selection-read timer can also be opened/searched as though it were the selected text.

Production chain: catalogue action `copy_selected_path` -> `modules/gestures/actions.lua:1433` `owner_action` -> `modules/shortcuts/actions/apps.lua:425` `begin_copy_capture` saves `readAllData`; normal-app branch `:940-974` clears, posts Cmd+C, waits for actual FIFO handoff and schedules selection read -> `restore_copy_capture:468-495` unconditionally `writeAllData(prior)`/clear -> `queue_copy_restore_retry:537` repeats the same restore after refusal. No `changeCount` is read anywhere in that Apps owner.

Strong reproduction avoids ambiguity about the writer of asynchronous Cmd+C:

1. Actual Apps/SyntheticInput/TimerScheduler owners copy and finish reading the selection.
2. The first native full-type restore returns false without mutating the board; the exact retry remains pending.
3. An independent new all-type clipboard write succeeds.
4. Apps' retained retry writes its old snapshot over that newer generation.

`probes/apps-foreign-clipboard.lua`, output in `probes/logs/apps-foreign-clipboard.log`, also exercises the earlier-write window and the healthy no-writer control:

```
REPRO RETRY: selection read completed and first restore refused; independent new clipboard write is overwritten by retained restore retry without generation check
CONTROL: no independent writer; one copy, one restore, one URL and original all-type clipboard preserved
```

The actual native generation port is supplied and records **zero reads**. The probe uses the existing `apps_fifo_capture_fixture`, which composes the real Apps, SyntheticInput and TimerScheduler; only native board/Quartz/URL ports record effects. No real URL opens.

Same-OS countercheck `probes/search-generation-control.lua`: actual Search owner under the same failed-restore/new-copy condition keeps the newer clipboard and revokes the stale snapshot. This is an existing available native mechanism, not an OS impossibility. Windows `infra/hotstrings/hotstring_send.ahk:1007-1024` admits/restores only its received-copy sequence through `CB_RestoreOwnedAllEventually`. Linux's normal-text `open_selection.open` reads PRIMARY rather than doing this temporary clipboard dance; its file-manager branch and general transformations have different custody and are not certified safe by this comparator.

Silent failure: Apps logs ordinary completion/retry; it has no observed generation with which to identify the newer owner. Regression/fix direction: retain a proven clear/copy/result generation and make normal, failed, cancelled and retried restoration conditional on that same generation. Test identical-text/new-generation writes, unreadable counts, restore false/nil/throw, cancellation and logging reentry. A late content sample must not retroactively authorize an unrelated writer.

## MCP-002 — Independent macOS borrowers can snapshot each other's temporary payload

Severity **medium**, confidence **high**. Violates **G2/G3**.

Text, Apps, Search, `adapters.text_sender` and `keymap.utils` have individual in-flight guards but no common admission authority for the process-global pasteboard. Intra-module serialization does not prevent one family from saving another family's temporary payload as the user's original clipboard.

Reproduced with **actual Text + Apps + SyntheticInput + TimerScheduler** on one native board:

1. Original board has plain text `ORIGINAL` plus HTML `<b>ORIGINAL</b>`.
2. `Text.paste_as_plain_text()` saves that full snapshot, publishes its temporary text-only payload and remains pending.
3. `Apps.copy_or_open_path()` returns true and snapshots that borrowed text-only payload; no external application write is needed.
4. Both flows settle. Text's generation guard recognizes Apps' mutation and relinquishes its true original; Apps restores its intermediate snapshot. Final board contains `ORIGINAL` but the original HTML type is gone.

`probes/cross-owner-clipboard.lua` and its log include a healthy plain-paste-alone control restoring every original type:

```
CONTROL: plain-paste owner alone restores original all-type snapshot including HTML
REPRO: pending actual plain-paste owner and Apps copy capture both admit; Apps snapshots borrowed text-only payload and eventually restores it; original HTML type lost
```

Root cause: `text.lua:97-113` checks only `_text_scopes`; `acquire_text_owner`/`paste_as_plain_text:1175` do not join Apps/Search's ownership. `apps.lua:425` checks only `_copy_capture_in_flight` and its own parent scope. The separate guards in `gestures/actions.lua` Search, `adapters/text_sender.lua` and `keymap/utils.lua` likewise do not establish a global snapshot receipt. The confirmed reproduction is the Text/Apps pair; other pairs are mapped risks, not separately claimed reproductions.

Windows provides a direct source comparator: `adapters/clipboard.ahk:80-100,118-127` has one `CB_TryBeginOwnedTransaction` authority shared by every snapshot-owning producer, explicitly to prevent saving another family's synthetic payload as user content. Linux's session adapter has separate synchronous/deferred paths and primary-selection capabilities; no universal cross-family safety claim was established here.

Silent failure: each local lifecycle correctly reports success/retirement in its own state; neither identifies the other's snapshot as borrowed. Fix/regression direction: common clipboard borrowing admission/receipt across families, preserving all types and correct owner identity through FIFO, timers, cancellation and refused cleanup. Test both ordering permutations and at least Text/Apps, Text/Search and direct output borrowers. Do not fix this only by comparing clipboard text, since identical text with missing HTML/image/file types is already corrupted state.

## MCP-003 — Ordinary delayed text transforms paste into a different focused application

Severity **high**, confidence **high** for production boundary behavior. Violates **G2/G3**.

Ordinary selection-case/wrap actions retain parent lifecycle and clipboard payload ownership but do not retain the application/field that owns the selected document text. After reading APP_A's selection and before the delayed paste, a focus change to APP_B leaves those guards true. The actual global Cmd+V and reselection are then posted to the new focused app with APP_A's captured text.

Production chain: `selection_lowercase` (and the other ordinary case/wrap actions) -> `gestures/actions.lua:1142-1174` Text owner -> `text.lua:1797` `do_transform(..., parent)` with no continuation receipt -> `TextContinuation.new(nil)` at `text_continuation.lua:18-36` always admits -> `text.lua:1000` publication checks only parent owner and that optional continuation -> copy/read -> paste timer `:1115` -> `SyntheticInput.emit_guarded_key_stroke({"cmd"}, "v", tx)` with no native application target. The clipboard guard checks payload count, not document destination. Generic SyntheticInput `publication_allowed` accepts this supplied guard; `begin` does not manufacture an application receipt.

`probes/transform-focus-switch.lua` composes the real Text, broker and scheduler, with a mutable native `window_info.getFocused` port and a native global-key route recorder. After copy/read produces lowercase payload at 210ms, it switches the reported/routed focus before paste. Output:

```
CONTROL: original APP_A selection read; native global Cmd+V delivered to APP_A with [selected words]; original clipboard restored
REPRO: original APP_A selection read; native global Cmd+V delivered to APP_B with [selected words]; original clipboard restored
```

Clipboard restoration is deliberately healthy in this reproduction; this is different from MCP-001/MCP-002. Source-wide call review finds Text pause/stop connected to binding/action lifecycle, not an application-focus watcher cancelling these ordinary owners. No native WindowServer/application was run; the recorder models the documented global-event routing boundary. The production owner omits the destination check irrespective of that native implementation.

Narrow safe counterpart: macOS tone/selection translation explicitly supply `SelectionPublication.capture` to the same Text API and test focus revocation. Linux shortcut manager `capture_text_destination:82-100` captures native field authority before clipboard I/O; its case/wrap callers at `:373` and `:590-600` refuse without it and pass it through copy/paste boundaries. Windows selection capture also retains foreground/physical-generation checks, but its whole transformation output was not executed here. Neither comparator certifies every desktop/application.

Silent failure: Text reports completed transformation and restores clipboard while emitting stale selected text to another document. Fix/regression direction: capture original destination at ordinary action admission, join full/cached destination authority to every deferred stage, and recheck before copy, paste and reselection. Exercise focus/field/caret change, unchanged focus control, pause, delayed FIFO handoff and cleanup refusal; cancellation must still restore only the clipboard owned by that action. Arbitrary previously accepted non-text jobs are outside this finding.

## Native return contracts, data and cancellation review

- Clipboard `setContents`/`writeAllData` require literal true; false/nil/throw are refusals, and failures after possible mutation retain recovery. `clearContents` has documented void return: nonthrow is success. Tests explicitly model this asymmetry; a nil native clear was not misreported as failure.
- Full-type snapshots use `readAllData` UTI-keyed maps, not `getContents` or array length. Empty valid board is nil+success; read failure is distinct. A race changing count during acquisition is rejected in guarded Text/TextSender families.
- Paste completion is not FIFO admission: TextDispatch, guarded key pairs and grace owners keep restore timers behind actual handoff. Tests simulate native post/refused stop, cancellation between key-down/up, delayed predecessors, double/stale callbacks and timer ownership.
- Parent pause differs from feature preference; cleanup debt may legitimately outlive logical pause, while business publication is closed. Healthy `stop`/`resume` is idempotent; a refused exact native timer is retried rather than replaced.
- Unicode case conversion follows shared Unicode corpus. Literal callback/program text and token output remain separate. `_cursor_steps` handles decomposed Latin, emoji modifiers/ZWJ/flags and CRLF but uses a handwritten join set. The executed `unicode-cursor-policy.lua` shows two steps for two-codepoint Hangul Jamo and Devanagari vowel sequences, versus one for decomposed Latin/emoji/flag controls. No native caret behavior was executed, so impact on a specific Mac editor remains an explicit qualification question, **not a fourth finding**.

Refutations held to concrete evidence:

- Local repeated wraps/plain pastes or repeated searches do not automatically lose the original clipboard: existing actual-owner tests serialize within each family. MCP-002 concerns **cross-family** admission, not a refutation of those tests.
- A refused restoration does not universally overwrite a later copy: actual Search countercontrol and guarded Text/TextSender/Utils tests preserve newer generations. MCP-001 identifies the unguarded Apps sibling, not the whole driver.
- Focus-safe Text API cannot be declared absent: translation/tone use its optional publication receipt and their real focus lifecycle tests pass. MCP-003 is ordinary callers that supply none.
- A native void clear result is not operational failure. The Clipboard adapter's documented zero-result contract and tests justify accepting nonthrowing nil.
- Output allowed to finish cleanup after PAUSE is not necessarily unwanted business output: native paste grace and exact clipboard restoration may remain retained, and tests verify logical publication remains closed.
- No claim that every helper is Unicode-grapheme-complete or that native event dispatch always means the target application has consumed the pasteboard. Both remain qualified native boundaries.
