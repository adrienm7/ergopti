# macOS field report coverage

The "To confirm on the Mac" lines of `TODO-tests-macos.md` ask for things only a real Mac
shows. One run of `bash tools/dev/collect-macos-field-report.sh --installed`
answers every open line: each line carries a `<!-- field-point: <id> -->` tag,
`static/ergopti_plus/macos/data/field_todo_coverage.json` names the evidence
that decides it, and the report ends with `todo_summary.md` (and
`todo_summary.json`): one verdict per point, which the coordinator ticks from
the report alone. Without `--installed` the steps that need the signed app are
`not_run` with `needs_installed_run`. No mode leaves the guided steps out: one
report does everything (decided by the coordinator on 2026-11-11, to review by
the maintainer).

Scope: this covers the macOS section only. Windows and Linux keep their own
« To confirm » sections, collectors (`collect-windows-field-report.ps1`,
`collect-linux-field-report.sh`) and live checks
(`docs/tooling/windows-maintainer-checks.md`); the shared protocol accepts the
guided step kind, but only the macOS field run declares guided steps today, so
a tagged-coverage contract for those sections is follow-up work.

## Verdicts

- ✅ `pass`: every check of the point passed, and every report step it names
  is a pass or an information within its bound. Tick the line, unless the
  table below names a remainder no run can test.
- ❌ `fail` or ⏱️ `timeout`: read the step's result in `field_run/` (its codes,
  report and log window) and the step details in
  `docs/memory/macos-hammerspoon.md` (`project-macos-field-run-step-details`).
- 🙋 `needs_person`: a guided step saw no gesture (`gesture_not_observed_<n>s`)
  or got no answer (`no_answer_<n>s`) within its bound. Run again at the Mac.
- ⏸️ `not_run`: the step was not part of this run, with its reason.
- ⏭️ `skip`: the person skipped it (`skipped_by_person`) or a precondition was
  missing (no VPN, Metrics off, no model installed); the condition column says
  what the point needs.
- 🚫 `not_testable`: a field report cannot decide it; the reason says what will.

## Guided steps

A guided step (`kind = "guided"` in `data/field_run.json`,
`infra/field_run_guided.lua`) needs one gesture of the person at the Mac. The
app publishes it in the run folder's `prompt.json`; the collector prints it
once (`👉 GUIDED <step> (up to <n> s): <gesture>`) and rings.

- An observed step needs no answer: it reads its field check before the prompt
  and every few seconds after, and passes or fails on the check's own verdict
  once each named count rose (a Wi-Fi switch adds `internet_down` and
  `internet_up` rows, a Ctrl+Caps Lock press adds `capslock_chord_presses`). A
  count meant to stay steady that rose (`vpn_connected` while no VPN was
  connected, the idle iCloud Private Relay case) fails it. Type `s` and Enter
  to skip it.
- An attested step is what only a person sees (a menu row, a page in dark mode,
  a tap typed on the internal keyboard, which Karabiner reads below the event
  system): type `y`, `n` or `s` then Enter. Its check still runs as evidence and
  a failed check turns a `y` into a failure.

The attested menu steps may change the configuration (Clear, Restore); the
field run's configuration guard puts it back after the run and names what it
restored.

## Adding a point

1. Add the TODO line with `<!-- field-point: <id> -->` after its checkbox.
2. Add the point to `field_todo_coverage.json`: the field run steps (and the
   report steps that decide them), or `not_testable` with the reason.
3. When no step reads it yet, add a field check (or a guided step) to
   `data/field_run.json` with its unit test, then regenerate the table above.
