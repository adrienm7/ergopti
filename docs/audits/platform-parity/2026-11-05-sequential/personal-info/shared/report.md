## PIS-001 — shared prefix count overstates unspaced personal mappings

The actual shared `compute_prefix_counts` reports two SSN mappings for any raw value of at least5 characters and two IBAN mappings for any raw value of at least6. Actual producers register a second spaced trigger only when it differs from the raw trigger. With valid compact values there is only one trigger per family.

Reproduction uses only private synthetic source files. `probes/prefix-count-owner.lua` initializes the actual Linux preferences and dynamic manager with only SSN/IBAN prefix families enabled, an unspaced fake SSN, an unspaced fake IBAN, no aliases, and no output injection. It produces:

```text
ACTUAL_MANAGER enabled_ssn_iban_only=true prefix_mappings=2 active_count=4
```

This role replayed that owner from the pinned shared worktree; decisive output is `logs/prefix-count-owner.log`. The exact actual menu caller at `linux/ui/menu/menu_hotstrings.lua` reads `dyn.active_count()` into the category count. `probes/shared-model.lua` separately runs the actual shared helper and actual pure Linux `Prefix.build`, on both genuine Lua5.4 and LuaJIT: unspaced values yield one mapping per family but counts of two; normally spaced values yield four mappings and an advertised four; empty data and disabled-producer controls stay empty. Every emitted personal prefix retains `is_private=true` and field provenance.

Root cause is in `_shared/lua/dynamic_hotstrings/init.lua`: the function estimates two variants from stripped length and never receives enough source information to know whether the spaced variant exists. Linux `prefix_rules.counts` feeds this into `manager.active_count`. macOS `rules_engine.publish_prefix_counts` source-traces the same helper into native section descriptors, while its producer applies the same distinct-trigger check. The macOS result is a **source analogue**, not an actual macOS menu run here. Windows has the distinct-trigger check in its AHK producer; it does **not** execute the shared Lua helper, so no Windows count defect is asserted.

Severity is low because text expansion continues to work; the user receives an overstated active-hotstring status. Confidence is high for the actual Linux manager/helper path. There is no raised error or refusal: both count and output are ordinary successful results, and threshold-only vectors do not compare against the producer. This is the named additional property **truthful_status**. No G1–G5 guarantee is forced onto a numerical menu count.

Regression direction: compare status with distinct actual produced mappings for compact, spaced, late-spacing, empty/short, and disabled-family inputs. Count the real admitted producer output or pass sufficient source identity; do not copy the existing threshold formula into another “expected” function. Native visual menu delivery remains unrun.

The phone decision is explicit in the canon; public preview does not make phone/name/email suitable for logs.

The policy preserves the first2 and last4 content codepoints only at length12 or above, otherwise hides all content. Spaces, hyphens and NBSP remain separators and do not count toward the reveal window. Unknown or absent field provenance masks by default. Full expansion values remain separate from display strings. This is the mask contract, not certification of the eventual injector: the macOS OS role retains a separate PIM002 prefix-tokenization candidate where an editor-accepted literal `0123{Tab}45` is parsed as a Tab by the ordinary prefix registry, while its @t combo control emits literal data. The raw full-injection matrix row references that OS owner; shared mask execution alone cannot refute it. Every mapping built from personal data is private for persisted metrics/log content, including fields deliberately unmasked on screen. Shared log redaction hides every codepoint, including separators, instead of retaining the screen's head/tail.

Actual execution uses the unchanged shared mask/TOML owners. The15 JSON golden vectors,16 TOML preview vectors and6 invalid-policy vectors all pass byte-for-byte. Additional controls cover every declared field, unknown field, missing declaration/flags, missing policy keys, empty/nonstring inputs, hyphen/NBSP separators, and a supplementary emoji mixed with accented text. The Windows twin explicitly recombines UTF16 surrogate pairs; that is source inspection, while the actual native AHK masking run belongs to the Windows role. No Unicode equivalence is inferred merely because a source file exists.

Malformed individual field records are better validated by the Linux binding than the macOS binding; a scalar declaration record could reach an indexing error in the pure mask. The shipped canon is valid and not an ordinary editor preference. No normal user path to malformed shipped classifier data was established, so this remains a corruption/admission hypothesis outside findings. ## Settings, aliases and actual source ownership

The13 example aliases address12 distinct fields; `e` and`m` both name email. The example describes a one-letter mapping, not a universal Unicode alias alphabet. Canonical aliases are lowercase ASCII. Linux explicitly accepts a single codepoint and does not normalize a decomposed spelling; Windows's writer accepts ASCII letters/digits/underscore; macOS's fixed schema reads its13 default keys. Stored alias case, tracker lowercasing and byte-based macOS combo iteration are distinct mechanisms. Custom uppercase/Unicode behavior remains an evidence-qualified source difference unless the OS role proves its accepted/consumed path.

All3 current transient resolvers explicitly reject an entire combo when any referenced field is absent/blank; none should shift later values into earlier form fields by silently skipping a part. The field order follows alias order, with a real Tab between fields and no trailing Tab. Windows also preregisters combinations through `pattern_max_length`; longer combinations use its fire-time resolver. Both Lua drivers resolve multi-field combos at use time and do not use this setting for eager pre-generation. Windows recursively enumerates alias-count raised to each configured length; this is a source-only observed limit. No high-value/hang experiment or latency/memory measurement was attempted. The feature schema accepts integer1..16 and defaults/recommends1, so values above1 are an accepted configured surface. A preregistered Windows combo's escaping behavior is owned by the Windows report; this shared report does not treat its source as native output proof.

The four relevant family defaults/recommendations are off. The personal-family feature's pattern length is1. Master dynamic/shortcut and per-family gates retain independent native ownership. Windows additionally exposes eight literal synonym tags (bic/cb/cc/iban/rib/ss/tel/tél); the Lua alias collectors are not that Windows literal table. Static registered trigger precedence and transient preview choice are therefore separate joins, retained in the matrix for native collision evidence rather than assumed identical.

Source placement matters: Windows keeps a retained `PersonalInfoTomlPath`; macOS accepts an explicit source path and otherwise uses its base-directory fallback; Linux's default init uses `default_config_dir()` unless explicitly passed a personal path, while its open-file action uses configured `Paths.config`. Linux's actual override mismatch is OS-owned. First-use seed behavior also differs: macOS writes its15-field default template, Windows has native bootstrap/read handling, Linux's manager returns empty info/aliases for an absent source and the editor's owned ready path may refuse missing-source initialization. The Linux role owns the missing-file/root proof; no three-platform first-use equivalence is certified here.

Custom source preservation must be traced independently from editor success. Windows reads recognized info keys and retains alias snapshots; macOS parses/serializes its fixed15 fields and13 aliases; Linux can load arbitrary source fields and aliases and patches edited values. The macOS loss of custom neighbors is an OS-owned result. Prior editor/config preservation, source CAS, stale callback, and close/refusal roots are deduplicated rather than promoted into PIS duplicates.
