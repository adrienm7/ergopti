# Windows × lifecycle, updater, configuration recovery and diagnostics

Audited SHA: `89b0b774c8c960c7ad458ac3cb98d5c97598e518`.
Date: 2026-11-04. Audit only; no source edits, installation, destructive operation, commit or push. Existing hotstrings and metrics artifacts were preserved. The preceding metrics report was supplemented with the exact security-document qualification requested by the parent.

## Outcome and limits

No **new confirmed actionable defect** was established in this bounded Windows pass. The machine-readable findings list is empty. Several apparent defects were refuted by their actual helper/ownership implementation; a backup restore-policy ambiguity is characterized below without inventing a deletion requirement.

This is two passes over selected production flows, not a claim that approximately 13,000 lines of updater/onboarding code or every native timing state were exhaustively verified. Native Windows/AutoHotkey/PowerShell execution was unavailable. The updater's terminal replacement, executable recovery, startup shortcut operations, native install/uninstall, UIA/WebView2 readiness and process races remain native validation boundaries. Nothing was installed, uninstalled or replaced.

## Restore semantics requiring product qualification, not a confirmed defect

`ConfigBackup_Restore` (`windows/modules/updater/config_backup.ahk:354-383`) and shared Lua `owner.restore` (`_shared/lua/updater/config_backup.lua:413-454`) restore the saved files as an overlay. They do not remove later-created included files or represent their earlier absence. A backup before tap_hold.toml existed followed by later creation and restore retains the new tap_hold.toml. Thus “restore these saved configuration files” and “return every file's presence/absence to the earlier snapshot” are different features.

Re-read `docs/memory/maintainer-decisions.md`, shared defaults backup description and module contract. Found explicit rules for included extensions, pre-restore backup and Windows/POSIX custody; found no explicit requirement to delete later user data or restore absence. The UI's “Configuration restored” wording alone is insufficient authority to infer deletion. A non-destructive overlay may deliberately preserve later user files, but that rationale is **inferred**, not an established maintainer decision. Do not silently add deletions to “fix” this. Future inventory/docs should state overlay scope or obtain a separate product decision for exact snapshots/tombstones.

`backup-contract-probe.lua` executes the real shared Lua backup owner with its existing in-memory I/O contract: 11 cases pass. An additional characterization creates a post-backup tap_hold.toml and verifies restore returns true, restores config.toml and retains the new file. The Windows implementation's same loop was source-inspected; no AHK runtime execution claimed. This artifact supports description of behavior, not a requirement that behavior change.
