# Word-reset and context continuity — shared review

Audited source: `b17e47ed3bb92c106703d3e3482b3c2973f5bc1e`.

No additional shared finding is confirmed. The shared idle/context rules and the actual Linux policy/engine/context owners passed 1,388 value assertions in each of Lua 5.4 and LuaJIT. These include 208 policy scenarios, seven idle vectors, thirteen rolling-context vectors and nine private-mark vectors. An independently reopened and replayed macOS peer fixture reproduces twelve public-caller scenarios with five violations of the intended next-key context lifetime. That root belongs to the macOS reviewer and is not counted again here.

## Scope and effective defaults

The six reviewed declarations are `hotstrings.idle_reset_seconds`, `click_resets_word`, `arrow_resets_word`, `shortcut_resets_word`, `tap_hold_resets_word` and `llm.generation.reset_on_nav`. The actual declaration-model code resolves idle to **3 seconds**, all five booleans to **true**, and tap-hold-origin reset to Windows/Linux only. Zero disables idle reset; it is not the shipped default. Raw macOS state fields initialized to false are placeholders: Keymap seeds the effective defaults through Manifest. An early shorthand description was corrected after reading the canonical source; it is not evidence of a default discrepancy.

`source_probe.py` authenticates twenty exact source blobs against the audited commit, checks current reviewed bytes match, and executes the actual feature-model loader. Its receipt records the per-OS declarations and explicit macOS tap-hold-origin reason. Source receipts are bounded provenance, not certification of every transitive dependency or native key event.

## Decisive observations

`context-controls.lua <repo>` loads the genuine shared matcher, shared rolling context and Linux WordReset/Engine/AIContext/Settings owners. It replaces only the logging output port. Settings are supplied through actual `WordReset.adopt_configuration` and a controlled valid cache restored through the actual Settings snapshot/restore API. It reads no user preferences and writes no source, logs or configuration.

The cross-product exercises arrow, shortcut and tap-hold option combinations with AI navigation reset both off and on. Every governed event checks its actual owner, immediate word/boundary, immediate AI text and both buffers after the next character. Unconditional controls, modified Backspace, terminal submission, idle reset, empty-line promises and Unicode Backspace have separate controls. The corpus runner invokes actual shared context operations and compares actual text/length/navigation receipts and private marks with authored vectors. This is behavioral checking of the owning modules; it is not native desktop receiving.

The intended independent AI lifetime is explicit in `_shared/lua/llm/context_buffer.lua`: after navigation it asks whether the sentence should remain available to the model, controlled by `reset_on_nav` and “nothing else.” Its corpus explicitly includes `navigation-keeps-typing-after`, preserving `one ` across navigation and then appending `two`.

The macOS peer snapshot `macos-peer-replay.lua` was opened together with its real fixture prefix and production Bridge before independent replay. The fixture runs actual public Keymap/Bridge code over recorded native ports. All twelve cases first satisfy the immediate navigation policy. After the next `x`, five differ: arrow/shortcut with keep-AI plus reset-word lose `bonjour`; arrow/shortcut with reset-AI plus keep-word restore the cleared `bonjour`; keep-AI plus click also loses the prefix. `update_preview_body` copies the hotstring buffer back to `llm_buffer`, contrary to its own independent-lifetime comment. This corroborates the peer-owned root without inventing a second shared defect.

The registered `test_nav_invalidates_hotstring_buffer.lua` checks retained AI text immediately after navigation, then types a magic key and checks only consumption/output. Its positive result does not assert post-key retained AI text. The pure corpus's next-key case does exercise its own helper correctly; the missing layer is caller integration, not a corrupt shared oracle.

## Intentional differences, known limits and rejected hypotheses

- macOS tap-hold origin cannot be distinguished from the keyboard in this driver because Karabiner owns those remaps. This restriction is explicitly declared, translated and already tracked; it is not a new discovery.
- Option on macOS types characters; Cmd/Ctrl represent shortcuts. Windows/Linux treat their Ctrl/Alt/Win/Super identities differently. Equivalence is by action, not modifier spelling.
- Linux can subtract a coarse wall-clock resolution when high-resolution timing is unavailable; exact corpus values do not prove identical fallback precision across OS.
- Linux terminal Shift+Enter ambiguity and browser inline-autocomplete Backspace drift are already documented limits. No new ID or implementation TODO is created here.
- Escape hotstring retention and modified-word-deletion AI retention are observed differences. No source-backed product decision establishing their cross-OS exclusivity was located, so neither is labeled intentional equivalence or confirmed corruption.
- Passing the shared predicate or preserving context immediately after a navigation cannot refute a later caller overwrite. The next physical key is included explicitly.
- Previously confirmed Linux repeat fallback context retirement belongs to the preceding undo/repeat audit and is excluded here.

## Final sweeps and evidence limitations

Two final bounded sweeps revisited declarations/default initialization, actual caller classification, independent AI/word lifetime, modified Backspace, terminal newline/empty-line behavior, idle/coarse-clock timing, Unicode/private marks, menus/source adoption and previous-root deduplication. Each replays the twenty-source receipt, both 1,388-assertion runtime probes and the actual macOS peer twelve-case/five-mismatch observation. Both yield zero new shared roots. `dry-receipts.json` retains exact commands, output hashes and completion times.

A diagnostic attempt passed the feature-model module as Node's first argument. That matched the module's CLI guard and ran deterministic regeneration before the JSON reader refused its non-JSON output. The corrected probe passes an explicit sentinel argument and only reads the exported model. Every frozen metadata hash was checked unchanged and no extra tracked difference resulted. That failed invocation is not credited as a successful observation.

No native AHK runtime, real Hammerspoon desktop, evdev/uinput device, editor selection, user configuration, user logs or clipboard was accessed. Actual acceptance and Undo grouping in terminal/editor/browser fields remain unmeasured. No G4 latency or memory-growth assertion is made. The rolling context's bounded capacity and privacy vectors are exercised, but this is not a runtime heap/leak measurement. No production or registered test fix was implemented in this module.
