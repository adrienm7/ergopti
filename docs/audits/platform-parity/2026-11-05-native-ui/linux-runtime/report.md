## LRT-001 — First installation leaves stale absence in the model page

The model page binding (`linux/ui/menu/llm_backend_rows.lua`, `bind_page`) passes actual `ollama_install_state.capture` into the bridge. Bridge `build_payload` calls it before displaying the installation button; `ollama_install` offers the install while AI is off. On a fresh install, observing the missing runtime therefore precedes the user selecting install.

`ollama_install_state.lua:95` caches `_resolver` forever after its first successful construction. `ollama_install_resolver.new` records the identities of existing ancestors **and the absence of missing ancestors** of the versioned release parent. Its `current()` properly refuses a newly present ancestor. That refusal is correct for an immutable operation witness.

The independent operation resolver constructed by `runtime_factory.new` owns `prepare()`, which creates missing parents and updates only its own captured receipts. The browser's observer resolver has no such update. Successful `note_repair` clears `_failure`, proxy fallback and refusal metadata but never reconstructs `_resolver`. A subsequent capture with no cached models and the normal local origin calls `installed_runtime.capture` on that stale observer. `managed_status` drops the classified reason, returns unavailable, and the outer capture calls it ordinary absence.

The result has direct UI effects: bridge payload marks the Ollama backend unavailable; `ollama_ready` refuses model actions. After installation enables AI, the install button is also unavailable with the separate AI-on reason. A populated cache can temporarily conceal the failure because the answering branch precedes managed inventory; it does not repair the stored witness. Fresh install with no models is the concrete trigger. No claim is made that every successful install always exhibits it.


The probe uses actual canonical release JSON and generated `app_dirs`, actual policy/resolver/state/inventory, and actual `luv` syscalls. It first captures missing state, creates the parents through a second real resolver's `prepare`, then constructs a tiny structurally valid published inventory. The native runtime capture independently qualifies that tree. The proof then records successful repair and reproduces stale absence. Reset plus fresh resolver reports installed; removing execute permission reports absent again. The tiny executable is never run. This establishes the observer/cache defect, not integrity or inference of official runtime bytes.

Controlled seams are explicit: the state module's resolver constructor is redirected to the owned XDG plan, and its logger records exact calls. Production ancestry, UID, permission, inventory and state decisions remain actual. Repair success is supplied as the real public `note_repair` API expects; the full install controller and graphical window are source-traced rather than executed in this proof.

Silence is specific: the result's unavailable reason is discarded and `_last_cause` remains `absent`, so there is no new state log on installation; the probe records only the initial ordinary absence message. The UI does show a reason, but it identifies a missing runtime instead of the stale observer. This is misleading visibility rather than an assertion that absolutely no warning exists anywhere.

Regression intent: retain the two independent real resolvers, capture before first parent creation, complete installation, deliver successful repair, then require available/installed with an empty model inventory **without reset**. Preserve actual ancestor-substitution refusal and nonexecutable controls. Also exercise bridge action admission after repair; don't replace the state resolver with an always-current mock.

## Refuted hypotheses and bounded uncertainties

- **A stock PATH executable should make Linux available:** refuted as a requirement. The source and settled PIN decision explicitly admit only the owned runtime on its private port. No stock executable was probed.
- **A failed or skipped mv could overwrite/adopt a foreign destination:** real no-clobber/raced destination native cases pass and actual identity transfer is required. Zero process status alone is not used as publication proof.
- **Late cancellation automatically deletes a successfully published tree:** native late-cancelled-publication control passes; cleanup observes actual transfer and retains it. Cancellation does not manufacture rollback of a foreign name.
- **Directory symlinks let extraction chmod an outside executable:** actual intermediate-bin/lib-link controls pass; cleanup unlinks symlinks without traversing the target.
- **A read-only runtime capture authorizes arbitrary process lifetime:** refuted by explicit logical-descriptor semantics, inventory checks and separate native process owner. No immutable-byte lease is claimed.
- **Each proxy callback necessarily owns all previous probes until close:** not proven. TCP answers before native close acknowledgments; proxy keeps one current child. A synthetic delayed-close schedule could challenge retention, but an actually reachable native lookup/probe schedule producing false settlement was not established. No additional finding retained. Needs dedicated native scheduling proof, not an invented impossible lookup callback shape.
- **Unknown native debt is necessarily a leak:** not established. Retained debt is deliberate fail-closed policy; callback/close refusal and inability to prove exit are not automatically memory leak claims.
